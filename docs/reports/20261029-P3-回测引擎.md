## 1. 做了什么

1. `trade/common/exits.py`：出场策略状态机（06 §3.3），`trail`/`fixed` 两种模式，numba 版 + 纯 Python 参考版逐字段一致。覆盖保本、追踪、只升不降、最小改动阈值、无进展、H_max、封顶止盈、入场 K 线 post 高低点、同根按止损、跳空、补齐分钟、数据末尾（eod）。
2. `trade/common/sizing.py`：单笔仓位计算 `calc_notional`（06 §5，回测与实盘共用），含 fixed_fraction/fixed_risk 两模式、风险/流动性/保证金三重截断、数量取整、最小下单额与取整损失放弃、权益下限判定、强平距离与仓位校验，numba + Python 参考一致。
3. `trade/backtest/costs.py`：成本模型（06 §4）：半价差、平方根冲击滑点、VIP0 费率对应、base/stress/hell/breakeven 四情景、盈亏平衡滑点二分搜索。
4. `trade/backtest/r0.py`：规则策略 R0（05 §2）输出 `signals.parquet`（`symbol, open_time, p, m, is_sample`），可手工复核。
5. `trade/backtest/engine.py`：逐笔预计算 + 组合模拟（06 §3.4），覆盖开仓过滤、追价保护、冷却期、组合持仓上限、候选排序（p 降序 m 降序）、当日亏损停止、权益下限、保证金与取整。
6. `trade/backtest/event_sim.py`：事件驱动参考模拟器（06 §3.4，S9 对拍），复用出场/仓位/成本代码。
7. `trade/backtest/metrics.py`、`report.py`、`sanity.py`：指标（06 §6）、报告产物 + `gate.json` + `EXPERIMENTS.log`（06 §8）、S1~S11 健全性检验骨架（06 §7）。
8. 新增 `configs/exits.yaml`、`sizing.yaml`、`backtest.yaml`、`train.yaml`（R0 阈值）；新增 `scripts/r0_signals.py`、`scripts/backtest.py`；测试 8 个文件 48 项。

## 5. 与设计的偏差（实现约定，非阈值/接口/成交规则变更）

1. **sizing 的滑点用参考名义估算**：06 §4.2 的滑点含 `sqrt(notional)`，而 06 §5.2 的 `loss_rate` 又含 `slip_stop`，存在 notional↔slip 循环。实现取 `notional_ref = B × position_frac × leverage` 估算滑点（小名义下平方根项可忽略），并在 `engine.precompute_trades` 中固定；实际下单名义的滑点差异为二阶量，未改变任何阈值。
2. **出场数据末尾新增 `eod` 类型**：06 §3.3 未写明持仓跨过数据末尾的情形，实现按最后一根收盘价离场并标记 `eod`（区别于 H_max 超时）。
3. **超时/无进展的 `bars_held = H_max + 1`**：按 06 §3.3“到达 H_max 在下一根开盘离场”的字面实现（离场在 t+H_max+1 开盘）。
4. **组合模拟为 Python 实现**：06 §3.4 写组合模拟用 numba；按 AGENTS.md §6.4“先正确后优化”，本轮组合模拟为 Python（逐笔预计算已复用 numba 的 exits/sizing），numba 优化留待需要时。
5. **权益复利用已实现权益**：06 §5.1 的 `base=equity` 含未实现盈亏，实现取“钱包余额 + 已实现盈亏”（保守、确定性，避免逐分钟盯市的路径依赖）。
6. **资金费**：bars 无 `funding_rate/funding_time` 列时按 0 计（P1 真实 metrics 对齐后接线，见 §6）。
