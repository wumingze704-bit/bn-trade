# 04 特征与标签

## 1. 决策时点与符号约定

- 每个币每根 1 分钟 K 线收盘后，在时刻 `t` 做一次决策：开多或不动。
- 记第 t 根 K 线的开高低收为 `o_t, h_t, l_t, c_t`，成交额 `qv_t`（`quote_volume`），成交量 `v_t`，主动买成交额 `tbq_t`（`taker_buy_quote_volume`），成交笔数 `n_t`（`count`）。
- `mean_N(x)`、`std_N(x)`、`sum_N(x)`、`max_N(x)`：以 t 结尾（含 t）的最近 N 根的统计量；`max_N^-(x)` 表示 t-N … t-1（不含 t）。
- `ε = 1e-12`，防除零。
- 对数收益 `r_t = ln(c_t / c_{t-1})`。

## 2. 防未来函数规则（强制）

1. t 时刻的特征只能使用 `open_time ≤ t` 的 K 线数据，以及 `transact_time < t + 60000` 的逐笔数据。
2. 5 分钟 metrics 数据（时间戳 T）视为在 `T + 300000` 毫秒时才可得，只能被 `close_time ≥ T + 300000` 的 K 线使用。
3. 资金费率只使用已结算的最近一期。
4. 大单阈值使用前一个 UTC 日的值（见 03 §2.2）。
5. 归一化统计量只用历史（EWM 递推，天然满足）。
6. 禁止在全数据集上 `fit` 任何缩放器、PCA、分箱器。
7. 回测入场价是 `o_{t+1}`，不是 `c_t`。
8. 08 §2 P2 的“未来函数测试”与 06 §7 S3 的“特征平移”检验必须通过。特征平移：把全部特征向后平移 1 根（即使用更旧的信息），模型表现应下降或持平，不应上升。

## 3. 特征注册表

所有特征在 `trade.features.registry` 中登记，每项包含：`name`、`group`、`func`、`lookback`（所需历史根数）、`norm`（`none` 或 `ewm_z`）、`enabled`（来自 `features.yaml`）。模型产物记录启用特征的有序列表及其哈希（`feature_hash = sha256("|".join(name:lookback:norm))`），实盘加载时校验一致。

## 5. 归一化

两层处理：

1. **构造层**：上表公式本身已是比例、对数或无量纲量，消除了价格与成交额的绝对尺度，这是“跨币种通用”的前提。
2. **统计层**：`norm = ewm_z` 的特征做每币独立的指数加权标准化：

```
μ_t  = (1-α)·μ_{t-1} + α·x_t
σ²_t = (1-α)·σ²_{t-1} + α·(x_t - μ_{t-1})²
z_t  = clip((x_t - μ_{t-1}) / (sqrt(σ²_{t-1}) + ε), -5, 5)
```

- `α` 由半衰期 3 天（4320 根）换算：`α = 1 - 0.5^(1/4320)`。
- 用 `t-1` 时刻的统计量标准化 `x_t`，保证不含当前值。
- 预热期内统计量收敛，不产出样本。
- 实盘每分钟递推一次，状态（μ、σ²）持久化到状态库；进程重启时用最近 `warmup_days` 天 K 线重新递推（启动预热，见 07 §2）。
- `norm = none` 的特征仅做 `clip(-5, 5)`。
- 任何特征出现 NaN/Inf：离线流水线报错并指出币种与时间；实盘该分钟跳过该币决策并告警。

## 6. 预过滤（事件采样）

绝大多数分钟是平静的，在上面训练会让模型被“什么都不发生”的样本淹没。只有满足以下任一条件的 K 线才成为样本（训练、回测、实盘一致）：

```
vol_z_60 ≥ 1.0
或 |r_1| ≥ 2.0 × std_60(r)
或 brk_60 > 0
```

阈值在 `features.yaml` 中配置。数据集构建脚本需输出各币的样本保留率（预期 15%~35%），超出 5%~60% 范围时告警。

## 7. 标签：三重障碍法

### 7.1 定义

对每个通过预过滤的样本 t：

- 入场价 `P0 = o_{t+1}`（下一根开盘价，不含滑点；成本在回测中计算）。
- 波动尺度 `σ = ATR14_t / c_t`（原始值，非标准化）。
- 止损幅度 `sl = clip(k_sl · σ, sl_min, sl_max)`，默认 `k_sl = 1.0, sl_min = 0.5%, sl_max = 1.5%`。
- 止盈幅度 `tp = rr · sl`，默认盈亏比 `rr = 2.0`（即止盈为价格的 1.0%~3.0%）。

止损位取值理由（设计方确定，使用者已授权）：

1. **下限 0.5%**：VIP0 往返成本（双边手续费 0.07%~0.10% + 滑点约 0.04%~0.06%）约 0.15%。止损太窄时成本占风险的比例过高，且山寨币 1 分钟级的正常噪音就会扫掉止损。0.5% 时成本约占止损的 30%，是可接受的上限。
2. **上限 1.5%**：超短持仓 30 分钟内，超过 1.5% 的逆向波动通常意味着判断失败；同时在 5x 杠杆下，1.5% 止损对应该笔保证金约 8% 的亏损，离强平（约 −19%）有足够距离。
3. **随 ATR 自适应**：同样 0.8% 的止损，对平静的币太宽、对活跃的币太窄。按 `1 × ATR14` 设置，使每个币的止损都落在“正常 1 分钟波动之外”。
4. **盈亏比 2:1**：止盈 = 2 倍止损时，含成本的盈亏平衡胜率约 36%~41%（止损越窄越高）。预期全样本正样本率为 20%~35%，模型需要在 `p ≥ θ` 的样本中把止盈率提升到 45% 左右才有可观的正期望，这是 G2 闸门实质上在检验的东西。超时出场（TO）的样本按实际收益计入。
5. **以仓位衡量**：由于每笔仓位固定为权益的 20%、5x，止损在“该笔保证金”上的亏损为 3%~8%，在“总权益”上为 0.6%~1.6%，与权益大小无关（06 §5.4 速查表）。

`k_sl`、`rr` 只允许在验证集上做 05 §6.1 的有限网格搜索，测试段与封存集上不得调整；改变后需重建标签并重新训练。

- 上障碍 `U = P0 · (1 + tp)`，下障碍 `D = P0 · (1 - sl)`，时间障碍 `H = 30` 根。

从 `j = t+1` 到 `t+H` 依次检查：

```
若 l_j ≤ D：结果 = SL，出场价 = D（若 o_j < D，即跳空，出场价 = o_j），结束
否则若 h_j ≥ U：结果 = TP，出场价 = U，结束
（同一根同时满足两者时，按上面的顺序先判 SL —— 保守假设）
若到 t+H 仍未触发：结果 = TO（超时），出场价 = c_{t+H}
```

用 numba 实现（`trade.labels.triple_barrier`），输入为 numpy 数组。

### 7.2 输出字段（每样本一行）

| 字段        | 含义                                                                                                     |
| :---------- | :------------------------------------------------------------------------------------------------------- |
| `open_time` | 样本 t 的 K 线开盘时间                                                                                   |
| `symbol`    | 币种                                                                                                     |
| `y`         | 分类目标：TP 为 1，否则为 0                                                                              |
| `outcome`   | `TP` / `SL` / `TO`                                                                                       |
| `tp`, `sl`  | 本样本的止盈、止损幅度                                                                                   |
| `ret_gross` | `出场价 / P0 - 1`                                                                                        |
| `r_mult`    | 回归目标：`(ret_gross - c_rt) / sl`，截断到 [-1.5, 3.0]，`c_rt` 为固定往返成本估计（默认 0.12%，配置项） |
| `bars_held` | 持有根数                                                                                                 |
| `t_exit`    | 出场 K 线 `open_time`，用于 Purge 与样本重叠计算                                                         |

数据不足 H 根（数据末尾）的样本丢弃。

### 7.3 样本重叠与权重

相邻样本的标签窗口高度重叠，会让模型高估自己的确定性。默认采用 López de Prado 的“平均独特性”权重：样本 i 的权重 = 其标签窗口内每根 K 线的 `1/并发样本数` 的平均值（同币内计算）。训练时作为 `sample_weight`，`train.yaml` 中 `use_uniqueness_weight: true` 可关闭用于对比。

### 7.4 原草案标签（保留为可选）

`label.mode: legacy`：未来 3 分钟内最高价相对 `c_t` 上涨 ≥ 1%，且期间最低价未跌破 `l_t`，则 y = 1。仅用于对比实验，不作为默认，因为它用 `c_t` 作基准且不含止损/成本，与可交易的结果不一致。

## 8. 数据集产物

`scripts/build_dataset.py --run-id <id>` 输出：

- `data/features/{run_id}/{symbol}.parquet`：全部分钟的特征（含未通过预过滤的分钟，因为序列模型需要连续历史作为输入窗口），列 = `open_time` + 特征列 + `is_sample`（是否通过预过滤）。
- `data/labels/{run_id}/{symbol}.parquet`：仅样本行，字段见 7.2，加 `weight`。
- `data/features/{run_id}/manifest.json`：配置快照、特征列表与 `feature_hash`、各币行数、样本保留率、正样本率、各文件 SHA256。

预期正样本率（TP 占比）约 20%~35%；超出 10%~50% 时告警，提示障碍参数可能不合理。
