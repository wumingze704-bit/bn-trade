# 04 特征与标签

## 1. 决策时点与符号约定

- 每个币每根 1 分钟 K 线收盘后，在时刻 `t` 做一次决策：开多或不动。
- 记第 t 根 K 线的开高低收为 `o_t, h_t, l_t, c_t`，成交额 `qv_t`（`quote_volume`），成交量 `v_t`，主动买成交额 `tbq_t`（`taker_buy_quote_volume`），成交笔数 `n_t`（`count`）。
- `mean_N(x)`、`std_N(x)`、`sum_N(x)`、`max_N(x)`：以 t 结尾（含 t）的最近 N 根的统计量；`max_N^-(x)` 表示 t-N … t-1（不含 t）。
- `ε = 1e-12`，防除零。
- 对数收益 `r_t = ln(c_t / c_{t-1})`。

## 2. 防未来函数规则（强制）

1. t 时刻的特征只能使用 `open_time ≤ t` 的 K 线数据，以及 `transact_time < t + 60000` 的逐笔数据。
2. 5 分钟 metrics 数据（时间戳 T）视为在 `T + 300000` 毫秒时才可得，只能被 `close_time ≥ T + 300000` 的 K 线使用。
3. 资金费率只使用已结算的最近一期。
4. 大单阈值使用前一个 UTC 日的值（见 03 §2.2）。
5. 归一化统计量只用历史（EWM 递推，天然满足）。
6. 禁止在全数据集上 `fit` 任何缩放器、PCA、分箱器。
7. 入场价不是 `c_t`，也不是理想化的 `o_{t+1}`，而是下一根 K 线开盘后经过执行延迟（默认 1 秒）的真实逐笔价 `p_1s`（03 §2.2、06 §3.2）。
8. 03 §2.2 中的执行类原子量（`p_*`、`hi_post_*`、`lo_post_*`）只能用于标签与成交模拟，**不得作为特征**，注册表加载时校验。
9. 08 §2 P2 的“未来函数测试”与 06 §7 S3 的“特征平移”检验必须通过。特征平移：把全部特征向后平移 1 根（即使用更旧的信息），模型表现应下降或持平，不应上升。

## 3. 特征注册表

所有特征在 `trade.features.registry` 中登记，每项包含：`name`、`group`、`func`、`lookback`（所需历史根数）、`norm`（`none` 或 `ewm_z`）、`enabled`（来自 `features.yaml`）。模型产物记录启用特征的有序列表及其哈希（`feature_hash = sha256("|".join(name:lookback:norm))`），实盘加载时校验一致。

## 5. 归一化

两层处理：

1. **构造层**：上表公式本身已是比例、对数或无量纲量，消除了价格与成交额的绝对尺度，这是“跨币种通用”的前提。
2. **统计层**：`norm = ewm_z` 的特征做每币独立的指数加权标准化：

```
μ_t  = (1-α)·μ_{t-1} + α·x_t
σ²_t = (1-α)·σ²_{t-1} + α·(x_t - μ_{t-1})²
z_t  = clip((x_t - μ_{t-1}) / (sqrt(σ²_{t-1}) + ε), -5, 5)
```

- `α` 由半衰期 3 天（4320 根）换算：`α = 1 - 0.5^(1/4320)`。
- 用 `t-1` 时刻的统计量标准化 `x_t`，保证不含当前值。
- 预热期内统计量收敛，不产出样本。
- 实盘每分钟递推一次，状态（μ、σ²）持久化到状态库；进程重启时用最近 `warmup_days` 天数据重新递推（启动预热，见 07 §2）。
- **预热长度与离线一致性**：离线流水线从数据起点一直递推，实盘只从最近 `warmup_days` 天开始递推，两者的差异等于被截掉的历史权重 `0.5^(warmup_bars / 4320)`。`warmup_days = 30` 时约为 0.1%，可以接受；`warmup_days = 10` 时约为 10%，会造成实盘与回测特征系统性不一致，因此预热取 30 天。06 §7 S7 按此口径验收。
- **数据段**：同一币的数据可能因不在交易范围而有长时间空档（03 §6“数据段”）。离线流水线对每段独立从零递推 EWM、独立计算滚动窗口，段首 `warmup_days` 天不产生样本；任何特征的回看窗口都不得跨越段间空档。
- `norm = none` 的特征仅做 `clip(-5, 5)`。
- 任何特征出现 NaN/Inf：离线流水线报错并指出币种与时间；实盘该分钟跳过该币决策并告警。

## 6. 预过滤（事件采样）

绝大多数分钟是平静的，在上面训练会让模型被“什么都不发生”的样本淹没。只有满足以下任一条件的 K 线才成为样本（训练、回测、实盘一致）：

```
vol_z_60 ≥ 1.0
或 |r_1| ≥ 2.0 × std_60(r)
或 brk_60 > 0
```

阈值在 `features.yaml` 中配置。数据集构建脚本需输出各币的样本保留率（预期 15%~35%），超出 5%~60% 范围时告警。

## 7. 标签：三重障碍法

### 7.0 标签模式与出场策略的关系

`features.yaml: label.mode` 有两种：

| 模式                     | 标签含义                                                                                    | 用途                 |
| :----------------------- | :------------------------------------------------------------------------------------------ | :------------------- |
| `exit_sim`（**默认**）   | 用实际出场策略 `trade.common.exits` 模拟这笔交易，以**扣除全部成本后的净 R** 为标签（§7.5） | 训练、阈值、正式回测 |
| `triple_barrier`（对照） | 三重障碍：先涨 `rr` 倍止损还是先跌 1 倍止损（§7.1~§7.2）                                    | 消融对照             |

- **为什么默认改为 `exit_sim`**：实际出场是保本 + 追踪 + 无进展离场 + 封顶止盈（06 §3.3）。三重障碍标签学的是“能否先到 2R”，与实际赚钱的方式不一致：例如先涨到 1R 把止损移到保本、再回落离场的交易，三重障碍可能标为正、实际却几乎不赚。`exit_sim` 让模型直接学习“按真实出场方式这笔交易值不值得做”，标签、回测与实盘使用同一份出场代码（AGENTS.md §6 红线 4）。
- **代价**：出场参数改变时标签随之改变，必须重建标签并重训模型。因此调参顺序为“先定出场策略，再调模型超参”，出场参数网格缩小（05 §6.1）。
- 初始止损 `sl` 的定义（§7.1 的 `k_sl`、`sl_min`、`sl_max`）两种模式共用。

### 7.1 定义

对每个通过预过滤的样本 t：

- 入场价 `P0 = p_1s(t+1)`：下一根 K 线开盘 1 秒后的真实逐笔价（03 §2.2），与实盘执行时刻一致；不含滑点与点差，成本在回测中计算。
- 波动尺度 `σ = ATR14_t / c_t`（原始值，非标准化）。
- 止损幅度 `sl = clip(k_sl · σ, sl_min, sl_max)`，默认 `k_sl = 1.0, sl_min = 0.5%, sl_max = 1.5%`。
- 止盈幅度 `tp = rr · sl`，默认盈亏比 `rr = 2.0`（即止盈为价格的 1.0%~3.0%）。

止损位取值理由（设计方确定，使用者已授权）：

1. **下限 0.5%**：VIP0 往返成本（双边手续费 0.07%~0.10% + 滑点约 0.04%~0.06%）约 0.15%。止损太窄时成本占风险的比例过高，且山寨币 1 分钟级的正常噪音就会扫掉止损。0.5% 时成本约占止损的 30%，是可接受的上限。
2. **上限 1.5%**：分钟级突破信号在一小时量级内，超过 1.5% 的逆向波动通常意味着判断失败；同时在 5x 杠杆下，1.5% 止损对应该笔保证金约 8% 的亏损，离强平（约 −19%）有足够距离。
3. **随 ATR 自适应**：同样 0.8% 的止损，对平静的币太宽、对活跃的币太窄。按 `1 × ATR14` 设置，使每个币的止损都落在“正常 1 分钟波动之外”。
4. **盈亏比 2:1**：止盈 = 2 倍止损时，含成本的盈亏平衡胜率约 36%~41%（止损越窄越高）。预期全样本正样本率为 20%~35%，模型需要在 `p ≥ θ` 的样本中把止盈率提升到 45% 左右才有可观的正期望，这是 G2 闸门实质上在检验的东西。超时出场（TO）的样本按实际收益计入。
5. **以仓位衡量**：由于每笔仓位固定为权益的 20%、5x，止损在“该笔保证金”上的亏损为 3%~8%，在“总权益”上为 0.6%~1.6%，与权益大小无关（06 §5.4 速查表）。

`k_sl`、`rr`、`H_label` 只允许在调参期（03 §6）做 05 §6.1 的有限网格搜索，测试段与封存集上不得调整；改变后需重建标签并重新训练。

- 上障碍 `U = P0 · (1 + tp)`，下障碍 `D = P0 · (1 - sl)`，时间障碍 `H_label` 根，默认 **60**（候选 30 / 60）。

**为什么标签窗口不取更长**：分钟级微观结构信号的有效期通常在数十分钟内，窗口越长，标签越多由“之后发生的大盘行情”决定，噪音越大；相邻样本的标签窗口重叠越多，独特性权重越低、Purge 删除的样本越多。更长的持有交给出场策略的 `H_max`（06 §3.3）。

检查顺序（入场 K 线 `t+1` 只用入场后的逐笔高低点，之后的 K 线用整根高低点）：

```
j = t+1：lo = lo_post_1s(j)，hi = hi_post_1s(j)
j > t+1：lo = l_j，hi = h_j
对 j = t+1 … t+H_label 依次：
  若 lo ≤ D：结果 = SL，出场价 = D（j > t+1 且 o_j < D 即跳空时，出场价 = o_j），结束
  否则若 hi ≥ U：结果 = TP，出场价 = U，结束
  （同一根同时满足两者时先判 SL —— 保守假设）
若到 t+H_label 仍未触发：结果 = TO（超时），出场价 = c_{t+H_label}
```

`is_filled = 1` 的分钟不产生样本；标签窗口内补齐分钟占比 > 10% 的样本丢弃。

用 numba 实现（`trade.labels.triple_barrier`），输入为 numpy 数组。

### 7.2 输出字段（每样本一行）

| 字段        | 含义                                                                                                     |
| :---------- | :------------------------------------------------------------------------------------------------------- |
| `open_time` | 样本 t 的 K 线开盘时间                                                                                   |
| `symbol`    | 币种                                                                                                     |
| `y`         | 分类目标：TP 为 1，否则为 0                                                                              |
| `outcome`   | `TP` / `SL` / `TO`                                                                                       |

### 7.3 样本重叠与权重

相邻样本的标签窗口高度重叠，会让模型高估自己的确定性。默认采用 López de Prado 的“平均独特性”权重：样本 i 的权重 = 其标签窗口（入场 K 线至出场 K 线，`exit_sim` 模式下即模拟持仓区间）内每根 K 线的 `1/并发样本数` 的平均值（同币内计算）。训练时作为 `sample_weight`，`train.yaml` 中 `use_uniqueness_weight: true` 可关闭用于对比。

### 7.5 出场模拟标签 `exit_sim`（默认）

对每个通过预过滤的样本 t：

1. 入场价、初始止损与成本**与回测完全相同**：`P_fill = p_1s(t+1) × (1 + half_spread + slip)`（06 §3.2、§4，`base` 情景，滑点用 `notional_ref`），`sl` 按 §7.1；入场 K 线为补齐分钟、追价保护不通过（06 §3.1 条件 5）的样本丢弃。
2. 调用 `trade.common.exits.simulate_exit`（与 `trade.backtest.engine.precompute_trades` 同一个函数、同一份 `exits.yaml`）得到出场时间、出场价、出场类型与费率。**不另写一份出场逻辑**。
3. 净收益率 `ret_net = 出场价 / P_fill − 1 − 开仓费率 − 出场费率`（资金费在 T0.8 接入后同样扣除）；净 R：`r_net = ret_net / sl`。
4. 输出：

| 字段                         | 含义                                                                                                 |
| :--------------------------- | :--------------------------------------------------------------------------------------------------- |
| `open_time`、`symbol`        | 同 §7.2                                                                                              |
| `y`                          | 分类目标：`r_net ≥ y_min_r` 为 1，否则为 0；`y_min_r` 默认 0.25（`features.yaml`，事先固定，不调参） |
| `r_mult`                     | 回归目标：`r_net`，截断到 [-1.5, 4.0]                                                                |
| `exit_type`                  | 出场类型（初始止损 / 保本 / 追踪 / 封顶 / 无进展 / 超时 / 数据末尾）                                 |
| `sl`、`ret_net`、`bars_held` | 初始止损幅度、净收益率、持有根数                                                                     |
| `t_exit`                     | 出场 K 线 `open_time`，用于 Purge、Embargo 与样本独特性权重                                          |

- `y_min_r = 0.25` 的理由：保本出场的净 R 约为 0（`be_offset` 只覆盖成本），把它们标为正样本会让分类目标被大量“打平”交易稀释；要求至少 0.25R 才算正样本，让模型区分“真正赚到的”与“基本打平的”。
- Purge 宽度改为样本的实际持仓区间（`t_exit`），不足 `H_max` 根就到达数据末尾的样本丢弃（同 §7.2）。
- 预期正样本率需在调参期实测后写入 manifest；超出 10%~50% 时告警（同 §8）。

### 7.4 原草案标签（保留为可选）

`label.mode: legacy`：未来 3 分钟内最高价相对 `c_t` 上涨 ≥ 1%，且期间最低价未跌破 `l_t`，则 y = 1。仅用于对比实验，不作为默认，因为它用 `c_t` 作基准且不含止损/成本，与可交易的结果不一致。

## 8. 数据集产物

`scripts/build_dataset.py --run-id <id>` 输出：

- `data/features/{run_id}/{alias}.parquet`：全部分钟的特征（含未通过预过滤的分钟，因为序列模型需要连续历史作为输入窗口），列 = `open_time` + 特征列 + `is_sample`（是否通过预过滤）。
- `data/labels/{run_id}/{alias}.parquet`：仅样本行，字段见 7.2，加 `weight`。
- `data/features/{run_id}/manifest.json`：配置快照（含 `label.mode`、`universe_rule_hash` 与 `exit_policy_hash`，后者为 `exits.yaml` 出场策略哈希，出场参数改变即视为新数据集）、特征列表与 `feature_hash`、各币行数、样本保留率、正样本率、各文件 SHA256。

预期正样本率（TP 占比）约 20%~35%；超出 10%~50% 时告警，提示障碍参数可能不合理。
