# 06 回测引擎

## 1. 目标与原则

- 回测的唯一目的是**尽量真实地估计实盘净收益，并尽早发现策略无效**。宁可低估，不可高估。
- 成交规则、风控规则、仓位规则与实盘（07）逐条对应。任何一方修改，另一方同步修改，并在两个文档里同时更新。
- 信号计算向量化（批量推理）；持仓与组合模拟有路径依赖，使用 numba 编译的顺序循环。**不追求“完全无 for 循环”，追求正确。**

## 2. 输入与输出

| 输入                                                            | 来源                                           |
| :-------------------------------------------------------------- | :--------------------------------------------- |
| 分钟数据 bars                                                   | 03 §2.3                                        |
| 信号 `signals.parquet`（`symbol, open_time, p, m, is_sample`）  | 05 §6 第 5 步                                  |
| 模型元数据（障碍参数、阈值 θ）                                  | `model_meta.json`                              |
| 回测配置                                                        | `configs/backtest.yaml`、`configs/sizing.yaml` |
| 交易规则快照（`tickSize`、`stepSize`、`minNotional`、杠杆分层） | exchangeInfo 与 leverageBracket 快照（09 §3）  |

输出见 §8。

## 3. 成交模拟规则

以下 t 为信号 K 线，`j` 为持仓期间的 K 线序号。

### 3.1 开仓条件（全部满足）

1. `is_sample = 1` 且 `p ≥ θ`。
2. 该币当前无持仓，且不在止损冷却期（该币上一次止损出场后 `cooldown_bars = 15` 根内不再开仓）。
3. 组合持仓数 < `max_positions`（来自当前仓位配置，§5.4）。同一时刻候选多于空位时，按 `p` 降序、`m` 降序取。
4. 当日（UTC）已实现亏损未达 `daily_loss_stop`（来自当前仓位配置，§5.4）。
5. 追价保护：`o_{t+1} ≤ c_t × (1 + max_chase)`，默认 `max_chase = 0.3%`。不满足则放弃（对应实盘限价 IOC 未成交）。
6. 按 §5 计算出的名义价值通过最小下单额、数量取整与保证金校验。
7. 权益未低于 §5.3 的权益下限。

### 3.2 开仓价格

```
P_fill = o_{t+1} × (1 + slip_entry)
```

数量按 `stepSize` 向下取整。止盈/止损价**以实际成交价 `P_fill` 为基准**重新计算（与实盘一致），并按 `tickSize` 取整：止盈向上取整、止损向下取整。

```
U = P_fill × (1 + tp)      D = P_fill × (1 - sl)      tp、sl 按 04 §7.1 由 t 时刻 ATR 计算
```

### 3.3 持仓期间（j = t+1 … t+H）

```
若 l_j ≤ D：
    止损。出场价 = min(D, o_j) × (1 - slip_stop)，吃单费率
否则若 h_j ≥ U × (1 + tp_penetration)：
    止盈。出场价 = U，挂单费率（限价止盈单）
同一根 K 线两者都满足时，按止损处理（保守）
若 j = t+H 仍未触发：
    超时平仓。出场价 = c_{t+H} × (1 - slip_exit)，吃单费率
```

- `tp_penetration`：默认 1 bp。价格仅“摸到”止盈价不一定能成交（队列靠后），要求穿越才算成交。
- 开仓所在的 K 线 `t+1` 也参与判断（开盘后的高低点可能已触发）。
- 持仓跨越资金费结算时刻（以 fundingRate 数据中的实际结算时间戳为准，不硬编码 8 小时）时：`PnL -= funding_rate × 名义价值`（费率为正时多头支付）。

### 3.4 实现要点

由于“单笔交易的出场结果”只取决于该币的 K 线，不取决于组合状态，实现分两步：

1. **逐笔预计算**（numba，按币并行）：对每个满足条件 1 和 5 的候选 t，算出假如开仓的 `P_fill, U, D, 出场时间, 出场价, 出场类型, 毛收益率, 费用率`。
2. **组合模拟**（numba，单线程）：把所有币的候选按 `(open_time, -p, -m)` 排序，按时间推进；维护各币持仓与冷却状态、持仓槽位、权益、当日已实现盈亏；调用 §5 的仓位函数决定接受或拒绝每个候选，接受的计入仓位并在其出场时间释放槽位、结算盈亏。组合模拟对不同仓位配置（§5.1 的两次运行、§5.5 的扫描）重复执行，逐笔预计算只做一次。

注意：§5 的仓位函数在 numba 内无法直接调用 pydantic 对象，实现为“纯数值参数的 numba 函数 + Python 包装函数”，两者共用同一份测试用例，确保与实盘调用结果一致。

## 4. 成本模型

### 4.1 手续费

使用者为 **VIP0、不使用 BNB 抵扣**。来自 `base.yaml` 的 `fees`（合约挂单 0.02%、吃单 0.05%，以币安官方费率页为准）。实盘启动时会读取账户实际费率并比对（09 §4），如果币安调整了 VIP0 费率，需同步更新 `base.yaml` 并重跑回测。

| 动作                       | 费率 |
| :------------------------- | :--- |
| 开仓（限价 IOC，视为吃单） | 吃单 |
| 止盈（限价单）             | 挂单 |
| 止损（条件市价单）         | 吃单 |
| 超时平仓（市价）           | 吃单 |

按 VIP0，一笔“吃单开仓 + 挂单止盈”的往返手续费为 0.07%，“吃单开仓 + 吃单止损”为 0.10%。以 5x 杠杆计，相当于每笔占用保证金的 0.35%~0.5%。

### 4.2 滑点

单边滑点（比例）：

```
slip = max(slip_min, 0.5 × tick_rel) + Y × rv_15_raw × sqrt(notional / (qv_t + ε))
```

- `slip_min`：默认 2 bp；`tick_rel = tickSize / 价格`；`rv_15_raw` 为未标准化的 15 分钟 1m 收益标准差；`qv_t` 为信号 K 线成交额；`Y = 1.0`（平方根冲击模型系数）。
- `slip_entry = slip_exit = slip`，`slip_stop = 2 × slip`（止损通常发生在单边急跌中，滑点更大）。

### 4.3 压力情景（每次回测必须全部运行）

| 情景        | 规则                                                           | 用途                     |
| :---------- | :------------------------------------------------------------- | :----------------------- |
| `base`      | 上述默认                                                       | 主结果                   |
| `stress`    | 滑点 × 2；止盈也按吃单费率计                                   | 闸门要求仍为正           |
| `hell`      | 单边固定滑点 0.15%（原草案的“地狱模式”），所有成交均按吃单费率 | 观察用，不作为闸门       |
| `breakeven` | 二分搜索使净收益 = 0 的单边固定滑点                            | 报告“盈亏平衡滑点”（bp） |

## 5. 仓位与资金

> 本节是仓位计算的**唯一规格来源**，回测（`trade.backtest.portfolio`）与实盘（`trade.live.risk`）调用同一个函数 `trade.common.sizing.calc_notional()`，禁止各写一份。07 只引用本节。

### 5.1 两次运行

每次回测对同一组信号跑两套资金设置：

| 运行                        | 用途                                                | 设置                                                                                                                              |
| :-------------------------- | :-------------------------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------- |
| **参考运行**（`reference`） | 闸门判定（08 §3），只看比例指标，排除小本金取整干扰 | `initial_equity = 10000`、`fixed_risk`、`risk_per_trade = 0.005`、`base = initial`（不复利）、`leverage = 5`、`max_positions = 3` |
| **实盘配置运行**（`user`）  | 让使用者看到“按我自己的设置，10 USDT 会变成多少”    | `configs/sizing.yaml` 的设置（§5.4：10 USDT、每笔 20%、5x、复利）、真实最小下单额与数量步长                                       |

报告中两者分开展示。`user` 运行会如实体现小本金下的各种放弃开仓（最小下单额、取整、权益下限）。

记基准金额为 `B`：`base = initial` 时为初始本金，`base = equity` 时为开仓时的**当前账户权益**（钱包余额 + 未实现盈亏）。

实盘与 `user` 运行都使用 `base = equity`，即**按当前权益的固定比例复利计算**：

- 权益 10 USDT → 每笔保证金 2 USDT，名义价值 10 USDT。
- 权益 100 USDT → 每笔保证金 20 USDT，名义价值 100 USDT。
- 权益 500 USDT → 每笔保证金 100 USDT，名义价值 500 USDT。

记**单笔保证金** `M = B × position_frac`，名义价值 `N = M × leverage`。

### 5.2 仓位模式

| 模式                         | 含义                               | 公式（未截断前）                                |
| :--------------------------- | :--------------------------------- | :---------------------------------------------- |
| `fixed_fraction`（实盘默认） | 每笔占用**保证金**为本金的固定比例 | `notional_raw = B × position_frac × leverage`   |
| `fixed_risk`                 | 每笔止损时亏损本金的固定比例       | `notional_raw = B × risk_per_trade / loss_rate` |

- `loss_rate = sl + slip_stop + 2 × fee_taker`，即止损出场时每 1 USDT 名义价值的预计亏损。
- `position_frac` 指**保证金**占当前权益的比例，不是名义价值。例：权益 10 USDT、`position_frac = 0.2`、5x → 保证金 2 USDT，名义价值 10 USDT。
- `position_frac` 范围 `[0.01, 0.95]`；`risk_per_trade` 范围 `[0.001, 0.05]`。

### 5.3 截断、取整与下限（两种模式通用）

```
notional = min(
    notional_raw,
    B × max_risk_per_trade / loss_rate,      # 单笔最大亏损硬上限（占权益），默认 2.5%
    liq_cap × mean_60(qv),                   # 流动性上限，默认 liq_cap = 0.5%
    available_margin × 0.95 × leverage       # 当前可用保证金（扣除其他持仓占用后）
)
qty = floor(notional / P / stepSize) × stepSize
qty × P < minNotional × 1.1        → 放弃，原因 below_min_notional
qty × P < 0.9 × notional           → 放弃，原因 step_rounding（取整损失超过 10%）
```

- 截断发生时记录 `size_capped_by`（`risk_cap` / `liquidity` / `margin`），报告中统计各原因的次数。
- **权益下限**：当 `B × position_frac × leverage < 全部交易币中最小的 minNotional × 1.1` 时，任何币都无法开仓，回测记录 `equity_floor` 并停止开仓（实盘对应 07 R14，停止开仓并通知）。按默认设置（20%、5x），若交易币最小下单额为 5 USDT，则权益下限约 **5.5 USDT**：10 USDT 本金亏损约 45% 后系统将无法再开仓。

### 5.4 仓位配置（使用者确认：10 USDT、每笔 20%、5x）

仓位与资金类风控参数集中在 `configs/sizing.yaml`，回测 `user` 运行与实盘共用。任何参数都可以在运行中手动覆盖（07 §7.1.1）。

```yaml
initial_equity: 10 # 初始本金（USDT），用于 user 运行
mode: fixed_fraction # fixed_fraction | fixed_risk
position_frac: 0.20 # 每笔保证金 = 当前权益 × 20%
leverage: 5
max_positions: 3 # 0.20 × 3 = 0.60 ≤ 0.95
base: equity # 按当前权益复利
risk_per_trade: 0.005 # 仅 fixed_risk 模式使用
max_risk_per_trade: 0.025 # 单笔止损亏损硬上限（占权益），正常不会触发，见下方速查表
daily_loss_stop: 0.05 # 当日亏损达权益 5%（约 3~4 笔宽止损）停止开仓
daily_loss_halt: 0.08 # 当日亏损达 8% 全平并停机
max_drawdown_halt: 0.20 # 从峰值回撤 20% 停机，人工复核
max_consecutive_losses: 6
liq_cap: 0.005
maint_margin_rate: 0.01 # 回测用维持保证金率（保守值）；实盘用 leverageBracket 实际值
```

止损位规则见 04 §7.1（止损随波动率在价格的 0.5%~1.5% 之间自适应，止盈 = 2 倍止损）。单笔盈亏速查（VIP0，含手续费与基准滑点估算；对“该笔保证金”和“总权益”的比例与权益大小无关）：

| 情形         | 价格变动 | 占该笔保证金 | 占总权益  | 权益 10 USDT 时              | 权益 100 USDT 时 |
| :----------- | :------- | :----------- | :-------- | :--------------------------- | :--------------- |
| 最窄止损     | −0.5%    | 约 −3.2%     | 约 −0.64% | −0.064 USDT                  | −0.64 USDT       |
| 典型止损     | −0.8%    | 约 −4.7%     | 约 −0.94% | −0.094 USDT                  | −0.94 USDT       |
| 最宽止损     | −1.5%    | 约 −8.2%     | 约 −1.64% | −0.164 USDT                  | −1.64 USDT       |
| 典型止盈     | +1.6%    | 约 +7.5%     | 约 +1.5%  | +0.15 USDT                   | +1.5 USDT        |
| 强平（参考） | 约 −19%  | −100%        | −20%      | 正常情况下止损远早于强平触发 |                  |

估算口径：止损亏损 = 名义价值 × (sl + 止损滑点 0.04% + 双边吃单费 0.10%)；止盈盈利 = 名义价值 × (tp − 开仓滑点 0.02% − 吃单 0.05% − 挂单 0.02%)。实际滑点以回测的动态滑点模型为准。

配置加载与修改时校验（不通过则拒绝，并给出提示文案）：

1. `position_frac × max_positions ≤ 0.95`，否则提示“满仓时保证金不足，请降低 position_frac 或 max_positions”。
2. `当前权益 × position_frac × leverage ≥ 交易币中位数 minNotional × 1.1`，否则提示本金或比例过小。
3. **强平距离**：`sl_max ≤ 0.5 × (1 / leverage − maint_margin_rate)`。5x 时右侧约 9.5%，远大于 `sl_max = 1.5%`；杠杆调高到不满足时拒绝。`leverage` 不得超过该币杠杆分层允许的最大值。
4. `max_risk_per_trade ∈ [0.005, 0.10]`，且 `≥ leverage × position_frac × (sl_max + 0.14%)`（否则最宽止损的单子会被频繁截断，提示使用者知悉）；`daily_loss_stop < daily_loss_halt`。
5. 生成“仓位设置摘要”（模式、比例、杠杆、按上表口径的单笔亏损/盈利区间、满仓保证金占用、权益下限），在启动日志、飞书通知、看板控制页显示。

### 5.5 比例敏感性扫描

由于比例由使用者手动决定，每次回测都额外按 `sizing_sweep`（默认 `position_frac ∈ [0.1, 0.15, 0.2, 0.3]`，`leverage = 5`，`max_positions = min(3, floor(0.95 / position_frac))`，`initial_equity = 10`，复利）重跑组合模拟，输出对比表：

| 列                                | 含义                                                                       |
| :-------------------------------- | :------------------------------------------------------------------------- |
| `position_frac` / `max_positions` | 比例与对应的最大持仓数                                                     |
| 期末权益 / 净收益率               | 期末权益与 期末 / 初始 − 1                                                 |
| 最大回撤                          | 权益曲线最大回撤                                                           |
| 最大单日亏损                      | 占当日初权益                                                               |
| 最长连续亏损                      | 笔数与金额                                                                 |
| 触发日亏损停止天数                | 按 `sizing.yaml` 阈值                                                      |
| 放弃开仓次数                      | 按原因：`below_min_notional` / `step_rounding` / `margin` / `equity_floor` |
| 是否触及权益下限                  | 是 / 否，及首次触及日期                                                    |

比例变化会改变“同时可持仓数”与“因保证金不足放弃的交易”，必须重跑组合模拟，不能按比例简单缩放收益。

### 5.6 合约保证金校验

逐仓保证金 = `notional / leverage`，所有持仓保证金合计 + 新仓保证金不得超过可用余额的 95%（留 5% 缓冲给手续费与资金费）。

## 6. 指标

所有指标同时给出：全部币、训练币、留出币三组；以及每币、每月、每 UTC 小时分组。`reference` 与 `user` 两次运行分别计算。

| 类别       | 指标                                                                                                                                                         |
| :--------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 收益       | 净收益（USDT 与 %）、毛收益、手续费合计、滑点合计、资金费合计、手续费+滑点占毛利比例                                                                         |
| 风险调整   | 日收益年化夏普（×√365）、索提诺、最大回撤（%）、最长回撤持续天数、Calmar                                                                                     |
| 交易       | 交易笔数、日均笔数、胜率、平均盈利/平均亏损、Profit Factor（毛盈利/毛亏损，均为扣成本后）、单笔期望（bp 与 R 倍数）、平均持仓分钟、TP/SL/TO 占比、时间占用率 |
| 稳健性     | 去掉收益最高的 1% 交易后的 PF；去掉贡献最大的单币后的净收益；正收益月份占比                                                                                  |
| 成本敏感性 | `base`/`stress`/`hell` 三情景对比表、盈亏平衡滑点                                                                                                            |
| 小本金     | `user` 运行的放弃开仓原因统计、权益下限触及情况                                                                                                              |

## 7. 健全性检验（`trade.backtest.sanity`）

这些检验用于发现“回测看起来很好但其实是错的”，**全部必须执行并写入报告**。均基于 `reference` 运行。

| 编号 | 检验                       | 方法                                                                                           | 通过标准                                          |
| :--- | :------------------------- | :--------------------------------------------------------------------------------------------- | :------------------------------------------------ |
| S1   | 随机入场基准               | 在同样的预过滤样本中随机抽取入场点，保持每币每月交易笔数与策略相同，出场规则相同，重复 1000 次 | 策略净收益 > 随机分布的 95 分位                   |
| S2   | 标签打乱                   | 训练集内随机打乱 `y` 后重新训练 M1，跑测试段回测                                               | `base` 情景 PF ≤ 1.05（否则存在信息泄露）         |
| S3   | 特征平移                   | 所有特征向后平移 1 根后推理与回测                                                              | 净收益不高于原结果 + 随机误差（S1 标准差的 1 倍） |
| S4   | 阈值扰动                   | θ ± 0.04                                                                                       | 两侧 `base` PF 均 ≥ 1.1                           |
| S5   | 时间稳定性                 | 4 个测试月分别统计                                                                             | ≥ 3 个月净收益为正                                |
| S6   | 集中度                     | 去掉最佳单币；去掉收益最高 1% 交易                                                             | 两种情况下净收益仍为正                            |
| S7   | 批量/增量一致性            | 随机选 2 币 × 2 天，用实盘引擎的增量特征与推理路径重算信号                                     | `p` 绝对误差 < 1e-5，信号完全一致                 |
| S8   | 逐笔成交复核（可选，推荐） | 保留 1 个月原始 aggTrades，按逐笔顺序重放开仓与止盈止损触发，对比 K 线级结果                   | 净收益差异 < 15%，否则 K 线级假设过于乐观         |

| `report.md`                                                          | 摘要（闸门判定结果放在最前）、配置、指标表、分组表、情景对比、健全性检验结果、`user` 运行结果                                                           |
| `summary.json`                                                       | 核心指标的机器可读版本（两次运行 × 三情景）                                                                                                             |
| `equity.parquet`                                                     | 权益曲线：`run`（reference/user/sweep_x）、`scenario`、`ts_ms`、`equity`、`drawdown`                                                                    |
| `equity.png` / `monthly.png` / `by_symbol.png` / `p_calibration.png` | 静态图片（报告文件内引用）                                                                                                                              |
| `trades.parquet`                                                     | 每笔交易明细：run、scenario、币、信号时间、p、m、开仓价、U、D、出场时间、出场价、类型、名义价值、保证金、手续费、滑点、资金费、净盈亏、`size_capped_by` |
| `skipped.parquet`                                                    | 被放弃的候选信号：币、时间、p、放弃原因                                                                                                                 |
| `sizing_sweep.md` / `sizing_sweep.parquet`                           | §5.5 比例敏感性对比表                                                                                                                                   |
| `gate.json`                                                          | 机器可读的闸门判定（基于 `reference` 运行），供 08 与看板读取                                                                                           |

`--final` 模式（封存集评估）额外在 `artifacts/reports/FINAL_RUNS.log` 追加一行记录（时间、model_id、结果），用于审计封存集被使用的次数。
