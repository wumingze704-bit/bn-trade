# 06 回测引擎

## 1. 目标与原则

- 回测的唯一目的是**尽量真实地估计实盘净收益，并尽早发现策略无效**。宁可低估，不可高估。
- 成交规则、出场策略、风控规则、仓位规则与实盘（07）逐条对应。任何一方修改，另一方同步修改，并在两个文档里同时更新。
- 信号计算向量化（批量推理）；持仓与组合模拟有路径依赖，使用 numba 编译的顺序循环。**不追求“完全无 for 循环”，追求正确。**
- 回测引擎与模型解耦：输入只是 `signals.parquet`，P3 阶段先用规则策略 R0（05 §2）的信号开发和验证引擎，P4 再接入模型信号。
- 已知的偏差来源及处理方式集中列在 §9，实现与评审时逐条核对。

## 3. 成交模拟规则

以下 t 为信号 K 线，`j` 为持仓期间的 K 线序号。执行延迟 `lat` 默认 1 秒（`base` 情景），`stress` 情景为 3 秒，对应使用 03 §2.2 的 `p_1s/hi_post_1s/lo_post_1s` 或 `p_3s/hi_post_3s/lo_post_3s`。下文以 1 秒为例书写。

### 3.1 开仓条件（全部满足）

1. `is_sample = 1` 且 `p ≥ θ`，且 `t+1` 分钟不是补齐分钟（`is_filled = 0`）。
2. 该币当前无持仓，且不在止损冷却期（该币上一次止损出场后 `cooldown_bars = 15` 根内不再开仓）。
3. 组合持仓数 < `max_positions`（§5.4）。同一时刻候选多于空位时，按 `p` 降序、`m` 降序取。
4. 当日（UTC）已实现亏损未达 `daily_loss_stop`（§5.4）。
5. 追价保护：`p_1s(t+1) ≤ c_t × (1 + max_chase)`，默认 `max_chase = 0.3%`。不满足则放弃（对应实盘限价 IOC 未成交）。
6. 按 §5 计算出的名义价值通过最小下单额、数量取整与保证金校验。
7. 权益未低于 §5.3 的权益下限。

### 3.2 开仓价格

```
P_fill = p_1s(t+1) × (1 + half_spread + slip_entry)
```

- `p_1s(t+1)`：下一根 K 线开盘 1 秒后的最后一笔真实成交价。实盘从 K 线收盘到订单到达撮合约需 0.4~1 秒（07 §4），突破行情里这段时间价格往往已经上移，用 `o_{t+1}` 会系统性高估。
- `half_spread`：吃单买在卖一价，而 K 线与逐笔价是买卖混合价。历史无盘口数据，取 `max(0.5 × tick_rel, half_spread_min)`，`half_spread_min` 默认 1 bp；影子盘期间用 `bookTicker` 实测各币价差中位数后更新（07 §8.6）。
- 数量按 `stepSize` 向下取整。初始止损 `D0 = P_fill × (1 - sl)`，按 `tickSize` 向下取整；`sl` 按 04 §7.1 由 t 时刻 ATR 计算。

### 3.3 出场策略 `trade.common.exits`（回测与实盘共用）

出场策略是一个纯数值状态机：每根 K 线收盘时输入该 K 线数据，输出“下一根 K 线生效的止损价、封顶止盈价、是否在下一根开盘离场”。**状态只在 K 线收盘时更新，更新结果从下一根 K 线起生效**——这是追踪类策略能用 1 分钟 K 线如实回测的前提（在同一根 K 线内先用最高价抬止损、再用最低价判止损，是常见的隐性未来函数）。

记 `R = P_fill × sl`（1R 的价格距离），`atr_abs = ATR14_t`（入场时刻的 ATR 绝对值，持仓期间固定，不随持仓期 K 线更新），`HH` 为入场以来已收盘部分的最高价（入场 K 线用 `hi_post_1s`）。

**`trail`（默认）**

| 参数（`exits.yaml`）     | 默认     | 含义                                                                           |
| :----------------------- | :------- | :----------------------------------------------------------------------------- |
| `be_trigger_r`           | 1.0      | `HH ≥ P_fill + 1.0R` 后，止损上移到保本价 `P_fill × (1 + be_offset)`           |
| `be_offset`              | 0.15%    | 覆盖往返手续费与滑点，保本出场基本不亏                                         |
| `trail_trigger_r`        | 1.5      | `HH ≥ P_fill + 1.5R` 后启动追踪：`stop = max(stop, HH − k_trail × atr_abs)`    |
| `k_trail`                | 1.5      | 追踪距离（ATR 倍数），调参候选 {1.0, 1.5, 2.0}                                 |
| `tp_cap_r`               | 4.0      | 封顶止盈：限价单挂在 `P_fill + 4R`，防止急拉后的急跌回吐（极端拉盘时直接兑现） |
| `stall_bars` / `stall_r` | 20 / 0.5 | 入场后 20 根内 `HH` 始终未达到 `P_fill + 0.5R`：视为“无进展”，下一根开盘离场   |
| `H_max`                  | 120      | 最长持仓根数，调参候选 {60, 120, 240}                                          |

止损只上移不下移；新止损与旧止损相差不足 `max(1 tick, 0.1R)` 时不更新（减少实盘改单次数，回测同样处理）。

**`fixed`（对照）**：止损 `D0` 不动，限价止盈 `P_fill × (1 + rr × sl)`，`H_max = H_label`。与 v1.x 的行为一致。

**`partial`（预留，P3 不实现）**：50% 仓位在 `+1.5R` 限价止盈，剩余按 `trail` 处理。只有在单笔名义价值 ≥ 4 × `minNotional` 时才能启用，否则拆分后的单子低于最小下单额；10 USDT 本金下不可用。

**逐根判定（j = t+1 … t+H_max）**，`stop_j`、`cap_j` 为上一根收盘时计算出的生效值：

```
j = t+1（入场 K 线）：lo = lo_post_1s(j)，hi = hi_post_1s(j)，不考虑跳空
j > t+1：lo = l_j，hi = h_j

若 lo ≤ stop_j：
    止损（或保本/追踪止损）出场。
    出场价 = max(l_j, min(stop_j, o_j) × (1 - slip_stop))（j > t+1 时考虑跳空 o_j < stop_j），吃单费率
否则若 hi ≥ cap_j × (1 + tp_penetration)：
    封顶止盈出场。出场价 = cap_j，挂单费率
同一根 K 线两者都满足时，按止损处理（保守）
收盘后更新状态机；若触发“无进展”或到达 H_max：
    在下一根开盘离场：出场价 = p_1s(j+1) × (1 - half_spread - slip_exit)，吃单费率
```

- `tp_penetration`：默认 1 bp。价格仅“摸到”限价不一定成交（队列靠后），要求穿越才算成交。
- 持仓跨越资金费结算时刻（以 fundingRate 数据中的实际结算时间戳为准，不硬编码 8 小时）：`PnL -= funding_rate × 名义价值`（费率为正时多头支付）。
- 持仓期间遇到补齐分钟（`is_filled = 1`，数据缺失）：该分钟不判定，记录 `data_gap` 次数；若缺失跨越了止损价（下一根有效 K 线 `o_j < stop_j`），按跳空处理。
- 实盘中止损上移需要先挂新止损单、再撤旧单（07 §5.2），新单生效前约 1 秒内旧止损仍在。回测按“新止损整根 K 线生效”处理，这一点略偏乐观，由 S8 逐笔重放量化其影响。
- 模拟中断言“止损价始终高于强平价”，违反即报错（说明仓位校验有缺陷）。

### 3.4 实现要点

“单笔交易的出场结果”只取决于该币的 K 线与入场信息，不取决于组合状态，因此实现分两步：

1. **逐笔预计算**（numba，按币并行）：对每个满足条件 1 和 5 的候选 t，调用 `exits` 的 numba 版本，算出假如开仓的 `P_fill, 出场时间, 出场价, 出场类型, 毛收益率, 费用率, 止损更新次数`。
2. **组合模拟**（numba，单线程）：把所有币的候选按 `(open_time, -p, -m)` 排序，按时间推进；维护各币持仓与冷却状态、持仓槽位、权益（含按 `c_t` 计价的未实现盈亏）、当日已实现盈亏；调用 §5 的仓位函数决定接受或拒绝每个候选。组合模拟对不同仓位配置（§5.1 的两次运行、§5.5 的扫描）重复执行，逐笔预计算只做一次。

- `exits` 与 `sizing` 都实现为“纯数值参数的 numba 函数 + Python 包装函数”，两者共用同一份测试用例；实盘调用 Python 包装函数。
- `trade.backtest.event_sim` 是一个**事件驱动的纯 Python 参考模拟器**：逐分钟回放 bars，调用实盘引擎同一套决策、风控、出场、仓位代码（不经过网络），用于 §7 S9 对拍。它慢，但它是“实盘到底会怎么做”的标准答案。

## 4. 成本模型

### 4.1 手续费

使用者为 **VIP0、不使用 BNB 抵扣**。来自 `base.yaml` 的 `fees`（挂单 0.02%、吃单 0.05%，以币安官方费率页为准）。实盘启动时读取账户实际费率并比对（09 §4），费率变化需更新 `base.yaml` 并重跑回测。

| 动作                                   | 费率 |
| :------------------------------------- | :--- |
| 开仓（限价 IOC，视为吃单）             | 吃单 |
| 封顶止盈 / 固定止盈（限价单）          | 挂单 |
| 止损、保本止损、追踪止损（条件市价单） | 吃单 |
| 无进展离场、超时平仓（市价）           | 吃单 |

按 VIP0，“吃单开仓 + 挂单止盈”往返 0.07%，“吃单开仓 + 吃单离场”往返 0.10%。`trail` 策略下多数出场为吃单，成本比 `fixed` 略高，这一点会如实体现在回测里。

### 4.2 滑点

单边滑点（比例，另加 §3.2 的 `half_spread`）：

```
slip = slip_min + Y × rv_15_raw × sqrt(notional / (qv_t + ε))
```

- `slip_min`：默认 1 bp；`rv_15_raw` 为未标准化的 15 分钟 1m 收益标准差；`qv_t` 为信号 K 线成交额；`Y = 1.0`（平方根冲击模型系数）。
- `slip_entry = slip_exit = slip`，`slip_stop = 2 × slip`（止损通常发生在单边急跌中）。

### 4.3 压力情景（每次回测必须全部运行）

| 情景        | 规则                                                                              | 用途                     |
| :---------- | :-------------------------------------------------------------------------------- | :----------------------- |
| `base`      | 上述默认，执行延迟 1 秒                                                           | 主结果                   |
| `stress`    | 滑点 × 2；`half_spread_min` × 2；止盈也按吃单费率；**执行延迟 3 秒**（`p_3s` 等） | 闸门要求仍为正           |
| `hell`      | 单边固定滑点 0.15%，所有成交按吃单费率，延迟 3 秒                                 | 观察用，不作为闸门       |
| `breakeven` | 二分搜索使净收益 = 0 的单边固定滑点                                               | 报告“盈亏平衡滑点”（bp） |

## 5. 仓位与资金

> 本节是仓位计算的**唯一规格来源**，回测（`trade.backtest.portfolio`）与实盘（`trade.live.risk`）调用同一个函数 `trade.common.sizing.calc_notional()`，禁止各写一份。07 只引用本节。

### 5.1 两次运行

| 运行                        | 用途                                                | 设置                                                                                                                              |
| :-------------------------- | :-------------------------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------- |
| **参考运行**（`reference`） | 闸门判定（08 §3），只看比例指标，排除小本金取整干扰 | `initial_equity = 10000`、`fixed_risk`、`risk_per_trade = 0.005`、`base = initial`（不复利）、`leverage = 5`、`max_positions = 3` |
| **实盘配置运行**（`user`）  | 让使用者看到“按我自己的设置，10 USDT 会变成多少”    | `configs/sizing.yaml` 的设置（§5.4：10 USDT、每笔 20%、5x、复利）、真实最小下单额与数量步长                                       |

报告中两者分开展示。`user` 运行会如实体现小本金下的各种放弃开仓（最小下单额、取整、权益下限）。

记基准金额为 `B`：`base = initial` 时为初始本金，`base = equity` 时为开仓时的**当前账户权益**（钱包余额 + 未实现盈亏）。实盘与 `user` 运行都使用 `base = equity`：

- 权益 10 USDT → 每笔保证金 2 USDT，名义价值 10 USDT。
- 权益 100 USDT → 每笔保证金 20 USDT，名义价值 100 USDT。

记**单笔保证金** `M = B × position_frac`，名义价值 `N = M × leverage`。

### 5.2 仓位模式

| 模式                         | 含义                               | 公式（未截断前）                                |
| :--------------------------- | :--------------------------------- | :---------------------------------------------- |
| `fixed_fraction`（实盘默认） | 每笔占用**保证金**为本金的固定比例 | `notional_raw = B × position_frac × leverage`   |
| `fixed_risk`                 | 每笔止损时亏损本金的固定比例       | `notional_raw = B × risk_per_trade / loss_rate` |

- `loss_rate = sl + slip_stop + half_spread + 2 × fee_taker`，即初始止损出场时每 1 USDT 名义价值的预计亏损。
- `position_frac` 指**保证金**占当前权益的比例。`position_frac` 范围 `[0.01, 0.95]`；`risk_per_trade` 范围 `[0.001, 0.05]`。

### 5.3 截断、取整与下限（两种模式通用）

```
notional = min(
    notional_raw,
    B × max_risk_per_trade / loss_rate,      # 单笔最大亏损硬上限（占权益），默认 2.5%
    liq_cap × mean_60(qv),                   # 流动性上限，默认 liq_cap = 0.5%
    available_margin × 0.95 × leverage       # 当前可用保证金（扣除其他持仓占用后）
)
qty = floor(notional / P / stepSize) × stepSize
qty × P < minNotional × 1.1        → 放弃，原因 below_min_notional
qty × P < 0.9 × notional           → 放弃，原因 step_rounding（取整损失超过 10%）
```

- 截断发生时记录 `size_capped_by`（`risk_cap` / `liquidity` / `margin`），报告中统计各原因的次数。
- **权益下限**：当 `B × position_frac × leverage < 全部交易币中最小的 minNotional × 1.1` 时，任何币都无法开仓，回测记录 `equity_floor` 并停止开仓（实盘对应 07 R14）。按默认设置（20%、5x、最小下单额 5 USDT），权益下限约 **5.5 USDT**。

### 5.4 仓位配置（使用者确认：10 USDT、每笔 20%、5x）

```yaml
initial_equity: 10 # 初始本金（USDT），用于 user 运行
mode: fixed_fraction # fixed_fraction | fixed_risk
position_frac: 0.20 # 每笔保证金 = 当前权益 × 20%
leverage: 5
max_positions: 3 # 0.20 × 3 = 0.60 ≤ 0.95
base: equity # 按当前权益复利
risk_per_trade: 0.005 # 仅 fixed_risk 模式使用
max_risk_per_trade: 0.025 # 单笔止损亏损硬上限（占权益）
daily_loss_stop: 0.05 # 当日亏损达权益 5% 停止开仓
daily_loss_halt: 0.08 # 当日亏损达 8% 全平并停机
max_drawdown_halt: 0.20 # 从峰值回撤 20% 停机，人工复核
max_consecutive_losses: 6
liq_cap: 0.005
maint_margin_rate: 0.01 # 回测用维持保证金率（保守值）；实盘用 leverageBracket 实际值
```

单笔盈亏速查（VIP0，含手续费与基准滑点、点差估算；对“该笔保证金”和“总权益”的比例与权益大小无关）：

| 情形                    | 价格变动  | 占该笔保证金 | 占总权益  | 权益 10 USDT 时              |
| :---------------------- | :-------- | :----------- | :-------- | :--------------------------- |
| 最窄初始止损            | −0.5%     | 约 −3.3%     | 约 −0.66% | −0.066 USDT                  |
| 典型初始止损            | −0.8%     | 约 −4.8%     | 约 −0.96% | −0.096 USDT                  |
| 最宽初始止损            | −1.5%     | 约 −8.3%     | 约 −1.66% | −0.166 USDT                  |
| 保本止损出场            | 约 +0.15% | 约 0         | 约 0      | 约 0                         |
| 追踪止损出场（典型 2R） | 约 +1.6%  | 约 +7%       | 约 +1.4%  | +0.14 USDT                   |
| 封顶止盈（4R，典型）    | 约 +3.2%  | 约 +15.5%    | 约 +3.1%  | +0.31 USDT                   |
| 强平（参考）            | 约 −19%   | −100%        | −20%      | 正常情况下止损远早于强平触发 |

估算口径：亏损 = 名义价值 × (sl + 止损滑点 0.04% + 点差 0.01% + 双边吃单费 0.10%)；盈利 = 名义价值 × (涨幅 − 滑点与点差约 0.04% − 手续费 0.07%~0.10%)。实际以回测动态模型为准。

配置加载与修改时校验（不通过则拒绝，并给出提示文案）：

1. `position_frac × max_positions ≤ 0.95`。
2. `当前权益 × position_frac × leverage ≥ 交易币中位数 minNotional × 1.1`。
3. **强平距离**：`sl_max ≤ 0.5 × (1 / leverage − maint_margin_rate)`。5x 时右侧约 9.5%；`leverage` 不得超过该币杠杆分层允许的最大值。
4. `max_risk_per_trade ∈ [0.005, 0.10]`，且 `≥ leverage × position_frac × (sl_max + 0.15%)`；`daily_loss_stop < daily_loss_halt`。
5. 生成“仓位设置摘要”（模式、比例、杠杆、单笔亏损/盈利区间、满仓保证金占用、权益下限），在启动日志、通知、看板控制页显示。

### 5.5 比例敏感性扫描

每次回测额外按 `sizing_sweep`（默认 `position_frac ∈ [0.1, 0.15, 0.2, 0.3]`，`leverage = 5`，`max_positions = min(3, floor(0.95 / position_frac))`，`initial_equity = 10`，复利）重跑组合模拟，输出：期末权益 / 净收益率、最大回撤、最大单日亏损、最长连续亏损、触发日亏损停止天数、放弃开仓次数（按原因）、是否触及权益下限。比例变化会改变同时可持仓数与因保证金不足放弃的交易，必须重跑组合模拟，不能按比例缩放收益。

### 5.6 合约保证金校验

逐仓保证金 = `notional / leverage`，所有持仓保证金合计 + 新仓保证金不得超过可用余额的 95%。

## 6. 指标

## 7. 健全性检验（`trade.backtest.sanity`）

这些检验用于发现“回测看起来很好但其实是错的”，**全部必须执行并写入报告**（均基于 `reference` 运行）。

| 编号 | 检验                     | 方法                                                                                                                              | 通过标准                                                                         |
| :--- | :----------------------- | :-------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------- |
| S1   | 随机入场基准             | 在同样的预过滤样本中随机抽取入场点，保持每币每月交易笔数与策略相同，出场规则相同，重复 1000 次                                    | 策略净收益 > 随机分布的 95 分位                                                  |
| S2   | 标签打乱                 | 训练集内随机打乱 `y` 后重新训练 M1（单种子），跑测试段回测                                                                        | `base` 情景 PF ≤ 1.05（否则存在信息泄露）                                        |
| S3   | 特征平移                 | 所有特征向后平移 1 根后推理与回测                                                                                                 | 净收益不高于原结果 + S1 标准差的 1 倍                                            |
| S4   | 阈值扰动                 | θ ± 0.04                                                                                                                          | 两侧 `base` PF 均 ≥ 1.1                                                          |
| S5   | 时间稳定性               | 10 个测试月、5 折分别统计                                                                                                         | ≥ 6 个月净收益为正，且 ≥ 4 折净收益为正                                          |
| S6   | 集中度                   | 去掉最佳单币；去掉收益最高 1% 交易                                                                                                | 两种情况下净收益仍为正                                                           |
| S7   | 实盘路径一致性           | (a) 同一起点：批量特征 vs 实盘增量特征与推理，2 币 × 2 天；(b) 实盘口径：从 30 天预热开始增量递推，与离线全历史结果比较           | (a) `p` 绝对误差 < 1e-5、信号完全一致；(b) `p` 绝对误差 < 1e-3、信号一致率 ≥ 99% |
| S8   | 逐笔成交重放（**必做**） | 在服务器上保留 3 个币 × 1 个测试月的原始 aggTrades，按逐笔顺序重放入场、止损更新（含新单生效前的 1 秒旧止损窗口）、止损与止盈触发 | 净收益差异 < 15%，出场类型一致率 ≥ 90%；否则 K 线级假设过于乐观                  |
| S9   | 事件驱动对拍             | `event_sim`（调用实盘引擎代码）与快速模拟器在 2 币 × 1 个月上对比逐笔交易                                                         | 交易列表完全一致（入场/出场时间与类型相同，价格误差 < 1e-9）                     |
| S10  | 名单外盲测               | 盲测币组（03 §4.4）的测试段结果                                                                                                   | `base` 情景 PF ≥ 1.0；与训练币组 PF 的差距在报告中说明                           |
| S11  | 试验次数登记             | 读取 `EXPERIMENTS.log` 中在测试段上运行过的全部配置数 N，计算 Deflated Sharpe Ratio                                               | 必须报告 N 与 DSR；DSR 对应概率 < 0.9 时报告首页标红警示                         |
