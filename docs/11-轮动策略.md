# 11 轮动策略（山寨币截面动量 + 大盘状态过滤）

> 本章规格对应代码：`trade.rotation`（配置、数据、信号、引擎、指标、阶段守卫）与 `scripts/rotation_backtest.py`。
> 打分与调仓代码在回测与将来实盘中共用同一份实现；冻结配置为 `configs/rotation_frozen.yaml`，冻结文件的 SHA256 记在 `docs/rotation/phase1.md`。

## 1. 目标与范围

- 月度交易范围 `U(R)` 内做**截面动量轮动**：每 8 小时按“过去 L 天对数收益 ÷ 过去 L 天 1h 收益标准差”排序，持有前 K 名；只做多、5x 逐仓。
- 大盘状态过滤：BTC 在 N 日均线之上、且 `U(R)` 等权山寨指数 7 日收益为正时才开仓，否则目标仓位为 0。
- 灾难止损：以 ATR 自适应止损距离（硬上限 15%）退出，控制单币尾部风险。
- 交易范围仍来自 `data/universe/{YYYY-MM}.json`（03 §4）；本策略不改选币规则、不改快照。

## 2. 配置

`configs/rotation.yaml`（工作配置）与 `configs/rotation_frozen.yaml`（冻结配置）字段完全一致，由 pydantic 模型 `trade.rotation.config.RotationConfig` 校验，未知字段报错。

| 字段                  | 类型  | 默认 | 含义                                                             |
| :-------------------- | :---- | ---: | :--------------------------------------------------------------- |
| `btc_symbol`          | str   | BTCUSDT | 大盘状态过滤基准                                              |
| `ma_days`             | int   | 50   | N：BTC 1h 收盘价的 N×24 小时均值                                  |
| `lookback_days`       | int   | 7    | L：动量打分回看天数                                               |
| `top_k`               | int   | 5    | K：目标持仓数                                                     |
| `buffer_mult`         | int   | 2    | 缓冲区倍数：已持有且仍在前 `buffer_mult × K` 名则继续持有          |
| `rebalance_hours`     | int   | 4    | 调仓周期（小时），只能是 1 / 4 / 8 且整除 24                      |
| `score_lag_hours`     | int   | 4    | 打分截止相对调仓时刻的滞后小时数                                   |
| `alt_index_days`      | int   | 7    | 山寨等权指数收益回看天数                                           |
| `min_score`           | float | 0.0  | 入选最低打分（`score ≤ min_score` 不选）                           |
| `stop_atr_period`     | int   | 14   | ATR 周期（4h 根数）                                               |
| `stop_atr_mult`       | float | 3.0  | `k_stop`：止损距离 = `k_stop × ATR14(4h) ÷ 入场价`                 |
| `stop_max_pct`        | float | 0.15 | 止损距离硬上限（不参与参数搜索）                                   |
| `stop_cooldown_hours` | int   | 24   | 止损后该币禁止再买入的小时数                                       |
| `exit_check_hours`    | int   | 0    | 0 = 关闭；N ≥ 1 = 每 N 个整点只做卖出检查（不在整点买入）           |
| `funding_filter`      | bool  | false| 只选资金费 ≤ 当月 `U(R)` 中位数的币                                 |
| `oi_bonus`            | float | 0.0  | `score += oi_bonus × z(Δlog OI)`，0 = 关闭                         |
| `oi_bonus_days`       | int   | 7    | OI 变化回看天数                                                    |

校验：`rebalance_hours ∈ {1, 4, 8}` 且整除 24；`exit_check_hours = 0` 或整除 24；`score_lag_hours ≥ 1`；`stop_max_pct ∈ (0, 0.5)`。

## 3. 数据

### 3.1 聚合

- 1m K 线来自 `data/bars/{alias}/{YYYYMM}.parquet`，按 UTC 对齐聚合 1h（`open_time // 3600000`）与 4h（`open_time // 14400000`）：桶内首开、末收、最高、最低、成交额求和。
- 1h 面板覆盖「评估起点 − 预热天数」到评估终点，缺数据的整点为 NaN。
- 4h 序列用于 ATR：`TR = max(high − low, |high − 前收|, |前收 − low|)`，ATR 取最近 `stop_atr_period` 根已收盘 4h K 线的 TR **简单均值**；调仓时刻 t 可用的最新 4h K 线须满足 `open_time + 4h ≤ t`。
- 资金费结算事件由 `trade.common.funding.funding_settlements` 提取（`funding_rate` / `funding_time` 为已向后对齐的最近一期）。
- 未收盘的 K 线一律不用：1h 收盘价的下标不得超过「调仓时刻 − 1 小时」对应的整点。

### 3.2 分钟块与成交数据

- 模拟按月推进：每月一块，行 = 该月需要的 symbol（本月、上月、下月交易范围的并集），列 = 该月每分钟的 `open / low / close / p_1s / quote_volume`，缺失分钟为 NaN。
- 流动性上限用最近 60 个**已收盘**分钟的 `quote_volume` 均值；月初前 60 分钟沿用上月末 60 分钟（跨块保留）。

### 3.3 交易范围

- 月 `m` 的交易范围为该月快照的 `symbols`；`universe.yaml` 的 `reviewed` 不为 `true` 时拒绝运行。
- 新进入（上月不在 `U(R)`）的币自该月 `rebalance_ms + new_entry_delay_days` 起才可买入。

### 3.4 读取守卫

- 单月读取 `read_month_bars` 与 `trade.data.loader.load_bars` 同一判定：请求区间的 `end_ms > holdout_start_ms`（M23 起点 2026-08-01）且 `allow_holdout=False` 时抛错。

## 4. 信号

记调仓时刻为 `t`（UTC 整点，`t % rebalance_hours = 0`），`i(t)` 为 t 所属整点在 1h 面板中的下标。

### 4.1 大盘状态过滤

在 t 时刻用已收盘的最后一根 1h K 线 `i_f = i(t) − 1`（即收盘于 t 的那根）：

```
通过 = close_BTC[i_f] > mean(close_BTC[i_f − N×24 + 1 : i_f + 1])
      且 mean_alt( close[i_f] / close[i_f − 7×24] − 1, 币 ∈ U(R) ) > 0
```

- 山寨等权指数只统计两端收盘价都有效的币；有效币少于 5 个、BTC 均线窗口内有缺失、或窗口不足时，一律按“不通过”处理，并在决策里记录原因（`btc_ma_insufficient` / `btc_ma_missing` / `btc_below_ma` / `alt_index_*`）。
- 过滤不通过时：本次调仓不买入，且**卖出全部持仓**（现行情景点按 `filter_off` 记录）。

### 4.2 打分

```
i_last  = i(t − score_lag_hours) − 1                 # 在 t − lag 时刻已收盘的最后一根 1h K 线
i_first = i_last − L×24
score   = ln(close[i_last] / close[i_first]) ÷ std(1h 对数收益, i_first+1 … i_last, ddof=1)
```

- 打分窗口内任何整点收盘价缺失、或标准差为 0 的币不参与排名；`score ≤ min_score` 的币不选。
- 可选开关（默认关闭）：
  - `funding_filter`：只保留 t 时刻最近已结算资金费 ≤ 当月 `U(R)` 内该值中位数的币（中位数按当月 `U(R)` 全部有值币计算，有效币少于 5 个时本轮不入选任何币）。
  - `oi_bonus > 0`：`score += oi_bonus × z(Δlog OI)`，`Δlog OI = ln(OI[i_last] / OI[i_last − oi_bonus_days×24])`，`z` 在本次候选币截面内做标准化（`ddof=1`，标准差为 0 或有效币少于 2 个时不加分）。

### 4.3 排名、缓冲区与调仓

- 候选币按 `score` 降序排名（同分按 symbol 字典序），记名次 `rank`。
- 已持有的币满足以下全部条件则继续持有，否则卖出：
  - 过滤通过；
  - 仍在当月 `U(R)`；
  - `rank ≤ buffer_mult × K`。
- 买入清单：按名次从前往后取 `rank ≤ K` 且未持有的币，直到持仓数达到
  `min(max_positions, max(K, 保留的持仓数))`；买入时跳过未解锁的新进入币与止损冷却中的币。
- 每个调仓时刻**先卖后买**，两者都使用同一根 1m bar 的 `p_1s` 成交。
- `exit_check_hours ≥ 1` 时，在非调仓的整点上只执行卖出检查（同一套卖出条件），不在整点买入。

## 5. 成交、成本与仓位

### 5.1 成交价

- 调仓时刻 t 之后第一根 1m bar（`open_time = t`）的 `p_1s` 为该笔的参考价；缺失（NaN）时本次不交易，记 `p1s_missing` 并在下一次调仓重试。
- 买入价 `= p_1s × (1 + 半价差 + 滑点)`；卖出价 `= p_1s × (1 − 半价差 − 滑点)`。
- 半价差 `= max(0.5 × tickSize / 价格, backtest.yaml: costs.half_spread_min)`；滑点用 `trade.common.costs.slip`（平方根冲击，`notional_ref = initial_equity × position_frac × leverage`，`rv_15_raw` 取最近 15 个 1m 对数收益的标准差，`qv` 取信号分钟成交额）。
- 手续费按 `base.yaml: fees.taker` 双边计。

### 5.2 灾难止损

- 入场时确定止损距离：`stop_pct = min(stop_atr_mult × ATR14(4h) ÷ 入场价, stop_max_pct)`；止损价 `= 入场价 × (1 − stop_pct)`。
- 持仓期间用 1m `low` 判断：`low ≤ 止损价` 即触发（入场分钟不参与判定）。
- 触发成交价：该分钟开盘价已低于止损价（跳空）时按 `开盘价 × (1 − 2 × 滑点)`，否则按 `止损价 × (1 − 2 × 滑点)`。
- 触发后该币 `stop_cooldown_hours` 内不再买入。
- 持仓币在新月份没有任何分钟数据时，按上一可得收盘价扣卖出成本平仓，出场原因记 `data_end`。

### 5.3 仓位（`trade.common.sizing.calc_notional`，fixed_risk）

```
风险额      = 钱包余额 × risk_per_trade
notional_raw = 风险额 ÷ loss_rate
loss_rate   = stop_pct + 2 × 滑点 + 半价差 + 2 × fee_taker
notional    = min(notional_raw,
                  钱包余额 × max_risk_per_trade ÷ loss_rate,
                  钱包余额 × position_frac × leverage,      # 每仓上限，截断原因 position_cap
                  liq_cap × mean_60(quote_volume),
                  available_margin × 0.95 × leverage)
qty         = floor(notional ÷ 入场价 ÷ stepSize) × stepSize
qty × 入场价 < minNotional × 1.1 → 放弃（below_min_notional）
qty × 入场价 < 0.9 × notional    → 放弃（step_rounding）
```

- `钱包余额 = 初始本金 + 已实现盈亏`（不含未实现，06 §5.2 口径）；`available_margin = 钱包余额 × 0.95 − 已占用保证金`。
- 交易规则（`tickSize` / `stepSize` / `minNotional`）取 `artifacts/exchange_info/rules.json`；缺失时抛错。
- 持仓数为 `sizing.yaml: max_positions` 上限；杠杆 `leverage`。

### 5.4 资金费

持有多头在结算时刻 `ft`（`entry_ts < ft ≤ exit_ts`）按 `notional × funding_rate` 扣减钱包余额（正费率支付）。资金费计入该笔净盈亏。

### 5.5 风控 R5~R8

逐分钟把盯市权益传入 `trade.common.risk_rules.risk_step`：

- R5（当日亏损达 `daily_loss_stop`）停止当日开仓；
- R6（当日亏损达 `daily_loss_halt`）/ R8（回撤达 `max_drawdown_halt`）在下一分钟全平并停机；
- R7（连续止损达 `max_consecutive_losses`）暂停开仓 `consecutive_loss_pause_min` 分钟。

`halt_mode` / `halt_reset_days` 取 `backtest.yaml: risk`。情景 `nohalt` 把 `daily_loss_halt`、`max_drawdown_halt` 置 0.99、`max_consecutive_losses` 置 10000（R5 仍生效）。

## 6. 指标与产物

- 日末盯市权益（UTC 日）：`equity.parquet`（`scenario, ts_ms, equity, drawdown`）；`trades.parquet` 为逐笔明细。
- 年化夏普 `= mean(日收益) ÷ std(日收益) × √365`；日收益按 UTC 自然日补齐（无采样的日子收益 0，首日相对初始权益）。
- 最大回撤按日末盯市权益峰值到谷底计算；月收益按 UTC 自然月、缺失月补 0；季度收益按自然季度。
- 评估月份按顺序切成 4 段（`eval_segments`），统计 `positive_segments`。
- 换手率 `= Σ(入场名义 + 出场名义) ÷ 平均日末权益 ÷ 评估年数`。
- 成本占毛收益比例 `= Σ(按 p_1s 计的毛收益 − 净收益) ÷ Σ毛收益`。
- 出场原因分布、持仓天数分位数（p10/p50/p90）、跳过原因统计（`below_min_notional` / `step_rounding` / `p1s_missing` / `atr_missing` / `cooldown` / `new_entry_delay` / `exit_p1s_missing` / `data_end`）。
- 日收益均值的 bootstrap 95% 置信区间：按 UTC 日整日有放回重抽样 10000 次，种子 42。
- 产物目录 `artifacts/reports/rotation/<run_id>/`：`summary.json`（全部指标 + 月/季/分段 + 出场与跳过分布）、`trades.parquet`、`equity.parquet`、`report.md`。

## 7. 运行与阶段守卫

`scripts/rotation_backtest.py --stage research|confirm|final`，守卫写死在 `trade.rotation.stage`，不能由命令行改写上限。

| stage      | 评估区间                                 | 允许读封存集 | 前置条件                                                                 |
| :--------- | :--------------------------------------- | :----------- | :----------------------------------------------------------------------- |
| `research` | M2 起点 2024-11-01 ~ M12 末尾 2025-10-01 | 否           | 无                                                                       |
| `confirm`  | M2 起点 ~ M22 末尾 2026-08-01            | 否           | `docs/rotation/phase1.md` 结论为 PASS，且 `phase2.md` 不存在或非 PASS     |
| `final`    | 2026-08-01 ~ 2026-12-01（预热可读 2026-07） | 是         | `phase2.md` 结论为 PASS，且 `FINAL_RUNS.log` 无 `run_id=rot_final` 完成记录 |

- 预热起点：`research` / `confirm` 从 M1 起点（2024-10-01）前 30 天开始读；`final` 从 2026-07-01 开始读。
- 情景（一次运行可同时输出）：`base`、`cost2x`（费率、半价差、滑点 ×2）、`nohalt`（关 R6/R8 停机与 R7 暂停）、`delay1`（决策整体延后一个调仓周期）、`shuffle`（截面打分随机打乱，种子 42）、`neighbors`（读 `docs/rotation/phase1.md` 的 `neighbor_grid`，把冻结组中只差一个参数的各组跑一遍 `base`）。
- `--params key=value` 覆盖轮动配置、`--sizing-params key=value` 覆盖仓位配置（参数搜索用）。
- 每次运行按 `kind=tuning` 追加一行 JSON 到 `artifacts/reports/EXPERIMENTS.log`（`--no-log` 关闭）。
- `scripts/rotation_report_confirm.py --run-dir <rot_confirm 目录>` 是只读汇总脚本：把该次 `confirm` 运行的 `summary.json`、`equity.parquet`、`trades.parquet`、`neighbors.json` 中的 M13~M22 区间切片，用 `trade.rotation.metrics.compute_metrics` 计算测试段指标与逐项判定，写出 `confirm_report.md` 与 `confirm_summary.json`；不重算策略、不改变任何计算。

- `--stage final` 是唯一允许 `allow_holdout=True` 的入口。
