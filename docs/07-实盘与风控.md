# 07 实盘与风控

> 本文档描述在实盘服务器（02 §5）上运行的交易进程 `trade.live`。市场为币安 USDⓈ-M 永续合约，单向持仓、逐仓、5x 杠杆。
> 币安接口清单见 [09-币安数据与API.md](./09-币安数据与API.md)。接口细节（端点路径、参数、权重、条件单接口）会变化，**实施时必须以 developers.binance.com 的最新文档为准**，本文给出的是行为规格。

## 1. 运行模式

| 模式     | 行情   | 下单                         | 用途                                     |
| :------- | :----- | :--------------------------- | :--------------------------------------- |
| `paper`  | 测试网 | 测试网真实下单               | 验证下单、止盈止损、对账、异常处理全流程 |
| `shadow` | 正式网 | 不下单，用 06 的成交规则模拟 | 验证信号与回测一致、观察真实滑点环境     |
| `live`   | 正式网 | 正式网真实下单               | 实盘                                     |

命令：`python scripts/run_live.py --mode {paper|shadow|live} --config configs/live.yaml`

`live` 模式启动时要求命令行再输入一次确认参数 `--i-understand-the-risk`，否则拒绝启动。

## 2. 启动流程

按顺序执行，任一步失败则退出并发送飞书告警：

1. 加载并校验配置（含 06 §5.4 仓位校验）；从环境变量读取密钥与飞书 Webhook（02 §7）。
2. **时钟检查**：请求服务器时间 3 次，本机与服务器时差中位数 > 500 ms 则退出。
3. **端点选择**：02 §5.3 的测速规则。
4. **交易规则**：拉取 exchangeInfo，缓存每个交易币的 `tickSize`、`stepSize`、`minNotional` 等过滤器以及 `rateLimits`；每 6 小时刷新。
5. **杠杆分层**：拉取每币杠杆分层（09 §3），确认 5x 可用，取对应档位的维持保证金率，执行 06 §5.4 校验 3（强平距离）。
6. **费率核对**：读取账户实际手续费率（09 §4）。与 `base.yaml` 的 VIP0 费率不一致时发送告警，并以实际费率记录到日报（不自动修改配置，回测需由使用者决定是否按新费率重跑）。实际吃单费率高于配置 20% 以上时拒绝以 `live` 模式启动。
7. **模型加载**：`trade.models.artifact.load`，校验特征哈希、市场类型。
8. **账户设置**：确认为单向持仓模式；对每个交易币设置逐仓（ISOLATED）与 `sizing.yaml` 的杠杆（默认 5x）。已有持仓的币跳过修改并记录。
9. **状态恢复与对账**：读取 SQLite 状态库，执行一次完整对账（§6）。
10. **特征预热**：
    - 通过 REST 拉取每币（含 BTCUSDT）最近 `warmup_days` 天的 1m K 线（分批，控制权重），递推 K 线类、环境类特征与 EWM 状态。若状态库中有不超过 6 小时前的 EWM 状态，则只补齐缺口。
    - 订单流类特征依赖逐笔原子量，REST 无法低成本回补。规则：本地有持续录制的原子量（§3.3）则直接使用；否则该币进入“订单流预热”状态，**实时采集满 60 分钟后才允许开仓**，期间订单流类 EWM 状态沿用状态库中最近值，没有则用该币训练期末的统计量（随模型产物保存）。
    - 大单阈值 `whale_thr`：优先用本地录制的前一完整 UTC 日数据计算；其次下载 data.binance.vision 上最新可得的日度文件计算；都没有则沿用最近一次的值。
11. 发送“启动成功”飞书卡片（模式、模型 ID、仓位设置摘要、权益、费率核对结果），订阅行情与用户数据流，进入主循环。

## 3. 实时数据

### 3.1 订阅

| 连接       | 流                                                                     | 说明                        |
| :--------- | :--------------------------------------------------------------------- | :-------------------------- |
| 行情连接 A | `<symbol>@kline_1m`（15 币 + BTCUSDT）、`<symbol>@bookTicker`（15 币） | 低频                        |
| 行情连接 B | `<symbol>@aggTrade`（15 币）                                           | 高频，单独连接避免阻塞 K 线 |
| 用户数据流 | listenKey                                                              | 订单与账户更新              |

- 留出币是否参与实盘交易由 `live.yaml` 的 `trade_holdout: true|false` 控制，默认 `true`（模型是通用的，留出币在回测中也要达标）。
- 交易所会在 24 小时左右断开 WebSocket 连接：程序在连接满 23 小时时主动新建连接，新连接收到首条消息后再关闭旧连接。
- listenKey 每 30 分钟续期一次；收到 `listenKeyExpired` 事件立即重建并触发对账。

### 3.2 分钟收盘判定 `bar_builder`

- 收到 `kline` 事件且 `x = true`（已收盘）时，K 线部分就绪。
- aggTrades 原子量：收到首条 `transact_time ≥ t + 60000` 的逐笔，或分钟结束后已过 300 ms，则视为该分钟逐笔完整。
- 分钟结束 3 秒后 K 线仍未收盘：用 REST 拉取该 K 线补齐，并记录 `ws_kline_late` 事件。
- **逐笔连续性**：检查 `agg_trade_id` 连续递增。出现缺口时用 REST `aggTrades?fromId=` 回补；回补失败则该分钟标记为 `degraded`，该币本分钟及之后 15 分钟内不开仓。
- **延迟监控**：事件时间 `E` 与本机接收时间差 > 2 秒持续 10 秒以上，视为行情延迟，全部币进入“只平不开”（R10）。

### 3.3 原子量录制

实时计算的分钟原子量与 K 线追加写入 `artifacts/live/bars/{symbol}/{YYYYMMDD}.parquet`（每小时落盘一次），用于重启恢复、次日计算大单阈值、§8 的漂移监控以及看板行情页。字段与 03 §2.3 完全一致。

### 3.4 信号记录

每分钟每个通过预过滤的币，把 `symbol, open_time, p, m, 是否开仓, 未开仓原因` 写入状态库 `signals` 表，供看板行情页标注与每日一致性检查使用。

## 4. 主循环时序（每分钟）

```text
T+0 ms       K 线 t 收盘
T+0~300 ms   K 线事件到达、逐笔原子量收齐（每币独立）
             → 计算特征（同 trade.features 增量接口）→ 预过滤
             → 通过预过滤的币：推理得到 p、m
T+~350 ms    读取控制表（runtime_overrides、halt_flag）→ 汇总候选 → 风控检查（§7）→ 按 p、m 排序取空位
T+~400 ms    发送开仓订单（目标：K 线收盘到下单请求发出 < 500 ms）
同时         检查持有中的仓位是否到达时间障碍 → 超时平仓
```

- 单币特征与推理的计算超过 200 ms 记录警告。所有币的处理在一个 asyncio 事件循环中进行，推理放到线程池以免阻塞网络。
- 每一步记录耗时，写入日志和 `latency` 表，用于日报与看板的延迟统计（P50/P95/P99）。
- 每 10 秒把账户快照（钱包余额、未实现盈亏、可用保证金）写入 `equity_snapshots` 表，供看板绘制实时权益曲线。

## 5. 订单执行 `orders`

### 5.1 开仓

- 订单类型：`LIMIT`，`timeInForce = IOC`。
- 限价 = `min(最优卖价 × (1 + 2 × tick_rel), c_t × (1 + max_chase))`，按 `tickSize` 向下取整。这既限制了追价（对应 06 §3.1 条件 5），也避免市价单在流动性突然变差时成交在极端价格。
- 数量 = `trade.common.sizing.calc_notional()`（06 §5，使用实时权益和 §7.1.1 的生效配置）÷ 限价，按 `stepSize` 向下取整；按 06 §5.3 的规则放弃不满足最小下单额或取整损失过大的订单。
- 部分成交：已成交部分 ≥ `minNotional` 则保留并按成交量挂止盈止损；否则立即市价平掉已成交部分（若剩余数量本身低于最小下单额无法平仓，则挂 `reduceOnly` 止损并告警，等待人工处理）。
- 请求返回类型设为“完整结果”，以便从响应直接拿到成交均价；同时以用户数据流的成交回报为准做二次确认。

### 5.2 止盈与止损（成交后立即挂出）

以实际成交均价 `P_fill` 计算 `U`、`D`（06 §3.2 的取整规则）：

| 单   | 类型                      | 关键参数                                                                                                                |
| :--- | :------------------------ | :---------------------------------------------------------------------------------------------------------------------- |
| 止损 | 条件市价单（STOP_MARKET） | 触发价 D、`reduceOnly`（或 `closePosition`）、触发价格类型为**最新成交价**（CONTRACT_PRICE，与回测使用 K 线高低点一致） |
| 止盈 | 限价单 LIMIT GTC          | 价格 U、`reduceOnly`                                                                                                    |

- **止损单必须先于止盈单发出**，并在 1 秒内确认挂单成功。失败重试 2 次仍失败：立即市价平仓并告警。
- 币安合约的条件单已迁移至独立的算法订单接口（09 §3），`OrderManager` 封装为统一的 `place_stop_market()` / `cancel_stop()`，具体端点以最新文档为准。
- 合约没有 OCO：一侧成交后（用户数据流收到成交事件），立即撤销另一侧。即使撤单失败，`reduceOnly` 也保证不会反向开仓；对账任务会清理残留订单。

### 5.3 超时平仓

持仓到达 `t + H` 根 K 线收盘：先撤销止盈、止损单，再发 `MARKET` + `reduceOnly` 平仓。撤单失败不阻塞平仓（`reduceOnly` 保证安全）。

### 5.4 订单标识与幂等

- `newClientOrderId = "trd-{SYMBOL}-{t_minute}-{E|TP|SL|TX}{重试序号}"`，长度不超过交易所上限（36 字符），SYMBOL 过长时用币种在配置中的序号代替。
- 请求超时或返回 5xx 时，订单状态未知：**先按 clientOrderId 查询**，确认不存在后才重发，禁止盲目重发。
- 本程序只管理以 `trd-` 开头的订单，不触碰手工订单（但建议策略使用独立子账户，见 §9）。

### 5.5 错误处理

| 情况                            | 处理                                   |
| :------------------------------ | :------------------------------------- |
| HTTP 429（超频）                | 按 `Retry-After` 暂停，期间只平不开    |
| HTTP 418（IP 被封）             | 立即进入停机流程（§7.3）并告警         |
| 时间戳错误（-1021）             | 重新同步时间偏移后重试一次             |
| 保证金不足                      | 放弃本次开仓，告警                     |
| 过滤器校验失败（价格/数量精度） | 视为程序缺陷，放弃并告警，记录完整参数 |
| 超时 / 5xx                      | 按 §5.4 查询确认                       |

- 持续读取响应头中的已用权重与下单计数（09 §6），超过限额 70% 时停止新开仓直到下一分钟。

## 6. 状态库与对账

### 6.1 SQLite 表

| 表                  | 主要字段                                                                                                                                                                       |
| :------------------ | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `orders`            | client_id、exchange_id、symbol、side、type、price、qty、status、created_ms、updated_ms、raw_json                                                                               |
| `fills`             | exchange_trade_id、client_id、symbol、price、qty、fee、fee_asset、realized_pnl、ts_ms                                                                                          |
| `positions`         | position_id、symbol、signal_t、p、m、entry_price、qty、margin、leverage、U、D、t_exit_deadline、status（OPEN/CLOSED）、exit_type、exit_price、fee、funding、pnl、position_frac |
| `signals`           | symbol、open_time、p、m、opened（0/1）、skip_reason                                                                                                                            |
| `equity_snapshots`  | ts_ms、wallet_balance、unrealized_pnl、available_margin                                                                                                                        |
| `latency`           | ts_ms、stage（bar_close→features→infer→order_sent→ack）、ms                                                                                                                    |
| `risk_state`        | date、realized_pnl、peak_equity、consecutive_losses、halt_flag、safe_mode_reason                                                                                               |
| `feature_state`     | symbol、feature、ewm_mu、ewm_var、updated_ms                                                                                                                                   |
| `runtime_overrides` | key、value、updated_ms、source（`cli` / `dashboard`）（§7.1.1）                                                                                                                |
| `events`            | ts_ms、level、event、symbol、detail_json                                                                                                                                       |

- 所有写入在事务中进行；数据库开启 WAL 模式，使看板可以并发只读查询而不阻塞交易进程。
- 看板对状态库**只读**，唯一例外是通过 `trade.live.control` 写 `runtime_overrides`、`risk_state.halt_flag` 与 `events`（10 §4）。
- `equity_snapshots`、`latency`、`signals` 保留 90 天，每日清理一次。

### 6.2 对账规则

启动时执行一次，之后每 60 秒、以及用户数据流重连后各执行一次。以交易所为准：

| 发现                                   | 处理                                                                   |
| :------------------------------------- | :--------------------------------------------------------------------- |
| 交易所有仓位、本地无记录               | 接管为本地仓位，`D` 设为 `入场价 × (1 - sl_max)`，确保止损单存在，告警 |
| 本地有 OPEN 仓位、交易所无仓位         | 查询该币近期成交补记出场信息，标记 CLOSED                              |
| 有仓位但没有有效止损单                 | **立即补挂止损**；若当前价已低于 D，立即市价平仓                       |
| 存在 `trd-` 前缀挂单但对应仓位已不存在 | 撤销                                                                   |
| 本地与交易所持仓数量不一致             | 以交易所为准更新，告警                                                 |

## 7. 风控

### 7.1 规则

阈值来自 `configs/sizing.yaml`（06 §5.4），可被 §7.1.1 的运行中覆盖。

| 编号 | 规则                          | 默认                                                    | 触发后                                                   | 回测是否模拟             |
| :--- | :---------------------------- | :------------------------------------------------------ | :------------------------------------------------------- | :----------------------- |
| R1   | 仓位大小（使用者手动调节）    | 每笔保证金 = 当前权益 × 20%，5x；单笔止损亏损上限 2.5%  | 决定仓位大小，规则见 06 §5                               | 是                       |
| R2   | 最大持仓数 / 每币持仓         | 3 / 1                                                   | 拒绝新开仓                                               | 是                       |
| R3   | 止损冷却                      | 15 分钟                                                 | 该币暂停开仓                                             | 是                       |
| R4   | 追价保护                      | 0.3%                                                    | 拒绝开仓                                                 | 是                       |
| R5   | 日亏损停止（已实现 + 未实现） | 当日初权益的 5%                                         | 当日（UTC）停止开仓                                      | 是（回测仅按已实现计算） |
| R6   | 日亏损熔断                    | 8%                                                      | 全部平仓并停机，需人工重启                               | 否                       |
| R7   | 连续止损                      | 6 次                                                    | 暂停开仓 2 小时                                          | 否                       |
| R8   | 权益从峰值回撤                | 20%                                                     | 停机，人工复核模型                                       | 否                       |
| R9   | 价差异常                      | 当前 bookTicker 价差 > 最近 60 分钟价差中位数 × 3       | 该币本分钟不开仓                                         | 否（只会让实盘更保守）   |
| R10  | 行情健康                      | 延迟 > 2 秒持续 10 秒、逐笔缺口未回补                   | 只平不开（全局或该币）                                   | 否                       |
| R11  | 下单错误                      | 5 分钟内 ≥ 5 次                                         | 只平不开 30 分钟                                         | 否                       |
| R12  | 时钟漂移                      | > 1 秒                                                  | 只平不开，重新同步成功后恢复                             | 否                       |
| R13  | 单笔名义价值截断              | 06 §5.3：单笔亏损上限、流动性上限、可用保证金、数量取整 | 截断或放弃                                               | 是                       |
| R14  | 权益下限                      | 06 §5.3：权益不足以满足最小下单额                       | 停止开仓，飞书告警“资金不足”，需人工充值或调整比例后清除 | 是                       |

“否”的规则只会减少交易，不会让实盘比回测更激进，因此不要求回测模拟；但影子盘与实盘报告中需统计它们的触发次数，用于判断回测是否高估了交易机会。

按默认设置，单笔止损约亏权益 0.6%~1.6%，R5 的 5% 约等于 3 笔最宽止损或 5 笔典型止损。调整 `position_frac` 时应结合回测的 `sizing_sweep.md`（06 §5.5）同步调整 R5~R8。

### 7.1.1 运行中调节仓位

除了修改配置后重启，还支持不重启调节。命令行与看板控制页（10 §3.5）调用同一组函数 `trade.live.control.*`：

```text
python scripts/set_sizing.py --position-frac 0.15           # 调整每笔占权益比例
python scripts/set_sizing.py --max-positions 2
python scripts/set_sizing.py --leverage 3
python scripts/set_sizing.py --mode fixed_risk --risk-per-trade 0.01
python scripts/set_sizing.py --max-risk-per-trade 0.04
python scripts/set_sizing.py --show                         # 查看当前生效值与仓位摘要
python scripts/set_sizing.py --reset                        # 清除所有覆盖，恢复 sizing.yaml 的值
```

- 可覆盖的键（白名单）：`mode`、`position_frac`、`max_positions`、`leverage`、`risk_per_trade`、`max_risk_per_trade`、`daily_loss_stop`、`daily_loss_halt`、`max_drawdown_halt`、`max_consecutive_losses`。其余参数只能改配置文件并重启。
- 生效值计算顺序：`sizing.yaml` → `runtime_overrides` 中的单项覆盖。
- 写入前执行与 06 §5.4 相同的校验（用当前实时权益），不通过则拒绝写入并给出原因。
- **只影响之后的新开仓**，已有持仓的数量与止盈止损不变。修改 `leverage` 时：无持仓的币立即调用设置杠杆接口；有持仓的币在平仓后再修改。
- 每次生效都记录 `events` 并发送飞书卡片，内容为“仓位设置摘要”（新旧值对比、来源 `cli`/`dashboard`）。
- 重启后覆盖值仍然有效，直到执行 `--reset`。

### 7.2 安全模式（只平不开）

- 不再发出任何开仓订单。
- 已有仓位的止盈、止损、超时平仓照常执行。
- 原因记录到 `risk_state.safe_mode_reason`，并发送告警。

### 7.3 停机与 Kill Switch

`python scripts/kill_switch.py` 或看板控制页“一键停机”按钮（也会在 R6、R8、HTTP 418 时被自动调用）：

1. 设置 `halt_flag = 1`（主进程每秒检查，看到后停止开仓）。
2. 撤销所有 `trd-` 前缀的挂单（含算法条件单）。
3. 对所有持仓发送 `MARKET reduceOnly` 平仓，最多重试 5 次，每次间隔 1 秒。
4. 通过 REST 确认仓位为 0，发送结果通知。

Kill Switch 脚本**不依赖主进程存活**：直接用 REST 完成第 2~4 步。看板按钮调用同一个函数。

`halt_flag` 只能通过 `python scripts/run_live.py --clear-halt` 人工清除（看板不提供清除按钮，避免误操作重新开始交易）。

### 7.4 交易所侧兜底

止损单始终挂在交易所，程序崩溃、断网时仓位仍受保护。systemd 在进程异常退出后 10 秒内重启，重启后按 §2 的流程对账。

## 8. 监控与通知

### 8.1 飞书自定义机器人

- 在飞书群中添加“自定义机器人”，安全设置选择**签名校验**，得到 Webhook 地址与签名密钥，分别放入环境变量 `FEISHU_WEBHOOK_URL`、`FEISHU_SECRET`。
- 签名算法（以飞书开放平台文档为准）：`timestamp` 为当前秒级时间戳；以 `f"{timestamp}\n{secret}"` 为 HMAC-SHA256 的密钥、对空字符串计算摘要，再 Base64 编码得到 `sign`。请求体带上 `timestamp` 与 `sign`。
- 消息类型：开平仓、告警、日报使用消息卡片（`msg_type: interactive`），心跳使用纯文本（`msg_type: text`）。卡片头部颜色：开仓蓝、止盈绿、止损红、告警橙、停机红。
- 频率限制：飞书自定义机器人有每分钟与每秒的发送上限（以官方文档为准）。`notifier` 内部使用队列 + 令牌桶（默认每秒 ≤ 4 条、每分钟 ≤ 80 条），超出时把同类消息合并为一张汇总卡片。单条消息体积控制在 20 KB 以内。
- 发送失败（网络错误、返回码非 0）重试 3 次（1s、3s、10s），仍失败写日志；**通知失败永远不影响交易**。
- 实现：`trade.live.notifier.FeishuNotifier`，接口 `send(event_type, payload)`；`provider: none` 时为空实现，便于测试。

### 8.2 通知内容

| 类型         | 时机                                                                           | 内容                                                                                                   |
| :----------- | :----------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------- |
| 启动 / 停止  | 进程启动成功、正常退出                                                         | 模式、模型 ID、仓位设置摘要、权益、费率核对结果                                                        |
| 开仓         | 每笔                                                                           | 币种、成交价、数量、名义价值、保证金、杠杆、p、止盈价 U、止损价 D、最长持仓截止时间（北京时间）        |
| 平仓         | 每笔                                                                           | 币种、出场类型（止盈/止损/超时）、出场价、持仓分钟、手续费、净盈亏（USDT 与占本金 %）、当日累计        |
| 仓位设置变更 | §7.1.1 每次生效                                                                | 新旧值对比、来源                                                                                       |
| 告警         | 安全模式、停机、对账差异、止损挂单失败、连接中断 > 60 秒、费率不一致、权益下限 | 原因与建议操作                                                                                         |
| 心跳         | 每小时一次（无交易时也发送）                                                   | 进程存活、权益、持仓数、最近 1 小时延迟 P95                                                            |
| 日报         | 每日 UTC 00:05（北京时间 08:05）                                               | 当日笔数、胜率、净盈亏、手续费、资金费、平均滑点 vs 模型滑点、延迟 P95、风控触发次数、与回测期望的对比 |

同类告警 5 分钟内合并发送。

### 8.3 漂移与一致性监控（每日任务）

1. **信号一致性**：用当日录制的 K 线与原子量，跑离线流水线和回测模拟器，与实盘（或影子盘）产生的信号对比，一致率 = 两边都出信号的分钟数 / 任一边出信号的分钟数，目标 ≥ 95%。
2. **滑点实测**：实际成交价与信号 K 线下一根开盘价的偏差，对比 06 §4.2 模型给出的滑点，计算比值。
3. **特征漂移**：每个特征当日分布与训练集分布的 PSI，> 0.25 告警。
4. **期望偏差**：最近 30 天实盘单笔期望与回测测试段单笔期望的差值，超过回测标准误的 2 倍时告警，提示模型可能失效。

结果写入 `artifacts/live/daily/{YYYYMMDD}.json`，看板“绩效”页展示趋势。

## 9. 安全

- **使用独立子账户**运行策略，只转入策略资金，与主账户隔离。
- API Key 权限：只开启“读取”与“合约交易”，**禁止开启提现与内部划转**；绑定实盘服务器固定 IP 白名单。优先使用币安支持的 Ed25519 密钥（私钥只在服务器上，交易所只保存公钥），否则使用 HMAC。详见 09 §5。
- 密钥存放在 `/etc/trade/env`（权限 600，属主为运行用户），不进 Git、不进日志、不进通知、不在看板显示。
- 服务器仅开放 SSH 密钥登录；看板只监听 `127.0.0.1`；定期更新系统补丁。
- 本地 Windows 不存放实盘密钥。
