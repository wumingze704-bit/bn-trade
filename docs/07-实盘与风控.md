# 07 实盘与风控

本文件是低频实盘引擎（小时级调仓、多空、持仓数个到十几个）的当前规格。策略、组合层与执行口径必须与 `docs/13` 共用同一份实现（AGENTS.md §6 红线 4）。

## 1 运行模式与入口

- `shadow`：正式网公开行情，只记录决策与虚拟成交，不调用任何下单、撤单、改杠杆、改保证金模式接口。
- `paper`：币安模拟盘下单，用于验证下单与止损流程；REST 为 `https://demo-fapi.binance.com`，WebSocket 为 `wss://fstream-demo.binance.com`。
- `live`：正式网真钱；启动条件见 §5。
- 入口：`python scripts/live_runner.py --mode {shadow|paper|live} --candidate <候选ID>`。
- 一次运行只服务一个候选；同一候选同一模式只允许一个实例（pid 锁文件 `<状态库目录>/<候选ID>-<模式>.lock`）。

## 2 启动流程

1. 读取 `docs/research/ledger.yaml` 与 `docs/research/candidates/<候选ID>.md`，核对冻结文件 SHA256；不一致立即退出（不得进入 BLOCKED 之外的任何交易状态）。
2. live / paper：同步服务器时间（3 次取中位数）与本地时钟差；超过 `engine.clock_drift_ms` 退出。
3. live / paper：核对手续费率、逐仓、单向持仓与杠杆。
4. 回补 1h / 1d K 线与资金费（`engine.history_days_hourly`、`engine.history_days_daily`）。
5. 从状态库恢复当日风控状态与停机标志；核对每个持仓都已有交易所侧止损，缺失立即平仓并告警。
6. 写入引擎心跳，发送启动通知。

## 3 候选文件

`docs/research/candidates/<候选ID>.md` 第一行为 `结论：...`；其后必须含一个 ```yaml 代码块：

```yaml
family: xs_momentum_ls        # 策略家族（trade.strategies.registry）
exposure: neutral             # neutral | directional
rebalance_hours: 24           # 24 的因数
risk_per_trade: 0.0075        # 冻结的单笔风险
framework_dir: src/trade/research
params: {lookback_days: 14, top_k: 5}
frozen:
  - path: configs/strategies/round_R1.yaml
    sha256: <64 位十六进制>
```

`framework_dir` 当前只接受 `src/trade/research`：引擎直接导入该包的 `interface`、`portfolio` 与 `trade.strategies.registry`，不复制任何策略或组合层代码。

## 4 行情与数据视图

- 每个整点后 `engine.rebalance_delay_sec` 秒用 REST 拉取刚收盘的 1h K 线；1d 与资金费只补尾部。
- 启动时回补窗口：1h 至少覆盖策略最长回看 + 缓冲（默认 45 天），1d 覆盖 30 天成交额中位数所需（默认 120 天）。
- 只使用 `open_time + 1h ≤ now` 的 K 线；拼出的 `MarketData` 与研究数据层同构，`View` 的防未来函数规则不变。
- 拉取失败重试 3 次；仍失败则本次调仓跳过、置行情过期标志并告警（只平不开，下一轮按目标对账）。
- 交易规则（tickSize / stepSize / minNotional）来自 exchangeInfo；交易状态非 `TRADING` 的持仓直接平仓。

## 5 真钱硬性约束

live 模式必须同时满足，任一不满足立即退出：

1. 命令行带 `--candidate` 与 `--i-understand-the-risk`；
2. 环境变量有正式网密钥（`BINANCE_API_KEY` + `BINANCE_API_SECRET`，或 `BINANCE_PRIVATE_KEY_PATH`）；
3. 总账该候选 `final=pass` 且 `ops` 为 `live_ready` / `live`；
4. `docs/research/final/<候选ID>_<窗口ID>.md` 第一行为 `结论：PASS`；
5. `docs/research/shadow/<候选ID>.md` 第一行为 `结论：LIVE_READY`；
6. 冻结文件 SHA256 与候选文件一致；
7. 账户手续费率不超过 `configs/base.yaml` 吃单费率 × `engine.fee_reject_ratio`；
8. 逐仓、单向持仓、杠杆等于风险包络 `configs/sizing_research.yaml: leverage`；
9. API Key 未开启提现权限、已设置 IP 白名单、已开启合约权限（调用 `GET /sapi/v1/account/apiRestrictions`）。

资金上限：`engine.live_capital_cap`（默认 100 USDT）。账户权益超过上限时只按上限计算仓位。

paper 模式需要 `BINANCE_DEMO_API_KEY` / `BINANCE_DEMO_API_SECRET`；shadow 不需要密钥。

## 6 调度与目标仓位对账

- 每个整点：拉取行情 → 影子盘结算上一轮待成交 → 巡检 → 调仓（仅策略声明的调仓整点）→ 心跳 → 日报。
- 调仓只执行“目标 − 实际”的差额：同向减仓与全部平仓使用 `reduceOnly`，平仓排在开仓之前；方向相反时先平后开。
- 实际持仓一律以交易所（paper / live）或状态库虚拟持仓（shadow）为准；进程崩溃重启后重新对账即可回到目标状态，不重复下单。
- 目标数量 = 组合层给出的名义价值 ÷ 决策收盘价，按 `stepSize` 向下取整；低于最小下单额的仓位由组合层丢弃。

## 7 执行器

- paper / live：每笔先挂 post-only 限价单（GTX，买单挂买一、卖单挂卖一），等待 `engine.post_only_wait_sec` 秒；未成交部分撤单并改挂一次；仍有剩余用 LIMIT IOC（买单上限 = 卖一 + `engine.ioc_tick_buffer` tick，卖单下限 = 买一 − 同样 tick 数）；最后用市价单完成。平仓单 `reduceOnly=true`。
- `clientOrderId` 由别名、调仓时刻、阶段与序号组成，保证幂等；订单状态未知（超时 / 5xx）时先按 `clientOrderId` 查询再决定是否重发。
- paper / live 每笔记录成交明细；shadow 按研究口径（13 §4）在 open_time = 决策时刻 t 的 1h K 线收盘后，以该根开盘价加半价差与滑点成交，并记录决策时刻的盘口。
- 实际成本以最近收盘价为基准统计（bp）；调仓记录同时写入研究口径的估计成本（半价差 + 最小滑点）。

## 8 交易所侧止损

- 每个持仓必须挂 STOP_MARKET 条件单（`POST /fapi/v1/algoOrder`，`algoType=CONDITIONAL`、`workingType=MARK_PRICE`、`reduceOnly=true`）。
- 多头止损为卖出、触发价 = 持仓均价 × (1 − sl) 向下取整；空头止损为买入、触发价 = 持仓均价 × (1 + sl) 向上取整。
- 开仓成交后立即挂止损并查询确认，确认后才算开仓完成；止损无法确认时立即平仓并告警。
- 调整仓位时先挂新止损、确认成功后再撤旧止损；平仓后撤销该币止损单。
- 巡检发现持仓缺少止损且状态库没有该仓位记录时，立即平仓该币（不存在“有仓位无止损”的窗口）。

## 9 风控规则对照表

| 旧规则 | 处理 | 说明 |
| :-- | :-- | :-- |
| R1 追价保护 | 删除 | 调仓频率为小时级，执行器已有 GTX / IOC 限价上限 |
| R2 逐笔缺口 | 删除 | 不使用逐笔与分钟级数据 |
| R3 止损冷却（分钟） | 改为按小时 | `execution.cooldown_hours`；影子盘止损后该币冷却期内不新开仓 |
| R4 单笔止盈 / 追踪 | 删除 | 策略只声明止损；止盈由下一轮调仓决定 |
| R5 日亏损停止开仓 | 保留 | `sizing_research.yaml: daily_loss_stop` |
| R6 日亏损熔断 | 保留 | `daily_loss_halt`，触发即平仓并写停机标志 |
| R7 连续止损暂停 | 保留 | `max_consecutive_losses`、`consecutive_loss_pause_min` |
| R8 峰值回撤停机 | 保留 | `max_drawdown_halt` |
| R9 行情延迟 | 改写 | 行情过期超过 1 个调仓周期 → 只平不开 |
| R10 下单错误 | 保留 | 1 小时内 ≥ `engine.max_order_errors_1h` → 只平不开 |
| R11 时钟漂移 | 保留 | 超过 `engine.clock_drift_ms` → 暂停下单 |
| R12 净敞口 | 保留 | 超过权益 × `engine.net_exposure_cap` 持续 `engine.net_exposure_grace_min` 分钟 → 安全模式 |
| R13 价差异常 | 保留（简化） | 下单时价差 > 该币 24 小时中位数 × `engine.spread_median_mult` → 该币本次跳过（由执行器盘口检查保证） |
| R14 下架 / 非交易状态 | 保留 | exchangeInfo 状态非 `TRADING` → 平掉该币 |

- 安全模式：只平不开，保留交易所侧止损，写事件并告警。
- 停机：R6 / R8 / 人工均写 `halt_flags`；引擎每次调仓前读取，停机时不新开仓。停机标志只能由人工用 `live_runner.py --clear-halt` 清除。

## 10 状态库

SQLite（WAL），路径 `storage.db_path`（默认 `artifacts/live/state.db`）。表：

- 旧表继续使用：`orders`、`fills`、`positions`、`equity_snapshots`、`risk_state`、`events`、`runtime_overrides`、`scan_cycles`、`scan_state`（最后一次调仓的目标与过滤结果）。
- 新增：`engine_status`（pid、心跳、上次/下次调仓）、`rebalance_log`（权益、多空名义、实际与估计成本）、`consistency_log`（shadow / live 一致性）、`halt_flags`（按候选与模式）、`control_flags`（暂停开仓、平仓请求）、`shadow_positions`（影子盘虚拟持仓）。
- 状态库只用于记录与展示；持仓判断以交易所为准。

## 11 控制、停机与紧急开关

- `trade.live.control`：暂停开仓、恢复开仓、请求全部平仓、调整 `risk_per_trade`（只允许 `[0.005, 0.01]`，只影响运行中的参数，不写回配置）。
- 不提供清除停机标志、切换运行模式的功能。
- 紧急停机：`python scripts/kill_switch.py --candidate <候选ID> --mode {live|paper|shadow}`。顺序固定：写停机标志 → 撤全部普通挂单 → 撤全部条件单 → 市价 `reduceOnly` 平仓 → REST 确认仓位为零 → 请求停止 systemd 实例。仍有持仓时返回失败，需人工在币安 App 处理。
- 停机标志清除：`python scripts/live_runner.py --mode <模式> --candidate <候选ID> --clear-halt`（仅人工执行）。

## 12 通知、日报与看门狗

- 通知复用 `trade.live.notifier`（WxPusher，企业微信为备份；未配置时 no-op）。事件：启动、停止、调仓汇总、止损触发、安全模式、停机、异常、每日 00:10 UTC 日报。
- 通知内容标明候选 ID 与运行模式，不含密钥；金额类字段可配置脱敏。
- 盈亏遮蔽：`engine.hide_pnl_until_final` 为 true 时，shadow / paper 且候选 `final` 为 pending / running 的情况下，日报、通知与看板只显示运行与一致性数据，不显示虚拟收益与权益。
- 看门狗 `scripts/live_watchdog.py`（systemd timer 每 5 分钟）：心跳超过 `engine.watchdog_stale_min` 分钟 → 重启该实例一次并告警；同一实例 1 小时内第二次超时 → 只告警不重启。心跳文件为 `<状态库目录>/<候选ID>-<模式>.heartbeat`。

## 13 部署

`deploy/` 下：

| 文件 | 用途 |
| :-- | :-- |
| `trade-runner@.service` | shadow / paper 实例模板，实例名 `<候选ID>-<模式>`，`MemoryMax=400M`，`Restart=always` |
| `trade-runner-live@.service` | live 实例模板，实例名 `<候选ID>`，`MemoryMax=500M`，固定带 `--i-understand-the-risk` |
| `trade-dashboard.service` | 看板，只监听 `127.0.0.1`，`MemoryMax=300M` |
| `trade-watchdog.service` / `.timer` | 看门狗，每 5 分钟执行一次 |

- 密钥只放在 `/home/ubuntu/trade/.env.live`（权限 600，不进入 git），由 systemd `EnvironmentFile` 注入。
- 启动示例：`sudo systemctl enable --now trade-runner@C1-shadow`、`sudo systemctl enable --now trade-runner-live@C1`。

## 14 配置

`configs/live.yaml` 字段与 `trade.live.config.LiveConfig` 一一对应：

- `mode`、`model_dir`、`sizing`、`exits`：仅用于兼容配置模型，低频引擎不读取后三项。
- `notify`、`storage`：通知与状态库。
- `engine`：交接文件路径、研究数据目录、历史回补天数、资金上限、盈亏遮蔽、执行等待、心跳、风控阈值、日报时间与看门狗阈值。

## 15 单一实现

研究、最终检验、影子盘与实盘共用 `src/trade/research/`、`src/trade/strategies/`、`trade.common.sizing`、`trade.common.risk_rules`、`trade.common.costs`。实盘的成交、止损取整与风控判定不得另写一份；改动任一侧必须同步其余各处与 `docs/13`。
