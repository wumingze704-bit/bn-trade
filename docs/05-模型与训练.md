# 05 模型与训练

## 1. 建模任务

- 输入：样本 t 之前（含 t）连续 `L = 60` 根 K 线的特征矩阵，形状 `(L, F)`，F = 启用特征数（默认 37）。
- 输出：
  - 主输出 `p`：按实际出场策略交易、扣成本后净 R ≥ `y_min_r` 的概率（二分类，对应标签 `y`，04 §7.5）。
  - 辅助输出 `m`：预期净 R 倍数（回归，对应标签 `r_mult`），只用于多任务正则和信号排序的平局打破，不直接用于交易决策。
- 交易规则：`p ≥ θ`（阈值，§7 确定）时开多；初始止损与标签的 `sl` 一致，之后的出场由出场策略（06 §3.3）决定。
- 所有模型（含 R0）对外暴露相同的 `Predictor.predict(x) -> (p, m)` 接口，回测与实盘不区分模型类型。

## 2. 模型选型与理由

| 编号 | 模型                                                                                                                                               | 角色                   | 理由                                                                                                                                                     |
| :--- | :------------------------------------------------------------------------------------------------------------------------------------------------- | :--------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R0   | 规则策略：预过滤通过 且 `brk_60 > 0` 且 `tbr_5 ≥ 0.60` 且 `vol_z_60 ≥ 2.0` 时输出 `p = 1`，否则 `p = 0`（阈值写在 `train.yaml`，事先固定，不调参） | **无模型下限**，必须做 | 让回测引擎（P3）与实盘引擎（P5）在没有模型时就能端到端联调；同时回答“模型到底比简单规则多赚了多少”。M1 / M0 不能稳定优于 R0 时，说明机器学习没有带来价值 |
| M0   | LightGBM（最后一根特征 + 第 t-1、t-5、t-15 根的特征差分，表格化）                                                                                  | **基线**，必须做       | 金融表格数据上通常是强基线，训练快。主模型如果不能稳定超越它，说明序列建模没有带来价值，应采用更简单的方案                                               |
| M1   | 因果 TCN + 注意力池化（PyTorch）                                                                                                                   | **主模型**             | 卷积并行训练快、梯度稳定；感受野可精确控制（与 L=60 匹配）；在短序列任务上通常不弱于 LSTM，且推理在 CPU 上更快                                           |
| M2   | 2 层 LSTM（PyTorch）                                                                                                                               | 消融对照               | 原草案方案，保留对比。原草案 3 层 LSTM 对 4 个特征偏深，易过拟合                                                                                         |
| M3   | Transformer（PatchTST 风格）                                                                                                                       | 可选，本期不强制       | 数据量（百万级样本、信噪比极低）下通常不占优，仅在 M1 明显优于 M0 后再尝试                                                                               |

不采用的方案：强化学习（样本效率低、回测过拟合风险极高）；直接价格回归（目标与可交易结果不一致）；按币种单独建模（违背“通用模型”的前提，且每币样本更少）。**交易范围按月变化（03 §4.2）不改变建模方式：模型始终跨币种通用，不因币种进出而按币单训；新进入的币直接使用当前模型，并在每月重训（§10）时进入训练数据。**

## 3. 主模型 M1 结构

```text
输入 x: (B, L=60, F)
 └─ Linear(F → 64) + LayerNorm                       # 特征投影
 └─ 转置为 (B, 64, L)
 └─ TCN 残差块 × 4，膨胀系数 d = 1, 2, 4, 8
      每块: CausalConv1d(64→64, k=3, dilation=d) → GELU → Dropout(0.2)
            CausalConv1d(64→64, k=3, dilation=d) → GELU → Dropout(0.2)
            + 残差连接；卷积权重使用 weight_norm
      感受野 = 1 + 2·(3-1)·(1+2+4+8) = 61 ≥ L
 └─ 转置回 (B, L, 64) 得到 H
 └─ 池化: concat[ H[:, -1, :],  AttnPool(H) ] → (B, 128)
      AttnPool: a = softmax(H·w)，输出 Σ a_i·H_i
 └─ MLP: Linear(128→64) → GELU → Dropout(0.2)
 └─ 两个头:
      cls_head: Linear(64→1)   → logit
      reg_head: Linear(64→1)   → m
```

- 因果卷积：左侧补零 `(k-1)·d`，保证 t 位置只看到 ≤ t 的输入。
- 参数量约 10 万级，推理单样本 CPU < 2 ms。
- 不使用币种 ID 嵌入（保证对留出组与新进入的币可用）。消融实验 `use_symbol_embedding: true` 可选，仅用于分析，不得上线。

M2（LSTM）：`Linear(F→64) → LSTM(64, hidden=64, num_layers=2, dropout=0.2, batch_first=True) → 取最后时刻 → 同 M1 的 MLP 与两个头`。

## 4. 损失函数

```
L = BCEWithLogits(logit, y, weight=w, pos_weight=π) + λ · Huber(m, r_mult, δ=1.0, weight=w)
```

- `w`：样本独特性权重（04 §7.3）× 币种均衡权重（§5.2）。
- `pos_weight π = (负样本数 / 正样本数)` 的平方根（只在训练集上计算），缓解类别不平衡但不过度。
- `λ = 0.3`。
- 备选：`loss: focal`（γ = 2），作为超参实验项。

## 5. 数据集与采样

### 5.1 内存布局

- 每币只加载**入选月份及其前 30 天预热**的特征（03 §6“按月入选”），按币拼成连续数组 `X_sym`，形状 `(N_minutes, F)`，**一律以 fp16 存储**（磁盘上为 `.npy` 并用 `np.load(mmap_mode="r")` 读取，避免 float32 中间副本）。
- 规模估算（`top_n = 60`，训练组约 80%）：每月约 48 个训练组币 × 21 个月 × 43200 分钟 × 37 特征 × 2 字节 ≈ 3.2 GB，加预热约 3.5~4 GB，可常驻 RTX 3060 6 GB（Laptop，显存目标 < 5 GB，§6.2）。
- 显存不足时的退路（`train.yaml: data_placement: gpu | pinned_cpu`）：`pinned_cpu` 时特征留在锁页内存，每个 batch 在 CPU 上 gather 后一次拷贝到 GPU。两种方式产出的窗口必须一致（08 P4 单测）。
- 样本只存索引：`(sym_id, row_idx, y, r_mult, w)`。`__getitem__` 返回 `X_sym[row_idx-L+1 : row_idx+1]`，**不预先展开序列**（展开会放大 60 倍内存）。
- 输入窗口内允许包含未通过预过滤的分钟和补齐分钟（`is_filled`），但窗口内补齐分钟占比 > 20% 的样本丢弃。
- 默认**不使用 DataLoader**：整个特征数组常驻 GPU，每个 batch 用索引张量在 GPU 上直接 gather 出 `(B, L, F)` 窗口（§6.2），避开 Windows 多进程序列化开销。

### 5.2 币种均衡

不同币的样本数可能相差数倍。每个 epoch 用 `WeightedRandomSampler` 使各币被抽到的期望次数相同（或在损失权重中乘以 `1 / 该币样本数` 再整体归一）。默认后者，`balance: loss_weight`。

### 5.3 打乱

训练集内跨币、跨时间完全打乱。验证集与测试集按时间顺序评估，不打乱。

## 6. 训练流程

对 03 §6 的每一折 F1~F5，以及最终模型 F_final（训练 M1~M21、验证 M22）：

1. 加载训练、验证段样本（只含训练组币，且只含其入选月份，03 §4.5、§6），执行 Purge 与 Embargo。
2. 生成 R0 信号（无需训练）。
3. 训练 M0（LightGBM，CPU），在验证集上早停（`early_stopping_rounds=100`，指标 `average_precision`）。
4. 训练 M1（与 M2）：
   - 优化器 AdamW，`lr = 1e-3`，`weight_decay = 1e-4`。
   - 学习率：前 1 个 epoch 线性预热，之后余弦衰减。
   - `batch_size = 2048`，最多 30 个 epoch。
   - 早停：验证集 PR-AUC，`patience = 5`，保存最优权重。
   - 混合精度 `torch.autocast("cuda", dtype=torch.bfloat16)`（RTX 30 系列支持 bf16，数值范围与 fp32 相同，不需要 `GradScaler`）；梯度裁剪 `max_norm = 1.0`。
   - 随机种子固定（`torch`、`numpy`、`random`），`torch.backends.cudnn.benchmark = False`。
   - **种子集成**：同一配置用 5 个种子各训练一次，推理时对 logit 取平均（再做温度缩放）。成本是训练时间 ×5，收益是显著降低“这次运气好”的方差；CPU 推理 5 个小模型仍 < 10 ms。
5. 在验证集上做概率校准（§7.1）和阈值选择（§7.2）。
6. 在测试段上对当月交易范围内的全部币（训练组 + 留出组）批量推理，输出 `signals.parquet`（`symbol, open_time, p, m`）交给回测。
7. 每个 epoch 记录到 `train_log.csv`：训练损失、验证损失、验证 PR-AUC、ROC-AUC、Top 5% 精确率、用时、显存峰值。

### 6.1 超参搜索（只在调参期）

**只允许在调参期（训练 M1~M10、验证 M11~M12，03 §6）上搜索**，候选范围（小规模网格或 Optuna，最多 30 组）。选定后写入 `train.yaml` 与 `exits.yaml` 并冻结，F1~F5 与 F_final 使用完全相同的设置，禁止每折各自挑选最优。

标签默认按实际出场策略模拟（04 §7.5），出场参数改变会重建标签，因此搜索分两步，**先定出场与止损，再调模型**：

**第 1 步：出场与止损（6 组，用 M0 LightGBM 评估）**

| 组  | `exits.type` | `H_max` | `k_trail` | `k_sl` |
| :-- | :----------- | :------ | :-------- | :----- |
| 1   | trail        | 120     | 1.5       | 1.0    |
| 2   | trail        | 60      | 1.5       | 1.0    |
| 3   | trail        | 240     | 1.5       | 1.0    |
| 4   | trail        | 120     | 1.0       | 1.0    |
| 5   | trail        | 120     | 2.0       | 1.0    |
| 6   | trail        | 120     | 1.5       | 1.3    |

- 每组：用该组参数重建调参期标签 → 训练 M0（CPU，每组数分钟）→ 在验证段 M11~M12 按 §7.2 的方法选阈值 → 计算 `base` 情景的净收益与 PF。取 PF 最高、且净收益 > 0 的一组；都不满足时选 PF 最高的一组并在报告中说明。
- `sl_min/sl_max` 固定为 0.5%/1.5%，其余出场参数固定为 06 §3.3 默认值。`fixed` 出场只作为对照报告，不参与选择（它对应 `triple_barrier` 标签模式，04 §7.0）。

**第 2 步：模型超参（固定第 1 步的结果，最多 24 组）**

| 超参                         | 范围                                         |
| :--------------------------- | :------------------------------------------- |
| `L`                          | 30, 60, 120（120 时 TCN 增加一个 d=16 的块） |
| 隐藏维度                     | 32, 64, 128                                  |
| dropout                      | 0.1, 0.2, 0.3                                |
| loss                         | bce, focal                                   |
| `time_decay_halflife_months` | 关闭, 12                                     |

- 两步合计最多 30 组，与原上限一致。每一组搜索都登记到 `artifacts/reports/EXPERIMENTS.log`（06 §7 S11），包括失败的组。
- `y_min_r`（04 §7.5）不参与搜索。

### 6.2 RTX 3060 训练建议

本项目的瓶颈不在算力，而在数据搬运与过拟合控制。使用者的显卡为 RTX 3060 **6 GB**（Laptop 版），显存目标 < 5 GB，留余量给系统与其他程序：

| 建议                 | 做法                                                                                                                                  | 理由                                                                                 |
| :------------------- | :------------------------------------------------------------------------------------------------------------------------------------ | :----------------------------------------------------------------------------------- |
| 数据常驻 GPU         | 所有币的特征拼成一个 fp16 张量（约 1 GB）+ 每币起始偏移；样本索引也放 GPU；每个 batch `X[idx[:, None] + arange(-L+1, 1)]` 一次 gather | 免去 DataLoader 与 CPU→GPU 拷贝，Windows 上提速最明显；一个 epoch 预计数十秒到几分钟 |
| bf16 混合精度        | `autocast(dtype=bfloat16)`，不用 GradScaler                                                                                           | Ampere 架构原生支持，比 fp16 少一类溢出问题                                          |
| 模型保持小           | 隐藏 64、约 10 万参数                                                                                                                 | 分钟级金融数据信噪比极低，大模型只会更快记住噪音                                     |
| 先跑 R0 与 LightGBM  | M0 在 CPU 上训练，几分钟出结果                                                                                                        | 如果 M0 都不比 R0 好，先回头改特征和标签，不必在 TCN 上花时间                        |
| 种子集成             | 5 个种子平均                                                                                                                          | 降方差，比加深网络更有效                                                             |
| 不用 `torch.compile` | Windows 上 Triton 不是官方支持；模型很小，收益有限                                                                                    | 减少环境问题；如改用 WSL2 可再评估                                                   |
| 可选 WSL2            | 在 WSL2 Ubuntu 中训练                                                                                                                 | 与服务器环境一致、自带 rsync；性能与原生 Windows 接近                                |
| 监控过拟合           | `train_log.csv` 中训练/验证 PR-AUC 差距；验证集上的置换重要性（permutation importance），找出“只在训练集有用”的特征                   | 提早发现泄露或过拟合                                                                 |
| 不建议               | 大 Transformer、强化学习、LLM 生成信号、按币单独建模                                                                                  | 样本效率低、过拟合风险高，或违背“通用模型”前提（§2）                                 |

训练耗时粗估：单折 M1（5 种子）约 0.5~2 小时，5 折 + F_final 一个晚上可以跑完；以 P4 实测为准，写入完成报告。

## 7. 校准与阈值

### 7.1 概率校准

在验证集上做温度缩放（Temperature Scaling）：学习单一标量 `T`，`p = sigmoid(logit / T)`，最小化验证集 NLL。报告校准前后 ECE（10 分箱）。

### 7.2 阈值选择

阈值 θ 必须在验证集上确定，再固定用于测试段与实盘。方法：

1. 在验证集上，对 θ ∈ {0.30, 0.32, …, 0.80} 逐个调用回测模拟器（使用 06 的基准成本情景），得到每个 θ 的净收益、交易次数、Profit Factor。
2. 约束：验证集上日均交易次数 ≥ 3 笔（全部币合计），否则统计不可靠。
3. 在满足约束的 θ 中，选择“净收益曲线平稳性”最好的点：取净 Profit Factor 最高的 θ*，然后最终 θ = 使 PF ≥ 0.9 × PF(θ*) 的最小 θ（偏向更多交易，降低对单点的过拟合）。
4. 记录 θ 及其在验证集的指标到 `model_meta.json`。

## 8. 评估指标（分类层面）

在测试段（10 个测试月拼接）与封存集上分别报告，并分“训练组”“留出组”“新进入组”三组（03 §4.5）：

- PR-AUC、ROC-AUC、Brier 分数、ECE。
- Top-k 精确率：概率最高的 1%、5% 样本中 y=1 的比例，对比基准正样本率（提升倍数 Lift）。
- 各币单独的 PR-AUC 与 Lift，找出模型无效的币。
- R0 / M0 / M1 / M2 对比表。

分类指标只是中间结果，**是否有效以 06 的经济指标和 08 的闸门为准**。

## 10. 重训策略（上线后）

- 每月初重训：记上一个完整自然月为 N，用 N-23 ~ N-2 训练、N-1 验证（早停、校准、阈值），N 作为新旧模型的对比测试月（新旧模型都没见过 N）。超参与出场策略沿用冻结值，不在重训时重新搜索。训练数据按各月的 `U(R)` 快照取币（03 §4.2），因此新进入的币在重训后自动进入训练组或留出组（按哈希规则），衰亡退出的币只保留其入选月份的历史样本，无需人工维护名单。
- 新模型在 N 月上的回测经济指标（06 基准情景的净收益与 Profit Factor）不劣于当前线上模型的 90%，且满足 08 G2 的单月最低要求，才可替换。
- 本期不做“用全部最新数据再训一次”，避免上线模型没有经过任何样本外检验。
- 保留最近 3 个模型产物，支持一键回滚（`live.yaml` 中 `model_dir` 指回旧目录后重启）。
