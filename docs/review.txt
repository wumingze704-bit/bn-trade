review.txt —— 问题汇总

说明：本文件汇总正式回测之前审查发现的问题，只描述“问题是什么、在哪里、有什么影响”。
结论来自对代码与设计书的静态审查，以及 docs/tasks.md 中已记录的真实运行结果；审查时没有运行回测或训练。
行号与函数位置以审查时的代码为准。


一、文档与规范

1. 设计书混入大量过程记录
   - 位置：docs/design.md、docs/01~10。
   - 现象：带日期的实测流水（09 有 14 处、05 与 07 各 3 处、03 有 1 处），“已决定 / 使用者决定”的决策过程，09 §9 核对记录表，阶段性开发提示，同一规则在多份文档重复解释。
   - 影响：不符合 AGENTS.md §5.2“只写当前规格、不写日期与流水账”；设计书难读，Agent 难以分清哪句是规格、哪句是历史。

2. AGENTS.md 红线重复
   - 原红线 4（单一实现）与 5（回测实盘一致）讲同一件事；6（名单不可擅改）与 7（不放宽风控与闸门）都是“参数只能由使用者定”；13（改单无空窗）是 9（实盘安全）的特例（现行编号见 docs/records.md 的 AGENTS.md §6 条目）。
   - 原红线 12 写了大量看板设计细节，属于 10 号设计书的内容。
   - §1、§1.1、§10 重复了原红线 10（不伪造）、11（只在服务器访问币安）的内容。

3. AGENTS.md 表述矛盾
   - §1.1“已授权 Agent ……完成需要使用者确认的服务器操作”：既说已授权又说需要确认，弱模型会理解为不用问。
   - §1“不要引入设计文档之外的新模块、新抽象层”：与使用者下达的新建脚本、新建模块的指令冲突。
   - §3.1“函数长度 ≤ 60 行”：现有大量函数超过 60 行（如 _simulate_exit_nb、precompute_trades），模型可能为满足此条去拆分已有代码，造成无关改动。
   - §1 写“服务器用发行版 Python”，§1.1 写“uv Python 3.13.18”，两处不一致。
   - §1.1 写了服务器公网 IP、用户名与密钥路径，这些运维信息不宜放在会提交到 git 的规范文件中。

4. AGENTS.md 缺少的红线
   - 没有“设计书与代码一致、同步时只写规格”的明确规则。
   - 没有“不得为了让测试通过而修改或跳过测试”。
   - 没有“禁止静默回退默认值”（审查中真实发现 tickSize 回退 0.01）。
   - 没有“服务器批量脚本在代码中硬性限制只处理 M1~M22”（修复首日大单阈值时曾处理到封存月）。
   - 没有覆盖服务器与 data/ 目录的危险操作确认（§9 只写了 git）。
   - 没有“性能改动必须结果等价”。

5. Cline + DeepSeek 不会自动加载项目规范
   - 现状：仓库没有 .clinerules/ 与 .clineignore；每个新窗口都要手动提醒 Agent 遵守规范。
   - 风险：Agent 可能读到 data/ 下的封存集数据、密钥文件；红线摘要与 AGENTS.md 没有一致性校验。


二、回测性能（三个月数据跑三四天）

6. 盯市权益曲线复杂度过高
   - 位置：src/trade/backtest/engine.py _mark_to_market_curve。
   - 现象：对每笔交易遍历该币全部 K 线时间戳（scripts/backtest.py 加载从 M1 前 30 天到封存集起点的整段数据，每币最多约 97 万根）；再对每个采样时刻遍历全部交易。两层纯 Python 循环，复杂度为“交易笔数 × 每币 K 线数 + 采样点数 × 交易笔数”。
   - event_sim._event_combine 调用同一函数。
   - 影响：判断为耗时的主要来源，需实测确认。

7. 每次组合模拟都为全部分钟建 Python dict
   - 位置：engine._close_lookup。
   - 影响：数千万个字典条目，耗时并占用数 GB 内存。

8. 同一进程内大量重复计算
   - scripts/backtest.py 一次运行约调用 40 次 run_backtest（reference/user × 3 情景、breakeven 二分每个运行约 12 次、sizing_sweep 4 次、S4 2 次），每次都从头重算全部币的预计算和盯市曲线。
   - scripts/tuning_exits.py 每组参数扫 26 个 θ，每个 θ 跑一次完整组合模拟。
   - 每次 run_backtest 都重算 wilder_atr（纯 Python 循环）、rv_15、rolling_mean、open_time 下标 dict，并在循环里反复布尔筛选 signals。

9. 预计算与标签逐信号 Python 循环
   - 位置：engine.precompute_trades、labels/exit_sim.exit_sim。
   - 现象：每个信号调用一次 compute_entry（Python）与 simulate_exit（30 个参数的 numba 调用），并构造 dataclass；标签每组出场参数要对数百万个预过滤样本重算；S1 随机基准对全部预过滤样本做同样计算。

10. 特征计算与调参准备阶段慢
    - features/normalize.ewm_standardize 逐元素纯 Python 循环，约 30 个 ewm_z 特征 × 每币全部分钟。
    - scripts/tuning_exits.py 每次启动都重算全部特征，不复用已落盘的数据集特征；month_index 逐样本做 datetime 转换。
    - common/_numba.py 使用 cache=False，每个进程重新编译全部 numba 函数。


三、实盘与数据接入

11. 实盘 WebSocket 路由过时，aggTrade / kline 收不到
    - 位置：src/trade/live/exchange/endpoints.py，正式网 ws_base = "wss://fstream.binance.com"。
    - 原因：币安 2026-03 起把 USDⓈ-M 合约 WebSocket 拆为 /public、/market、/private，旧地址 2026-04-23 下线；不带路由的连接只收 /public 数据。
    - 影响：订单流特征 #23~#27（whale_ratio、whale_net、whale_net_15、burst_1s、max_trade_rel）在实盘算不出来，回测对实盘失去参考价值；T1-5 实时/历史成交口径比对一直阻塞。


四、数据与标签

12. 缺交易规则时 tickSize 静默回退 0.01
    - 位置：scripts/build_dataset.py，tick_size_by_alias.get(alias, 0.01)。
    - 影响：价格 0.05 的币用 tick 0.01 时 half_spread = 10%，初始止损取整到 0，该币标签全部作废；正样本率仅 0.07 的 C027 需排查是否与此有关。缺规则的多为已下架合约，若被悄悄排除会造成幸存者偏差。

13. Purge 长度小于标签最长持仓
    - 位置：configs/train.yaml purge_bars: 60；默认标签 exit_sim 最长持仓 H_max = 120。
    - 影响：训练集最后 60~121 分钟样本的标签落进验证月，属于标签重叠泄露；调参脚本内部的训练/验证切分同样存在。

14. 只缺逐笔、K 线完整的分钟被出场模拟跳过
    - 位置：src/trade/data/aggregate.py 中 is_filled = kline_missing | atomic_missing；src/trade/common/exits.py 遇到 is_filled == 1 直接跳过，不判止损止盈。
    - 影响：这些分钟的 K 线高低点是真实成交价，价格可能已打穿止损，回测却当没发生（偏乐观）；真实数据存在整日级逐笔缺失（1423~1437 分钟），持仓会一整天不检查止损，最后按陈旧价格离场。
    - 附带缺陷：无进展判定要求第 stall_bars 根恰好不被跳过，被跳过时永远不触发。
    - 附带缺陷：盯市曲线遇到缺失分钟按入场价计，会抹掉浮亏。

15. 入场价可能是陈旧价，追价判断与实盘口径不同
    - 第一秒内无成交时 p_1s 取上一分钟收盘价并置 p_1s_filled = 1，但 precompute_trades 与 exit_sim 从不检查 p_1s_filled / p_3s_filled。
    - 实盘限价 = min(卖一价 × (1 + 2 × tick_rel), c_t × (1 + max_chase))，LIMIT IOC；回测用最近成交价判断追价上限，且假设 100% 成交。
    - 影响：用陈旧价格入场；突破时实盘可能因价格跑掉而吃不到的单，回测照算（逆向选择，偏乐观）。

16. 本金配置与使用者要求不符
    - configs/sizing.yaml initial_equity = 10；configs/backtest.yaml reference.initial_equity = 10000；使用者要求本金与所有回测都用 100 USDT。
    - 设计书多处写“10 USDT”（design.md、01、03、06、07、08、10）。
    - notional_ref = initial_equity × position_frac × leverage 影响滑点与 exit_sim 标签，改本金后数据集必须重建。
    - 代码中存在写死的默认值（如 sweep.sizing_sweep 的 initial_equity: float = 10.0、ReferenceConfig 默认 10000.0）。

17. 本地数据与数据集是修复前版本；封存月曾被处理
    - 服务器已修复 M1~M22 共 1347 个「币·月」的首日大单阈值，本地未同步，数据集 ds_20261102 仍是修复前版本，在其上做的训练与调参不可信。
    - 修复脚本首次运行时处理过 SUIUSDT 2026-08、2026-09 两个封存月（只写盘、未看结果）。


五、回测引擎与方法

18. Walk-Forward 五折阈值无法正确拼接
    - 位置：trade/models/walkforward.run_fold 每折单独选 θ 与温度，信号文件不含 θ；scripts/backtest.py 只接受一个 --model 的阈值；仓库没有拼接 M13~M22 的代码。
    - 影响：合并后用某一折的 θ 跑等于测试段泄露；分五次跑则复利、回撤、bootstrap、S5 在折边界断开。

19. 返佣没有计入回测
    - base.yaml 为 VIP0 毛费率（taker 0.05%、maker 0.02%），使用者有 30% 返佣，单笔往返约省 3bp；按月 150 笔、名义 = 权益估算约 4.5%/月。
    - 约束：不能直接改 base.yaml 费率，否则实盘启动时 fee_reject_live 会拒绝 live。

20. 回测没有执行实盘风控 R5~R8
    - 07 §7.1 把 R6（日亏 8% 全平停机）、R7（连续 6 次止损暂停）、R8（回撤 20% 停机）标为“回测不模拟”。
    - engine.simulate_portfolio 中 max_drawdown_halt 只事后打标记，交易照常继续；R5 用当前权益与已实现亏损，与 07 的“当日初权益、已实现 + 未实现”不一致。
    - 影响：实盘会停机，回测却继续交易并可能“自己回本”，权益曲线不代表实盘路径。

21. 点差与滑点下限 1bp 可能偏乐观
    - backtest.yaml half_spread_min = slip_min = 0.0001；100U 名义下冲击项几乎为 0，真实成本主要是点差；突破时盘口变薄，靠后的山寨币点差常见 3~10bp。

22. 出场 / 止损参数的选择存在选择偏差
    - 位置：scripts/tuning_exits.py。
    - 同一验证段 M10~M12 用了三次：LightGBM early stopping、扫 θ、按 PF 选组。
    - 共跑 3 轮 18 组，前两轮看了结果后才改止损区间（0.5%~1.5% → 1.0%~2.5%）与验证段（M11~M12 → M10~M12）。
    - 选中组 PF 1.473，其余 5 组 1.001~1.087，一组离群更像噪声；18 组都在大单阈值修复前的数据上运行，依据已过期。
    - _scan_theta 没有 05 §7.2 的“PF 保留 0.9 的最小 θ”规则，与设计不一致。

23. 闸门按 reference 运行判定，与实际仓位风险不匹配
    - reference 每笔止损亏权益 0.5%；实际配置（20% 保证金 × 5 倍）每笔止损亏约 1.15%~2.65%，是 reference 的 2.3~5.3 倍，最多 3 仓同时止损约亏 3.5%~8%。
    - reference 回撤 15% 对应实际仓位约 35%~60%，会触发 R8（20%）；现有闸门对 user 运行没有任何要求。

24. 月化 15% 目标与已知数据差距大
    - 每笔名义 = 权益时，月 150 笔需要单笔净收益约 11bp、毛优势约 20~23bp；月 90 笔需要约 17bp / 27~29bp。
    - R0 在调参期扣成本前单笔期望为 −7.9bp；G2 门槛只是扣成本后 ≥ 3bp。G2 通过只说明有正期望，不代表能达到月化 15%。
    - 2026 年月份因成交额门槛入选币只有 28~48 个，可能出现“任何 θ 都达不到日均 3 笔”。

25. 次要问题
    - 出场手续费按入场名义计算，精确值应按出场名义（误差约为 收益率 × 费率）。
    - 交易规则用当前 exchangeInfo 快照套用到两年前的价格，tick 相对值与取整误差会偏离真实值。
    - exit_sim 要求 t + H_max 仍在同一数据段，下架前约 2 小时的信号被丢弃，下架前的暴跌行情被系统性排除（偏乐观）。
    - 验证月一个月同时用于早停、温度缩放与 θ 选择，θ 估计噪声较大。
