# 03 数据与选币

## 1. 数据源

全部使用币安官方公开数据，无需 API Key。**下载与聚合在东京服务器上执行**（02 §5.2），本地只接收聚合后的分钟数据。币安数据与接口总说明见 [09-币安数据与API.md](./09-币安数据与API.md)。

| 数据                  | 来源                                                                | 粒度   | 用途                                                                 | 必需 |
| :-------------------- | :------------------------------------------------------------------ | :----- | :------------------------------------------------------------------- | :--- |
| 交易规则 exchangeInfo | REST `/fapi/v1/exchangeInfo`                                        | 快照   | 合约列表、上线时间 `onboardDate`、`tickSize`/`stepSize`/最小名义价值 | 是   |
| 1m K 线 klines        | data.binance.vision `data/futures/um/monthly/klines/{SYMBOL}/1m/`   | 1 分钟 | 主特征、标签、回测成交                                               | 是   |
| 归集逐笔 aggTrades    | data.binance.vision `data/futures/um/daily/aggTrades/{SYMBOL}/`     | 逐笔   | 订单流特征、**入场延迟价与入场后高低点**（§2.2）                     | 是   |
| 合约指标 metrics      | data.binance.vision `data/futures/um/daily/metrics/{SYMBOL}/`       | 5 分钟 | 持仓量变化、多空比                                                   | 否   |
| 资金费率 fundingRate  | data.binance.vision `data/futures/um/monthly/fundingRate/{SYMBOL}/` | 每期   | 回测资金费成本、可选特征                                             | 是   |
| BTCUSDT 1m K 线       | 同 klines                                                           | 1 分钟 | 市场环境特征                                                         | 是   |

### 1.1 已知数据格式陷阱（实现时必须处理）

1. **CSV 表头不统一**：部分较新的文件第一行是表头，较旧的没有。读取时检测首行是否为数字。
2. **时间戳单位**：合约为毫秒；为防将来变更，统一规则：值 > 1e14 视为微秒，除以 1000 转为毫秒。
3. **月度文件与日度文件**：当月数据只有日度文件。下载器优先月度，缺失月份用日度补齐。
4. **校验和**：每个 zip 都有同名 `.CHECKSUM` 文件（SHA256），下载后必须校验，失败重试 3 次后报错。
5. **倍数合约**：如 `1000PEPEUSDT` 价格与数量单位与现货不同。特征只使用比例类量，不受影响；报告中显示原合约名。
6. **缺失分钟**：缺失 K 线时价格 OHLC 用上一收盘价填充、成交量填 0，带 `is_filled = 1` 标记，并在质量报告中统计。`is_filled` 的分钟**不产生样本、不允许开仓**。
7. **中文交易对名**（如 `龙虾USDT`）：URL 中需百分号编码；本地文件路径、`newClientOrderId`、日志键名一律使用 `coins.yaml` 中的 ASCII 别名（`alias`，如 `C14`），避免 Windows 路径编码与交易所 ID 字符集问题。WebSocket 流名称的写法以官方文档为准，P1 用 `api_smoke.py` 实测。
8. **成交口径一致性**：确认历史 aggTrades 与实时 `@aggTrade` 流的成交口径一致（例如是否包含某些特殊订单类型的成交）。P1 用一天的实时录制与次日的历史文件逐条比对，差异写入质量报告。

### 1.2 K 线字段（12 列）

`open_time, open, high, low, close, volume, close_time, quote_volume, count, taker_buy_volume, taker_buy_quote_volume, ignore`

### 1.3 aggTrades 字段（7 列）

`agg_trade_id, price, quantity, first_trade_id, last_trade_id, transact_time, is_buyer_maker`

`is_buyer_maker = true` 表示买方是挂单方，即**主动卖出**；`false` 为**主动买入**。这是最常见的方向理解错误，必须写单测。

## 2. 下载与存储

### 2.1 下载器 `trade.data.downloader`（服务器运行）

- 输入：`symbols`、`data_types`、月份范围。
- 并发：线程池 4~8 并发，单文件失败指数退避重试（1s、2s、4s）。
- 断点续传：目标 zip 已存在且校验通过则跳过；已聚合完成的日期记录在 `data/raw/_done.parquet`，重跑时跳过。
- 输出：`data/raw/{type}/{alias}/{文件名}.zip`。

### 2.2 聚合 `trade.data.aggregate`（服务器运行）

aggTrades 体积很大，**不保存解压后的原始逐笔**，按日流水线处理：下载一天 → 校验 → 聚合 → 删除该日 zip（`keep_raw_aggtrades: false`）。

**第一遍：每日大单阈值。** 对每个币每个 UTC 日 D，计算当日全部归集成交单笔成交额（`price × quantity`）的 99 分位数 `p99(D)`，写入 `data/bars/{alias}/whale_thr.parquet`（`date`、`p99_quote`、`n_trades`）。**第 D 日使用的大单阈值 `whale_thr(D) = p99(D-1)`**，只用前一天。

**第二遍：分钟原子量。** 用 `zipfile` 打开日度 zip，`pd.read_csv(chunksize=500_000)` 分块读取，按 `transact_time // 60000 * 60000` 归入分钟；跨块的同一分钟合并（原子量均为求和、最大、最小或“最后一个”，可合并）。

| 字段                        | 含义                                                                                                                                     |
| :-------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------- |
| `open_time`                 | 分钟起点（毫秒）                                                                                                                         |
| `agg_n`                     | 归集成交条数                                                                                                                             |
| `buy_quote` / `sell_quote`  | 主动买 / 主动卖成交额（USDT）                                                                                                            |
| `max_trade_quote`           | 本分钟最大单笔成交额                                                                                                                     |
| `max_buy_1s_quote`          | 本分钟内任一秒的主动买成交额合计的最大值                                                                                                 |
| `whale_buy_quote`           | 单笔成交额 ≥ `whale_thr(D)` 的主动买成交额                                                                                               |
| `whale_sell_quote`          | 单笔成交额 ≥ `whale_thr(D)` 的主动卖成交额                                                                                               |
| `whale_thr`                 | 本分钟所用的大单阈值（便于审计）                                                                                                         |
| `p_1s` / `p_3s`             | **入场延迟价**：`transact_time ≤ open_time + 1000`（或 3000）ms 的最后一笔成交价；该区间无成交时取上一分钟收盘价，并置 `p_1s_filled = 1` |
| `hi_post_1s` / `lo_post_1s` | **入场后高低点**：`transact_time > open_time + 1000` ms 且在本分钟内的成交价最高 / 最低；无成交时等于 `p_1s`                             |
| `hi_post_3s` / `lo_post_3s` | 同上，以 3000 ms 为界                                                                                                                    |

`p_*`、`hi_post_*`、`lo_post_*` 只用于回测成交模拟与标签（入场发生在 t+1 分钟内，属于“未来”的执行信息），**禁止作为特征**；特征注册表加载时校验特征列中不包含这些字段。

### 2.3 分钟数据文件

`data/bars/{alias}/{YYYYMM}.parquet`，一行一分钟，字段 = K 线 12 列（去掉 `ignore`）+ aggTrades 原子量 + 可选 metrics（5 分钟值，按 04 §2 规则对齐）+ fundingRate（最近一期已结算值与结算时间戳）。

- 数据类型：价格与量 `float64`，计数 `int64`。压缩：zstd。
- 按 `open_time` 严格递增、无重复，缺失分钟已补齐并带 `is_filled` 标记列。
- 同步到本地：`rsync` 整个 `data/bars/`（02 §5.8）。

### 2.4 数据质量报告 `trade.data.quality`

每币输出：总分钟数、缺失分钟占比、最长连续缺失、零成交分钟占比、价格跳变（|1m 收益| > 20%）次数、aggTrades 与 K 线成交额一致性（分钟级 `buy_quote + sell_quote` 与 `quote_volume` 相对误差的中位数，应 < 1%）、§1.1 第 8 条的实时/历史口径比对结果。缺失 > 1% 或一致性误差 > 2% 的币标记为不合格，不得用于训练或评估。

## 4. 币种名单 `configs/coins.yaml`

### 4.1 方式：固定名单 + 可交易性校验

v2.0 起采用**使用者确认的固定名单**，不再由算法自动选取。原因：名单可解释、可控，便于先跑通全流程。代价是名单带有“事后挑选”偏差（这些币多为已知涨过的币），由留出币、名单外盲测币（§4.4）、封存月与影子盘来校验。

**三类“币种范围”必须区分，互不混淆：**

| 范围 | 用途 | 来源 | 是否可变 |
| :--- | :--- | :--- | :--- |
| 训练名单 | 训练跨币种通用模型 | `coins.yaml` 的 `train`（13 个固定代表币，使用者确认） | 否（不可擅改，AGENTS.md §6.6） |
| 回测评估名单 | 评估模型跨币泛化 | `coins.yaml` 的 `train` + `holdout`（留出）+ 固定种子抽取的 `blind`（盲测） | 否（盲测币抽取后不得重抽） |
| 实盘候选池 | 实盘监控/信号候选（非强制交易） | 动态获取币安 USDⓈ-M USDT 永续 24 小时涨幅榜前 20（07 §3.5），经可交易性过滤 | 是（按配置周期刷新） |

`coins.yaml` 只管训练与回测评估名单，**不决定实盘交易哪些币**。实盘候选池动态化后，训练名单与回测评估名单保持不变。

`scripts/select_coins.py` 的两种模式：

- `--validate`（默认）：对 `coins.yaml` 中每个币执行 §4.2 的校验，输出 `coins_validation.md`；“阻断”项不通过的币移除，“警告”项只记录。
- `--suggest`：保留原来的“打分 + 聚类 + 板块”算法（§4.5），只输出建议名单供使用者参考，**不会改写 `coins.yaml`**。

### 4.2 校验项（窗口 `[T_start, T_end]` = 24 个完整自然月）

校验分两级：**阻断**项不通过意味着“交易不了或数据不可信”，该币不能使用；**警告**项不通过只写入 `coins_validation.md` 提醒使用者，使用者确认保留的币（如 AKE）照常使用，其影响由回测的成本模型如实体现（流动性差 → 冲击滑点与流动性上限截断增多；跳动大 → 点差增大）。盲测币抽样时两级都作为筛选条件（§4.4）。

| 检查                         | 规则                                                                                                                           | 级别 | 说明                                 |
| :--------------------------- | :----------------------------------------------------------------------------------------------------------------------------- | :--- | :----------------------------------- |
| 合约类型                     | `contractType == PERPETUAL`、`quoteAsset == USDT`、`status == TRADING`、**非 TradFi 合约**                                     | 阻断 | TradFi（股票、商品、指数）合约不纳入 |
| 历史长度                     | 训练币：`onboardDate + 30 天 ≤ T_start + 6 个月`（窗口内至少约 18 个月有效数据）；留出币：测试段 + 封存集内至少 3 个月有效数据 | 阻断 | 上线后前 30 天的数据一律不用         |
| `step_notional` 数量步长价值 | `stepSize × 最近 7 天价格中位数` ≤ 0.5 USDT                                                                                    | 阻断 | 10 USDT 小本金下取整误差控制         |
| `min_notional` 最小下单额    | ≤ 5 USDT                                                                                                                       | 阻断 |                                      |
| `max_leverage`               | 杠杆分层允许 ≥ 5x                                                                                                              | 阻断 |                                      |
| 数据质量                     | §2.4 合格                                                                                                                      | 阻断 |                                      |
| `liq` 流动性                 | 有效期内日成交额中位数 ≥ 5000 万 USDT                                                                                          | 警告 | 门槛在 `universe.yaml` 配置          |
| `liq_min` 最差月流动性       | 各月日成交额中位数的最小值 ≥ 1000 万 USDT                                                                                      | 警告 |                                      |
| `tick_rel` 相对最小跳动      | `tickSize / 价格中位数` ≤ 0.02%（2 bp）                                                                                        | 警告 | 太大则滑点不可控                     |

### 4.4 名单外盲测币

为检验“名单是事后挑的”带来的偏差，从**名单之外**的 USDⓈ-M 永续中，按 §4.2 的合约类型、流动性、`tick_rel`、`step_notional`、`min_notional`、数据质量条件筛选（历史长度要求：`onboardDate + 30 天 ≤` 第一个测试月 M13 起点），用固定随机种子（`universe.yaml: blind_seed: 2026`）均匀抽取 5 个，写入 `coins.yaml` 的 `blind` 段。

- 盲测币只下载 M12（预热）至 M24 的数据，只在测试段与封存集上评估，**不参与训练、验证、调参、阈值选择**。
- 抽样在 P1 一次完成，结果写入后不得重抽（重抽即为挑选）。
- 盲测币、留出币只用于回测评估；实盘是否交易由动态候选池决定（07 §3.5），与 `coins.yaml` 的训练/留出/盲测分段无关（§4.1）。

### 4.5 `--suggest` 算法（参考用，保留）

1. 候选池：§4.2 的合约类型、历史长度、可交易性条件。
2. 指标：`liq`、`vol`（每日 1m 对数收益标准差 × √1440 的中位数，取候选池 30%~95% 分位之间）、`burst`（15 分钟收益 ≥ 2% 的非重叠窗口数 / 天）。
3. 打分：`score = 0.40 × pct_rank(liq) + 0.30 × pct_rank(vol) + 0.30 × pct_rank(burst)`。
4. 多样性：对剔除 BTC 影响后的 1 小时残差收益做层次聚类（average linkage，距离 = 1 − 相关系数，6 簇），每簇最多 3 个、每个板块最多 4 个。
5. 输出建议名单与 `rejected_top`，供使用者参考。

## 6. 时间切分（24 个月）

记 24 个完整自然月为 M1…M24（M24 = `end_month`；按 2026-09 计，M1 = 2024-10）。预热期为 M1 之前 `warmup_days = 30` 天，只用于计算特征。

| 用途                | 月份    | 说明                                                                                 |
| :------------------ | :------ | :----------------------------------------------------------------------------------- |
| 调参期              | M1~M12  | 训练 M1~M10、验证 M11~M12，**只用于**选择超参、出场策略及其参数、标签参数（05 §6.1） |
| Walk-Forward 测试段 | M13~M22 | 5 折，每折测试 2 个月，共 10 个月样本外                                              |
| 封存集              | M23~M24 | 开发期间**禁止**加载。仅在 08 G3 执行一次最终评估                                    |

Walk-Forward 采用扩展窗口（`train.yaml: window: expanding`，可选 `rolling_12m` 作对比），超参在调参期选定后 5 折完全相同：

| 折  | 训练   | 验证（早停、校准、选阈值） | 测试    |
| :-- | :----- | :------------------------- | :------ |
| F1  | M1~M11 | M12                        | M13~M14 |
| F2  | M1~M13 | M14                        | M15~M16 |
| F3  | M1~M15 | M16                        | M17~M18 |
| F4  | M1~M17 | M18                        | M19~M20 |
| F5  | M1~M19 | M20                        | M21~M22 |

- **为什么单独设调参期**：如果用各折的验证月挑超参，F4 的验证月 M18 恰好是 F3 的测试月，测试信息就会通过超参泄露进来。调参期全部位于第一个测试月之前，彻底隔离。
- 每个边界执行 **Purge**：删除训练集末尾 `H_label` 根 K 线的样本（其标签窗口会延伸进下一段）。
- 每个边界执行 **Embargo**：再额外删除下一段开头 1 天的样本。
- 开发集结论 = 5 折测试段拼接（10 个月样本外）。
- 最终候选模型：训练 M1~M21、验证 M22，在封存集 M23~M24 上评估一次。通过后上线的就是这个模型，不再用封存集数据重训。
- 留出币、盲测币在所有折中都不参与训练和验证，只在测试段与封存集上评估。
- 窗口内上线较晚的训练币（例如上线于 M5），只在其有效期内贡献样本；每折训练段中某币有效样本 < 60 天时，该币不计入该折训练。
- 封存集访问控制：`loader` 的 `allow_holdout` 参数开发脚本不暴露，只有 `scripts/backtest.py --final` 可以打开，并在 `FINAL_RUNS.log` 记录执行次数。
- **行情阶段差异**：24 个月跨越不同牛熊阶段，越早的数据与当前越不相似。`train.yaml: time_decay_halflife_months`（默认关闭，候选 12）作为超参在调参期评估（05 §6.1）。
