# 03 数据与选币

## 1. 数据源

全部使用币安官方公开数据，无需 API Key。币安数据与接口的总说明见 [09-币安数据与API.md](./09-币安数据与API.md)，本节只描述离线研究用到的部分。

| 数据                  | 来源                                                                | 粒度   | 用途                                                                 | 必需           |
| :-------------------- | :------------------------------------------------------------------ | :----- | :------------------------------------------------------------------- | :------------- |
| 交易规则 exchangeInfo | REST `/fapi/v1/exchangeInfo`（现货 `/api/v3/exchangeInfo`）         | 快照   | 合约列表、上线时间 `onboardDate`、`tickSize`/`stepSize`/最小名义价值 | 是             |
| 1m K 线 klines        | data.binance.vision `data/futures/um/monthly/klines/{SYMBOL}/1m/`   | 1 分钟 | 主特征、标签、回测成交                                               | 是             |
| 归集逐笔 aggTrades    | data.binance.vision `data/futures/um/daily/aggTrades/{SYMBOL}/`     | 逐笔   | 大单类订单流特征                                                     | 是             |
| 合约指标 metrics      | data.binance.vision `data/futures/um/daily/metrics/{SYMBOL}/`       | 5 分钟 | 持仓量变化、多空比                                                   | 否（可选特征） |
| 资金费率 fundingRate  | data.binance.vision `data/futures/um/monthly/fundingRate/{SYMBOL}/` | 每期   | 回测资金费成本、可选特征                                             | 合约模式必需   |
| BTCUSDT 1m K 线       | 同 klines                                                           | 1 分钟 | 市场环境特征                                                         | 是             |

现货模式路径把 `futures/um` 换成 `spot`，且没有 metrics 与 fundingRate。

### 1.1 已知数据格式陷阱（实现时必须处理）

1. **CSV 表头不统一**：部分较新的文件第一行是表头，较旧的没有。读取时检测首行是否为数字。
2. **时间戳单位**：现货数据自 2025-01-01 起时间戳改为微秒，合约为毫秒。统一规则：值 > 1e14 视为微秒，除以 1000 转为毫秒。
3. **月度文件与日度文件**：当月数据只有日度文件。下载器优先月度，缺失月份用日度补齐。
4. **校验和**：每个 zip 都有同名 `.CHECKSUM` 文件（SHA256），下载后必须校验，失败重试 3 次后报错。
5. **改名与倍数合约**：如 `1000PEPEUSDT` 这类合约名带倍数，价格与数量单位与现货不同。选币与特征只使用比例类量，不受影响；但报告中显示名称需保留原合约名。
6. **缺失分钟**：交易所维护或极低流动性时可能缺失 K 线。缺失分钟不前向填充价格以外的量（成交量填 0、价格 OHLC 用上一收盘价填充），并在数据质量报告中统计。

### 1.2 K 线字段（12 列）

`open_time, open, high, low, close, volume, close_time, quote_volume, count, taker_buy_volume, taker_buy_quote_volume, ignore`

### 1.3 aggTrades 字段（7 列）

`agg_trade_id, price, quantity, first_trade_id, last_trade_id, transact_time, is_buyer_maker`

`is_buyer_maker = true` 表示买方是挂单方，即**主动卖出**；`false` 为**主动买入**。这是最常见的方向理解错误，必须写单测。

## 2. 下载与存储

### 2.1 下载器 `trade.data.downloader`

- 输入：`market`、`symbols`、`data_types`、月份范围。
- 并发：线程池 4~8 并发，单文件失败指数退避重试（1s、2s、4s）。
- 断点续传：目标 zip 已存在且校验通过则跳过。
- 输出：`data/raw/{market}/{type}/{symbol}/{文件名}.zip`，保留原始 zip，不解压到磁盘。

### 2.2 聚合 `trade.data.aggregate`

aggTrades 体积很大（活跃山寨币合约单日可达数百 MB 解压后），**不保存解压后的原始逐笔**，逐日流式处理：

采用两遍处理：

**第一遍：每日大单阈值。** 对每个币每个 UTC 日 D，计算当日全部归集成交的单笔成交额（`price × quantity`）的 99 分位数，记为 `p99(D)`，写入 `data/bars/{market}/{symbol}/whale_thr.parquet`（列：`date`、`p99_quote`、`n_trades`）。**第 D 日使用的大单阈值 `whale_thr(D) = p99(D-1)`**，只用前一天，杜绝未来信息。窗口第一天用预热期最后一天的值。

**第二遍：分钟原子量。**

1. 用 `zipfile` 打开日度 zip，`pd.read_csv(chunksize=500_000)` 分块读取。
2. 每块按 `transact_time // 60000 * 60000` 归入分钟，按下表计算原子量。
3. 跨块的同一分钟需要合并（分块边界可能切开一分钟），所有原子量均为求和或求最大值，可直接合并。

分钟级原子量（每币每分钟一行）：

| 字段                       | 含义                                                                |
| :------------------------- | :------------------------------------------------------------------ |
| `open_time`                | 分钟起点（毫秒）                                                    |
| `agg_n`                    | 归集成交条数                                                        |
| `buy_quote` / `sell_quote` | 主动买 / 主动卖成交额（USDT）                                       |
| `max_trade_quote`          | 本分钟最大单笔成交额                                                |
| `max_buy_1s_quote`         | 本分钟内任一秒（`transact_time // 1000`）的主动买成交额合计的最大值 |
| `whale_buy_quote`          | 单笔成交额 ≥ `whale_thr(D)` 的主动买成交额                          |
| `whale_sell_quote`         | 单笔成交额 ≥ `whale_thr(D)` 的主动卖成交额                          |
| `whale_thr`                | 本分钟所用的大单阈值（便于审计）                                    |

### 2.3 分钟数据文件

`data/bars/{market}/{symbol}/{YYYYMM}.parquet`，一行一分钟，字段 = K 线 12 列（去掉 `ignore`）+ aggTrades 原子量 + 可选 metrics（5 分钟值，按 04 §2 规则对齐）+ fundingRate（最近一期已结算值）。

- 数据类型：价格与量 `float64`，计数 `int64`。
- 压缩：zstd。
- 按 `open_time` 严格递增、无重复，缺失分钟已补齐并带 `is_filled` 标记列。

### 2.4 数据质量报告 `trade.data.quality`

每币输出：总分钟数、缺失分钟占比、最长连续缺失、零成交分钟占比、价格跳变（|1m 收益| > 20%）次数、aggTrades 与 K 线成交额一致性（分钟级 `buy_quote + sell_quote` 与 `quote_volume` 相对误差的中位数，应 < 1%）。超过阈值（缺失 > 1% 或一致性误差 > 2%）的币标记为不合格，不得入选。

## 3. 存储量估算

| 项                                      | 估算                            |
| :-------------------------------------- | :------------------------------ |
| 原始 klines zip，16 币（含 BTC）× 12 月 | < 1 GB                          |
| 原始 aggTrades zip，16 币 × 365 天      | 数十 GB 至上百 GB，视币种活跃度 |
| 分钟级 bars Parquet，16 币 × 12 月      | < 2 GB                          |

建议准备 200 GB 以上可用磁盘。aggTrades 原始 zip 在聚合并校验完成后可配置是否删除（`keep_raw_aggtrades: false`）。

## 4. 选币算法 `trade.data.universe`

目标：从全部 USDT 本位永续合约中，用**可复现的规则**选出 15 个币，其中 12 个用于训练、3 个作为留出币。

### 4.1 候选池（硬过滤）

记数据窗口为 `[T_start, T_end]`（12 个完整自然月）。

1. `contractType == PERPETUAL`、`quoteAsset == USDT`、`status == TRADING`。
2. `onboardDate <= T_start - 30 天`（保证窗口内全程有数据且度过上线初期的异常波动）。
3. 排除：BTC、ETH；稳定币与类稳定币（USDC、FDUSD、TUSD、USDP、DAI 等）；指数类合约（如 BTCDOM、DEFI 指数）；黄金等非加密资产映射合约。
4. 窗口内无连续 > 24 小时的停牌或下架记录（用 K 线缺失检测）。

### 4.2 指标计算（基于 1m K 线，在窗口内计算）

| 指标                             | 定义                                               | 门槛                      |
| :------------------------------- | :------------------------------------------------- | :------------------------ |
| `liq` 流动性                     | 日成交额（USDT）的中位数                           | ≥ 1 亿 USDT               |
| `liq_min` 最差月流动性           | 各月日成交额中位数的最小值                         | ≥ 3000 万 USDT            |
| `vol` 波动率                     | 每日 1m 对数收益标准差 × √1440 的中位数            | 在候选池 30%~95% 分位之间 |
| `burst` 爆发频率                 | 15 分钟收益 ≥ 2% 的非重叠窗口数 / 天               | 用于打分                  |
| `tick_rel` 相对最小跳动          | `tickSize / 窗口内价格中位数`                      | ≤ 0.02%（2 bp）           |
| `step_notional` 最小数量步长价值 | `stepSize × 最近 7 天价格中位数`（USDT）           | ≤ 0.5 USDT                |
| `min_notional` 最小下单额        | exchangeInfo 中 `MIN_NOTIONAL` 过滤器的 `notional` | ≤ 5 USDT                  |
| `quality` 数据质量               | §2.4 合格                                          | 必须合格                  |

`vol` 上限的目的是排除极端操纵币；`tick_rel` 的目的是排除价格太低导致每跳一档就是大比例的币（滑点无法控制）。`step_notional` 与 `min_notional` 是为 10 USDT 级别小本金加的约束：10 USDT 本金、每笔 20%、5x 时单笔名义价值仅约 10 USDT（06 §5.4），数量步长价值过大会使取整误差超过 5%，最小下单额过高会直接无法开仓（BTC、ETH 等合约最小下单额通常更高，本就已排除）。这两项门槛在 `universe.yaml` 中配置，本金变大后可放宽。

### 4.3 打分

在通过门槛的候选中计算：

```
score = 0.40 × pct_rank(liq) + 0.30 × pct_rank(vol) + 0.30 × pct_rank(burst)
```

### 4.4 多样性约束

山寨币之间高度相关，只按分数取前 15 会集中在某一类。规则：

1. 用 1 小时对数收益，对每个候选币回归掉 BTC 收益（`r_coin - β·r_btc`，β 用窗口内 OLS 估计），得到残差收益序列。
2. 对残差收益相关系数矩阵做层次聚类（`scipy.cluster.hierarchy`，average linkage，距离 = 1 − 相关系数），切成 6 簇。
3. 另外维护人工板块表 `configs/sectors.yaml`（L1 公链、L2、Meme、DeFi、AI、基础设施/其他），由开发方初填、使用者审阅。
4. 选取：按分数从高到低遍历，若该币所在聚类簇已有 3 个、或所在板块已有 4 个，则跳过；直到选满 15 个。
5. 从 15 个中划分留出币：按分数排序后，取排名第 3、8、13 位（覆盖高中低三档），且三者分属不同板块；若冲突则顺延到下一位。

按历史经验，满足上述条件的通常是这一类币：SOL、XRP、DOGE、ADA、AVAX、LINK、SUI、1000PEPE、WIF、NEAR、APT、ARB、OP、FET、TIA、INJ、SEI、ENA、WLD 等。**最终名单以脚本在实际数据窗口上的计算结果为准**，开发方不得手工指定。

## 6. 时间切分

记 12 个完整自然月为 M1…M12（M12 = `end_month`），预热期为 M1 之前 `warmup_days` 天（只用于计算特征，不产生样本）。

| 用途                | 月份    | 说明                                                     |
| :------------------ | :------ | :------------------------------------------------------- |
| Walk-Forward 开发集 | M1~M10  | 训练、验证、测试都在其中滚动                             |
| 封存集              | M11~M12 | 开发期间**禁止**加载。仅在 08 的 G3 闸门执行一次最终评估 |

Walk-Forward 采用扩展窗口，共 4 折：

| 折  | 训练  | 验证（早停、校准、选阈值） | 测试 |
| :-- | :---- | :------------------------- | :--- |
| F1  | M1~M5 | M6                         | M7   |
| F2  | M1~M6 | M7                         | M8   |
| F3  | M1~M7 | M8                         | M9   |
| F4  | M1~M8 | M9                         | M10  |

- 每个边界执行 **Purge**：删除训练集末尾 `H`（时间障碍长度，默认 30）根 K 线的样本，因为它们的标签窗口会延伸进下一段。
- 每个边界执行 **Embargo**：再额外删除下一段开头 1 天的样本。
- 开发集的综合结论 = 4 个测试月拼接后的结果（共 4 个月样本外）。
- 最终候选模型：训练 M1~M9、验证 M10（用于早停、校准、选阈值），然后在封存集 M11~M12 上评估一次。通过后上线的就是这个模型，不再用封存集数据重训。
- 留出币在所有折中都不参与训练和验证，只在测试段与封存集上评估。
- 封存集的访问控制：`loader` 增加 `allow_holdout: bool = False` 参数，开发脚本不暴露该参数；只有 `scripts/backtest.py --final` 可以打开，并在报告中记录执行次数。
