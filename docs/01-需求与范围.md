# 01 需求与范围

## 1. 背景

山寨币在资金拉盘、爆量突破时，分钟级别的成交行为（主动买单激增、大单集中、成交笔数加速、价格突破近期高点）在不同币种之间有相似性。本项目假设：**这种“突破前后的微观结构模式”可以跨币种学习**，用一个通用模型识别“接下来一段时间内先涨到目标位、而不是先跌到止损位”的概率较高的时刻，然后做多，并用弹性出场策略尽量吃到趋势段。

这个假设未必成立。整个项目的设计目标之一，就是**用尽可能低的成本、尽可能早地证伪它**：回测不过就停，不过闸门就不上实盘。

数据与交易全部基于币安（Binance）：历史数据来自币安官方公开数据仓库，实时行情与下单使用使用者自己的币安 API Key 调用 USDⓈ-M 永续合约 API，详见 [09-币安数据与API.md](./09-币安数据与API.md)。

| :--- | :-------------------------------- | :---------------------------------------------------------------------------------------------------- |

## 3. 非目标（本期不做）

- 不做空、不做对冲、不做套利、不做做市。
- 不做现货、不做币本位合约、不做 TradFi（股票、商品）合约。
- 不做毫秒级高频（HFT）。决策频率为 1 分钟，延迟预算为数百毫秒级，足够。
- 不使用完整 L2 盘口深度历史（币安公开数据不提供完整历史盘口）。实盘订阅 `bookTicker` 用于下单限价与价差风控，但不作为模型特征。
- 不做多用户与账号体系。看板只供使用者本人访问（HTTPS + 认证，见 10 §5）。
- 不做桌面安装包与手机 App，手机端用浏览器访问看板。
- 不做多交易所。
- 不托管他人资金。
- **不实现把中国大陆本地的币安请求转发出去的代理、隧道**（理由见 02 §5.3）。交易程序本身就运行在东京服务器上，不需要这类功能。

## 4. 角色与使用流程

只有一个使用者（研究者兼运维）。典型流程：

1. 在东京服务器上运行 `select_coins --validate` → `download` → `aggregate`，把聚合后的分钟数据（Parquet）用 `rsync` 拉回本地。
2. 在本地 Windows（RTX 3060）运行 `build_dataset` → `train` → `backtest`，在本地看板“回测报告”页查看结果。
3. 报告通过闸门后，把模型产物（`model.pt` + `model_meta.json`）用 `rsync` 推送到服务器。
4. 在服务器上依次以 `paper`（测试网）、`shadow`（真实行情不下单）、`live`（真实下单）模式启动交易进程。
5. 在个人微信中接收开平仓、日报、告警（WxPusher），企业微信作备份；通过手机或电脑浏览器访问服务器上的看板，查看状态、调节仓位、一键停机。
6. 每月重新训练一次，新模型同样过闸门才能替换旧模型。

## 6. 术语

| 术语             | 含义                                                                                                                                                       |
| :--------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Bar / K 线       | 1 分钟 OHLCV 数据。`t` 表示第 t 根 K 线，其收盘时刻为决策时刻                                                                                              |
| Taker 主动买入量 | K 线中由买方主动吃单成交的量，币安 K 线自带字段 `taker_buy_volume`                                                                                         |
| aggTrades        | 币安的归集逐笔成交，同一时刻同价同方向的成交合并为一条                                                                                                     |
| CVD              | 累计成交量差（主动买 − 主动卖）                                                                                                                            |
| 三重障碍         | 止盈线、止损线、时间线，哪个先碰到决定**标签**                                                                                                             |
| 出场策略         | 实际交易如何平仓的规则（`fixed` 固定止盈止损 / `trail` 保本 + 追踪），回测与实盘共用一份实现（06 §3.3）                                                    |
| R / R 倍数       | 以初始止损幅度为单位的盈亏。1R = 入场价 × sl                                                                                                               |
| 保本止损         | 浮盈达到一定程度后把止损上移到“入场价 + 往返成本”，之后最坏也基本不亏                                                                                      |
| 追踪止损         | 止损随持仓期间的最高价上移，与最高价保持固定距离（本项目用 ATR 的倍数）                                                                                    |
| 预过滤           | 只在“市场有动静”的 K 线上评估模型，减少无效样本，实盘同样适用                                                                                              |
| Walk-Forward     | 按时间滚动的“训练→验证→测试”，测试段永远在训练段之后                                                                                                       |
| Purge / Embargo  | 在训练集与测试集边界删除标签窗口重叠的样本，并留出隔离期，防止信息泄露                                                                                     |
| 调参期           | M1~M12，只用于选择超参与出场策略，之后的测试月不得再影响任何超参（03 §6）                                                                                  |
| 封存月           | 最后 2 个月数据（M23~M24），开发期间禁止查看，只在最终验收时运行一次                                                                                       |
| 留出币           | **完全不参与训练和验证**的币，只在测试段与封存集上评估。模型在训练币上赚钱可能只是“记住了这些币的脾气”，在从没见过的留出币上也赚钱，才说明学到的是通用规律 |
| 盲测币           | 从固定名单之外、满足可交易性条件的币中按固定随机种子抽出的 5 个币，只在测试段评估，用来检验“名单是事后挑的”带来的偏差（06 §7 S10）                         |
| 规则策略 R0      | 不用模型、只用简单突破规则开仓的基准策略，用于回测引擎与实盘引擎的早期联调，也是模型必须超越的下限（05 §2）                                                |
| 影子盘（Shadow） | 实盘进程接真实行情、产生信号、模拟成交，但不真实下单                                                                                                       |
| 闸门（Gate）     | 阶段之间的硬性准入条件                                                                                                                                     |
| 名义价值         | 合约仓位价值 = 保证金 × 杠杆                                                                                                                               |
| bp               | 基点，1 bp = 0.01%                                                                                                                                         |

## 7. 合规与风险提示（必须阅读）

- **法律合规**：中国大陆监管部门已明确虚拟货币相关业务活动属于非法金融活动，境外交易所向境内居民提供服务同样违规，参与者的权益不受法律保护。币安用户协议也限制受限地区用户使用其服务。**交易程序运行在东京服务器上只解决了网络连通问题，并不改变账户本身的合规属性**，账户冻结等风险仍由使用者自行评估与承担，本设计书不构成法律意见。**不要在公司网络或公司设备上运行实盘程序或保存密钥。**
- **杠杆与仓位风险（本项目配置）**：5x 杠杆 × 20% 保证金比例 = 每笔名义价值等于当前权益（满 3 仓时总名义价值为权益的 3 倍）。单笔止损约亏总权益的 0.6%~1.6%（含成本）；急跌跳空时止损会以更差价格成交。强平距离约 −19%（以交易所维持保证金率为准）。
- **小资金风险**：10 USDT 本金、每笔 20% 时，单笔名义价值仅 10 USDT，接近最小下单额 5 USDT；权益跌到约 5.5 USDT 时将无法开仓，系统自动停止开仓（06 §5.3）。小金额下手续费与精度取整占比更高，回测已按真实最小下单额和精度模拟。
- **云厂商风险**：服务器使用腾讯云（国内实名账号）的东京地域，受其服务协议约束，存在实例被停用的可能（02 §5.1）。交易所侧止损单保证服务器停机时仓位仍受保护。
- **第三方推送风险**：个人微信通知经 WxPusher（第三方）转发，消息内容会经过其服务器，且无可用性承诺；告警同时发企业微信备份（07 §8）。
- **选币偏差风险**：固定名单里的币多是“已知涨过”的币，回测会因此偏乐观。设计中用留出币、盲测币、封存月和影子盘层层校验（06 §9），但无法完全消除。**实盘动态候选池（涨幅榜前 20）同样带有“追涨”偏差，且历史回测无法验证这种榜单策略**（07 §3.5），仅作为监控/信号候选池，不绕过模型与风控。
- **策略风险**：零售费率（VIP0）下的分钟级超短策略，多数在扣除手续费和滑点后为负期望。本设计以“快速证伪”为原则，回测通过也不代表实盘盈利。
- **技术风险**：网络中断、交易所接口变更、程序缺陷都可能导致止损未挂上或重复下单。07 中的对账、止损兜底、Kill Switch 设计必须全部实现。
- **资金风险**：实盘只使用可完全承受损失的资金。
