# 01 需求与范围

## 1. 背景

山寨币在资金拉盘、爆量突破时，分钟级别的成交行为（主动买单激增、大单集中、成交笔数加速、价格突破近期高点）在不同币种之间有相似性。本项目假设：**这种“突破前后的微观结构模式”可以跨币种学习**，用一个通用模型识别“接下来 30 分钟内先涨到止盈位、而不是先跌到止损位”的概率较高的时刻，然后做多。

这个假设未必成立。整个项目的设计目标之一，就是**用尽可能低的成本、尽可能早地证伪它**：回测不过就停，不过闸门就不上实盘。

数据与交易全部基于币安（Binance）：历史数据来自币安官方公开数据仓库，实时行情与下单使用币安 USDⓈ-M 永续合约 API，详见 [09-币安数据与API.md](./09-币安数据与API.md)。

## 2. 目标

| 编号 | 目标                                   | 衡量方式                                                                                |
| :--- | :------------------------------------- | :-------------------------------------------------------------------------------------- |
| G-1  | 自动选出 15 个过去一年有代表性的山寨币 | 选币脚本输出 `configs/coins.yaml`，附每个币的入选理由和指标                             |
| G-2  | 构建可复现的数据管道                   | 同一配置重复运行，特征文件 SHA256 一致                                                  |
| G-3  | 训练一个跨币种通用的 PyTorch 模型      | 在留出币和封存月上仍有正期望（定义见 06）                                               |
| G-4  | 回测结果可信                           | 通过 06 §7 全部健全性检验                                                               |
| G-5  | 实盘与回测一致                         | 影子盘期间信号一致率 ≥ 95%，实际滑点不高于回测假设的 1.5 倍                             |
| G-6  | 实盘安全可控                           | 风控规则全部生效，任何异常可在 1 分钟内一键停机并平仓                                   |
| G-7  | 可视化                                 | localhost 网页看板可查看行情信号、持仓、绩效、回测报告，并可调节仓位、一键停机（见 10） |

## 3. 非目标（本期不做）

- 不做空、不做对冲、不做套利、不做做市。
- 不做毫秒级高频（HFT）。决策频率为 1 分钟，延迟预算为数百毫秒级，足够。
- 不使用完整 L2 盘口深度历史（币安公开数据不提供完整历史盘口，自行录制成本高）。实盘可以订阅 `bookTicker` 用于滑点控制，但不作为模型特征。
- 不做公网可访问的网页、不做多用户与账号体系。看板只监听 `127.0.0.1`（见 10）。
- 不做桌面安装包，看板以本机浏览器打开 localhost 网页的形式提供。
- 不做多交易所。
- 不托管他人资金。
- **不提供代理、隧道、反向代理等绕过交易所地区访问限制的功能**（理由见 02 §5.2）。

## 4. 角色与使用流程

只有一个使用者（研究者兼运维）。典型流程：

1. 在本地 Windows 运行 `select_coins` → `download` → `build_dataset` → `train` → `backtest`，在看板“回测报告”页查看结果。
2. 报告通过闸门后，把模型产物（`model.pt` + `model_meta.json`）上传到实盘服务器。
3. 在实盘服务器上依次以 `paper`（测试网）、`shadow`（真实行情不下单）、`live`（真实下单）模式启动交易进程。
4. 通过飞书机器人接收开平仓、日报、告警；通过看板（SSH 端口转发后在本机浏览器打开）查看状态、调节仓位、一键停机。
5. 每月重新训练一次，新模型同样过闸门才能替换旧模型。

## 6. 术语

| 术语             | 含义                                                                   |
| :--------------- | :--------------------------------------------------------------------- |
| Bar / K 线       | 1 分钟 OHLCV 数据。`t` 表示第 t 根 K 线，其收盘时刻为决策时刻          |
| Taker 主动买入量 | K 线中由买方主动吃单成交的量，币安 K 线自带字段 `taker_buy_volume`     |
| aggTrades        | 币安的归集逐笔成交，同一时刻同价同方向的成交合并为一条                 |
| CVD              | 累计成交量差（主动买 − 主动卖）                                        |
| 三重障碍         | 止盈线、止损线、时间线，哪个先碰到决定标签和平仓方式                   |
| 预过滤           | 只在“市场有动静”的 K 线上评估模型，减少无效样本，实盘同样适用          |
| Walk-Forward     | 按时间滚动的“训练→验证→测试”，测试段永远在训练段之后                   |
| Purge / Embargo  | 在训练集与测试集边界删除标签窗口重叠的样本，并留出隔离期，防止信息泄露 |
| 封存月           | 最后 2 个月数据，开发期间禁止查看，只在最终验收时运行一次              |
| 留出币           | 3 个不参与训练的币，用于检验模型是否真的“通用”                         |
| 影子盘（Shadow） | 实盘进程接真实行情、产生信号、模拟成交，但不真实下单                   |
| 闸门（Gate）     | 阶段之间的硬性准入条件                                                 |
| 名义价值         | 合约仓位价值 = 保证金 × 杠杆                                           |
| bp               | 基点，1 bp = 0.01%                                                     |

## 7. 合规与风险提示（必须阅读）

- **法律合规**：中国大陆监管部门已明确虚拟货币相关业务活动属于非法金融活动，境外交易所向境内居民提供服务同样违规，参与者的权益不受法律保护。币安用户协议也禁止受限地区用户使用其服务，以及通过技术手段规避地区限制；违反可能导致账户被冻结、资产无法取回。使用者需自行评估所在地法律与自身合规义务（含所在公司的合规规定），本设计书不构成任何法律意见。**不要在公司网络或公司设备上运行实盘程序。**
- **杠杆与仓位风险（本项目配置）**：5x 杠杆 × 20% 保证金比例 = 每笔名义价值等于当前权益（满 3 仓时总名义价值为权益的 3 倍）。单笔止损约亏总权益的 0.6%~1.6%（含成本）；急跌跳空时止损会以更差价格成交。强平距离约 −19%（以交易所维持保证金率为准），远大于止损幅度，正常情况下由止损先出场，但不能排除极端行情。
- **小资金风险**：10 USDT 本金、每笔 20% 时，单笔名义价值仅 10 USDT，接近最小下单额 5 USDT；权益跌到约 5.5 USDT 时将无法满足最小下单额，系统自动停止开仓（06 §5.3 权益下限）。手续费与精度取整在小金额下占比更高，回测已按真实最小下单额和精度模拟。
- **策略风险**：零售费率（VIP0）下的分钟级超短策略，多数在扣除手续费和滑点后为负期望。本设计以“快速证伪”为原则，回测通过也不代表实盘盈利。
- **技术风险**：网络中断、交易所接口变更、程序缺陷都可能导致止损未挂上或重复下单。07 中的对账、止损兜底、Kill Switch 设计必须全部实现，不可省略。
- **资金风险**：实盘只使用可完全承受损失的资金。
