# docs 相关规则（AGENTS.md 摘要）

本文件是 AGENTS.md 的摘要，只在上下文涉及 `docs/**` 时生效；冲突时以 AGENTS.md 为准。

## 文档同步规则（照抄 AGENTS.md §5）

**原则：设计文档描述的是“当前真实行为”。** 代码行为变化而设计文档未同步，视为任务未完成。

- 改动研究框架与策略时更新 `docs/13-研究框架.md`；改动实盘引擎、下单与风控时更新 `docs/07`；改动币安接口时更新 `docs/09`；改动看板时更新 `docs/10`。
- **只写规格**：只写变化后的规则、公式、参数、字段、默认值；不写修改履历、日期、实测过程、决策过程与“为什么改”。
- 过程记录、取舍理由与实测结论写入 `docs/research/decisions.md`；进度写入 `docs/research/` 下对应的 `progress_*.md`。
- 旧策略文档在 `docs/archive/`，只供查阅，不随代码改动更新，也不作为当前规格引用。
- 直接修改对应章节正文，不在文末追加“补充说明”；不修改与本次改动无关的章节，不借重构改写措辞，不改章节编号。

### 5.2 同步后的文字自查

- 新增或修改的句子里不得出现日期、“实测”“已决定”“本次修改”“原来是……现在是……”“补充说明”这类过程性措辞。
- 修改后检查：章节号引用是否仍正确、配置示例与 pydantic 模型字段是否一致。

## 设计文档与过程记录的划分

- 设计文档：`docs/design.md`（索引）与 `docs/00`、`02`、`03`、`07`、`09`、`10`、`13`。只描述当前真实行为与规格，不写日期、履历、实测过程与决策过程。
- 过程记录：`docs/research/decisions.md`（取舍理由、实测结论）与 `docs/research/progress_*.md`（进度）。可以写日期与过程，但不是规格；与设计文档冲突时以设计文档为准。
- 旧策略文档：`docs/archive/`，只供查阅，不代表当前规格，不随代码改动更新。

## 完成报告要求

修改设计文档后，在报告中逐条列出“改了哪一节、改成了什么规格”。
