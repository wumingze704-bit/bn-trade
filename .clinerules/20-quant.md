# 量化核心代码规则（AGENTS.md 摘要）

本文件是 AGENTS.md 的摘要，只在上下文涉及 `src/trade/**`、`scripts/**`、`configs/**`、`tests/**` 时生效；冲突时以 AGENTS.md 为准。

## 强制约定（照抄 AGENTS.md §3.2）

| 主题     | 规则                                                                                                               |
| :------- | :----------------------------------------------------------------------------------------------------------------- |
| 时间     | 一律 UTC、`int64` 毫秒时间戳；变量名以 `_ms` 结尾（如 `open_time_ms`）。禁止使用本地时区和 naive `datetime` 做计算 |
| 路径     | 一律 `pathlib.Path`；路径根来自配置 `paths`，禁止硬编码绝对路径                                                    |
| 数值     | 价格、数量在下单前必须经 `tickSize`/`stepSize` 取整函数处理；金额比较使用容差，不用 `==`                           |
| 魔法数字 | 阈值、费率、窗口长度全部来自配置；代码内常量须命名并注释出处（设计文档章节）                                       |
| 配置     | 新增配置项必须同时：加入 pydantic 模型（含范围校验）、加入对应 `configs/*.yaml` 示例、更新设计文档                 |
| 随机性   | 需要随机的地方显式传入 `np.random.Generator` 或种子，不使用全局随机状态                                            |
| 异常     | 离线流程失败即抛出（带币种、时间、文件等上下文）；实盘流程进入安全模式，不吞异常；禁止静默回退默认值（§6 红线 12） |
| 日志     | 使用 `trade.common.logging`，结构化字段；禁止输出密钥、签名、Webhook 完整地址                                      |
| 依赖     | 新依赖需锁定精确版本写入对应 `requirements-*.lock`（base/research/live，见 02 §4），并在完成报告说明用途；优先标准库与已有依赖 |
| 性能     | 先写正确的版本并有测试，再优化；numba 函数必须有对应的纯 Python 参考实现用于测试比对                               |

## 写代码时最容易被忽略的红线（照抄 AGENTS.md §6）

1. **无未来函数**：t 时刻只用 t 及以前已知的信息；任何决策只用决策时刻之前已收盘的数据；归一化只用历史统计量；执行类原子量不得作为特征；调仓与出场状态只在 K 线收盘更新、下一根生效。新增特征必须通过防未来函数测试。
2. **最终检验窗口不可提前读取**：最终检验窗口在使用前不得下载或读取；每个窗口只检验一个候选、只检验一次，结论为 PASS 或 FAIL 后不得重跑（程序崩溃且未产生任何收益数字时按指令的崩溃规则处理）。
3. **参数只在研究期按滚动验证选择**：超参、出场参数、标签参数只能在研究期按滚动验证选择；每一组参数的评估都算一次试验，失败与修订的组同样登记。
4. **单一实现**：研究、最终检验、影子盘、实盘共用同一份策略、组合层与执行口径（`src/trade/research/`、`src/trade/strategies/`、`scripts/portfolio_backtest.py`、取整与撮合假设）；改动任一侧的成交或风控规则，其余各处必须同步。
11. **不得篡改测试**：不得为了让测试通过而修改断言、删除测试、跳过测试（`pytest.mark.skip`、`xfail`）或放宽容差；只有使用者指令明确要求修改某个测试时才可以改，并在报告中说明改了什么、为什么。
12. **禁止静默回退**：缺数据、缺交易规则、缺配置项、缺列时直接抛出带上下文（币种、时间、文件）的异常，不得用默认值、空值或跳过的方式继续计算；实盘流程进入安全模式。
14. **提速必须等价**：以性能为目的的改动不得改变任何计算结果；必须与改动前的结果快照逐字段比对一致（整数与字符串完全相同，浮点 `rtol=1e-12`、`atol=1e-9`），不一致不算完成。
