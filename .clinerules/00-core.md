# Cline 核心规则（AGENTS.md 摘要）

本仓库的最高优先级规范是根目录 AGENTS.md。开始任何任务前先读 AGENTS.md；本文件是摘要，冲突时以 AGENTS.md 为准。

## 每个新任务的第一条回复

第一条回复先列出下面两项，再开始读代码：

1. 本次涉及的 AGENTS.md 红线编号（AGENTS.md §6 的 1~15）；
2. 将要读的设计章节（`docs/xx` §y）与将要修改的现有代码文件。

## 工作流程（AGENTS.md §2）

1. 读：读任务相关的设计章节和将要修改的现有代码。不读不改。
2. 对齐：发现设计文档缺失、矛盾或与真实接口不一致时，先列出问题与建议方案；影响交易结果、风险或资金安全的问题必须停下来问使用者。
3. 改：小步修改，一次只做任务范围内的事，不顺手重构无关代码。
4. 同步设计书：按 AGENTS.md §5.1 对照表找到受影响章节，按红线 11 修改（只写规格，不写履历与过程）。
5. 验：运行 AGENTS.md §8 的质量检查命令，全部通过。
6. 报：按 AGENTS.md §10 在对话中给出中文完成报告。

## 红线 1~15（照抄 AGENTS.md §6，逐条不得改写或删减）

1. **无未来函数**：t 时刻只用 t 及以前已知的信息；入场价用延迟后的逐笔价 `p_1s(t+1)`（06 §3.2）；执行类原子量不得作为特征；归一化只用历史统计量；出场策略状态只在 K 线收盘更新、下一根生效。新增特征必须通过未来函数测试（08 §2 P2）。
2. **封存集不可碰**：开发中不得加载 M23~M24 数据，不得用 `--final` 以外的方式评估封存集，不得根据封存集结果调参。服务器上批量处理数据的脚本必须在代码中硬性限制只处理 M1~M{months−holdout_months}，不能只依赖命令行参数。
3. **测试段不可调参**：超参、出场策略与标签参数只能在调参期（M1~M12）选择；阈值只能在各折验证集上选择；每次测试段回测登记 `EXPERIMENTS.log`。
4. **单一实现、回测实盘一致**：特征计算（`trade.features`）、仓位计算（`trade.common.sizing`）、出场策略（`trade.common.exits`）、交易规则取整在回测与实盘中共用同一份代码。改了任一边的成交或风控规则，另一边必须同步，或在 07 §7.1“回测是否模拟”列写明为什么不需要。
5. **参数归使用者**：选币规则参数（`top_n`、上线天数、成交额下限等）、风控默认阈值、闸门标准、仓位比例与杠杆、`--i-understand-the-risk` 确认机制只能由使用者设定，Agent 不得自行修改。训练与回测评估币种只能来自规则化月度选币快照 `data/universe/{YYYY-MM}.json`（规则见 `configs/universe.yaml`），快照须经使用者审阅并把 `reviewed` 置 `true`；Agent 不得增删币种、不得按名单结果调规则参数、不得自行把 `reviewed` 置 `true`；哈希角色由 `sha256(symbol)` 决定，不得人工调换。实盘候选池（涨幅榜）不在回测范围内，属已知偏差，不得因此修改回测或放宽风控与闸门。
6. **密钥安全**：密钥只来自环境变量；不写入代码、配置、日志、测试、报告、通知消息（WxPusher 等第三方会看到消息内容）；API Key 不开提现权限。
7. **实盘安全**：任何改动不得造成“有仓位无止损”的窗口；止损先于止盈挂出；追踪止损改单必须先挂新单、确认成功后再撤旧单（07 §5.2）；订单请求状态未知时先查询再重发。
8. **不伪造结果**：报告中的数字必须来自实际运行输出，未运行的写“未运行”及原因；不得用 fixture 结果冒充真实数据验收。
9. **币安只在服务器访问**：凡需访问币安（REST、WebSocket、data.binance.vision）的步骤只在东京服务器执行；不实现把本地币安请求转发出去的代理、隧道等代码或配置（02 §5.3）。SSH 端口转发只把服务器上的看板端口映射到本地浏览器，不属于此类。
10. **看板安全**：看板只监听 `127.0.0.1`，不得增加任何公网入口；控制操作必须经 `trade.live.control` 与 PIN 二次确认；不得提供清除停机标志、切换运行模式的功能（10 §5.6、§9）。
11. **设计书与代码一致、只写规格**：`docs/design.md`、`docs/01`~`docs/10`、`docs/dashboard-overview.svg` 是设计书，只描述当前真实行为与规格。(a) 代码行为、配置项、接口、文件契约发生变化时，必须在同一任务内按 §5.1 对照表同步修改设计书对应章节，使设计书与代码一致；(b) 同步时只写变化后的规格（规则、公式、参数、字段、默认值），不添加修改履历、日期、实测过程、决策过程、“为什么改”的说明或补充说明段落；过程记录写入 `docs/records.md`，进度写入 `docs/tasks.md`；(c) 不修改与本次改动无关的章节，不借重构、格式化改写措辞，不改章节编号；(d) 发现设计书与代码不一致、但不属于本次任务范围时，停下报告“章节 / 原文 / 代码现状 / 建议”，不自行修改任何一边。
12. **不得篡改测试**：不得为了让测试通过而修改断言、删除测试、跳过测试（`pytest.mark.skip`、`xfail`）或放宽容差；只有使用者指令明确要求修改某个测试时才可以改，并在报告中说明改了什么、为什么。
13. **禁止静默回退**：缺数据、缺交易规则、缺配置项、缺列时直接抛出带上下文（币种、时间、文件）的异常，不得用默认值、空值或跳过的方式继续计算；实盘流程按 07 进入安全模式。
14. **危险操作先确认**：删除目录或批量删除文件（`rm -rf`、`Remove-Item -Recurse`）、删除或覆盖 `data/`、`artifacts/` 下已有文件、在服务器上删除文件或修改系统配置、重启服务、`git push --force`、`git reset --hard`、`git clean`、`git branch -D`：执行前必须列出将影响的路径或对象，获得使用者确认后再执行。
15. **提速必须等价**：以性能为目的的改动不得改变任何计算结果；必须与改动前的结果快照逐字段比对一致（整数与字符串完全相同，浮点 `rtol=1e-12`、`atol=1e-9`），不一致不算完成。

## 质量检查命令（照抄 AGENTS.md §8）

完成任务前在仓库根目录依次执行，全部通过才能写完成报告：

```text
ruff format --check .
ruff check .
mypy --strict src/trade/common src/trade/backtest src/trade/live
mypy src/trade/dashboard
pytest -q
```

## 完成报告（照抄 AGENTS.md §10）

每次任务结束后，在对话中给出中文完成报告；不生成报告文件，也不落地到仓库。

报告要点：做了什么、改了哪些文件、设计书同步了哪些章节（列出章节号）、验证结果（命令与输出摘要）、与设计的偏差、遗留问题与需要使用者决定的事项。**不夸大，未验证的明确写未验证。**

## 环境约定

- 本地 Windows + PowerShell；命令用 PowerShell 语法书写，路径用绝对路径。
- 东京服务器用 `ssh tokyo`（仅密钥登录）；密钥内容严禁写入任何文件、代码、日志、报告或通知。
- 凡需访问币安的步骤（REST、WebSocket、data.binance.vision）只在东京服务器执行，不在本地实现代理或隧道（红线 9）。

## 任务来源

- 任务来自使用者在对话中给出的指令与 `docs/tasks.md`。
- 每个窗口只做一个任务，做完按 §10 给完成报告后停止，等使用者确认。
- 本目录不得写入 AGENTS.md 没有的新规范；要新增规范，先改 AGENTS.md，再同步本目录摘要。
