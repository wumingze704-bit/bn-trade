# Cline 核心规则（AGENTS.md 摘要）

本仓库的最高优先级规范是根目录 AGENTS.md。开始任何任务前先读 AGENTS.md；本文件是摘要，冲突时以 AGENTS.md 为准。

## 每个新任务的第一条回复

第一条回复先列出下面两项，再开始读代码：

1. 本次涉及的 AGENTS.md 红线编号（AGENTS.md §6 的 1~14）；
2. 将要读的指令文件（`指令/自动多轮/`）、`docs/research/` 交接文件与将要修改的现有代码文件。

## 工作流程（照抄 AGENTS.md §2）

1. **读**：读本次指令文件与 `docs/research/` 下相关交接文件（`ledger.yaml`、候选说明、进度文件），以及将要修改的现有代码。不读不改。
2. **执行**：按指令规定的步骤做；一次只做任务范围内的事，不顺手重构无关代码。需要取舍时自己决定，并按指令把理由记入 `docs/research/decisions.md`。
3. **验**：运行 §8 的质量检查命令，全部通过。
4. **写交接**：更新指令要求的结果文件、进度文件与 `ledger.yaml`（写之前先 `git pull --rebase`，写完立即提交推送）。
5. **提交推送**：提交本次新建、修改、移动、删除的文件并推送到 `develop` 分支（本仓库为 `devlop`）；不提交 `data/`、`artifacts/`、`指令/` 与密钥。
6. **报**：按 §10 写出中文报告。

## 红线 1~14（照抄 AGENTS.md §6，逐条不得改写或删减）

1. **无未来函数**：t 时刻只用 t 及以前已知的信息；任何决策只用决策时刻之前已收盘的数据；归一化只用历史统计量；执行类原子量不得作为特征；调仓与出场状态只在 K 线收盘更新、下一根生效。新增特征必须通过防未来函数测试。
2. **最终检验窗口不可提前读取**：最终检验窗口在使用前不得下载或读取；每个窗口只检验一个候选、只检验一次，结论为 PASS 或 FAIL 后不得重跑（程序崩溃且未产生任何收益数字时按指令的崩溃规则处理）。
3. **参数只在研究期按滚动验证选择**：超参、出场参数、标签参数只能在研究期按滚动验证选择；每一组参数的评估都算一次试验，失败与修订的组同样登记。
4. **单一实现**：研究、最终检验、影子盘、实盘共用同一份策略、组合层与执行口径（`src/trade/research/`、`src/trade/strategies/`、`scripts/portfolio_backtest.py`、取整与撮合假设）；改动任一侧的成交或风控规则，其余各处必须同步。
5. **风险包络与真钱实盘归使用者**：杠杆、单笔风险范围、总名义与净敞口上限、R5~R8 阈值，以及真钱实盘的启动与加资金，只能由使用者决定，Agent 不得自行修改、不得代为启动。
6. **密钥安全**：密钥只来自环境变量；不写入代码、配置、日志、测试、报告、通知消息（WxPusher 等第三方会看到消息内容）；API Key 不开提现权限。
7. **实盘安全**：任何改动不得造成“有仓位无止损”的窗口；止损先于止盈挂出；调整止损必须先挂新单、确认成功后再撤旧单；订单请求状态未知时先查询再重发；`shadow` 模式调用任何下单、撤单、改杠杆、改保证金模式接口必须直接抛错。
8. **不伪造结果**：报告中的数字必须来自实际运行输出，未运行的写“未运行”及原因；不得用 fixture 结果冒充真实数据验收；异常收益先查泄露，查出泄露按失败处理，不得修复后重跑同一窗口。
9. **币安只在服务器访问**：凡需访问币安（REST、WebSocket、data.binance.vision）的步骤只在东京服务器执行；不实现把本地币安请求转发出去的代理、隧道等代码或配置（02 §5.3）。SSH 端口转发只把服务器上的看板端口映射到本地浏览器，不属于此类。
10. **看板安全**：看板只监听 `127.0.0.1`，不得增加任何公网入口；控制操作必须经 `trade.live.control` 与 PIN 二次确认；不得提供清除停机标志、切换运行模式的功能。
11. **不得篡改测试**：不得为了让测试通过而修改断言、删除测试、跳过测试（`pytest.mark.skip`、`xfail`）或放宽容差；只有使用者指令明确要求修改某个测试时才可以改，并在报告中说明改了什么、为什么。
12. **禁止静默回退**：缺数据、缺交易规则、缺配置项、缺列时直接抛出带上下文（币种、时间、文件）的异常，不得用默认值、空值或跳过的方式继续计算；实盘流程进入安全模式。
13. **数据与制品只按清单删除**：`data/` 与 `artifacts/` 只按指令明确列出的清单删除并记录清单（目录、文件数、大小、时间），清单以外的文件不得删除；其他文件的删除一律用 git 操作（`git mv` 归档或 `git rm`），保证历史可以恢复；不使用 `--force`，不改写已推送的历史。
14. **提速必须等价**：以性能为目的的改动不得改变任何计算结果；必须与改动前的结果快照逐字段比对一致（整数与字符串完全相同，浮点 `rtol=1e-12`、`atol=1e-9`），不一致不算完成。

## 质量检查命令（照抄 AGENTS.md §8）

完成任务前在仓库根目录依次执行，全部通过才能写完成报告：

完成任务前在仓库根目录执行，全部通过才能写完成报告：

```text
ruff format --check .
ruff check .
mypy --strict src/trade/common src/trade/backtest src/trade/live
mypy src/trade/dashboard
pytest -q
```

涉及数据下载、研究、回测的任务，另需运行相关脚本的最小规模版本（如 1 个币 × 3 天）并在报告中附关键输出。

## 完成报告（照抄 AGENTS.md §10）

每次任务结束后，按所执行指令的规定在对话中写出中文报告；不生成报告文件，也不落地到仓库。

- 进度写入 `docs/research/` 下对应的 `progress_*.md`；取舍与过程结论追加到 `docs/research/decisions.md`。
- 报告中的数字必须来自实际运行输出；没跑的写“未运行”及原因；**不夸大，未验证的明确写未验证**。

## 环境约定

- 本地 Windows + PowerShell；命令用 PowerShell 语法书写，路径用绝对路径。
- 东京服务器用 `ssh tokyo`（仅密钥登录）；密钥内容严禁写入任何文件、代码、日志、报告或通知。
- 凡需访问币安的步骤（REST、WebSocket、data.binance.vision）只在东京服务器执行，不在本地实现代理或隧道（红线 9）。

## 任务来源

- 任务来自使用者发来的 `指令/自动多轮/` 指令文件；平时只发 `0_自动调度_每次发这个.txt`。
- 进度与状态以 `docs/research/ledger.yaml` 与对应的 `progress_*.md` 为准；取舍理由写入 `docs/research/decisions.md`。
- 本目录不得写入 AGENTS.md 没有的新规范；要新增规范，先改 AGENTS.md，再同步本目录摘要。
